小巧实用的功能

HMAC 🍬

使用共享密钥进行消息认证的函数：

:) SELECT HMAC('SHA256', 'ClickHouse is good', key)

HMAC 广泛用于 API，尤其是 Webhook。

现在可以将 ClickHouse 服务器用作 Webhook，
在 INSERT 时验证消息真实性：

INSERT INTO logs SELECT raw_blob::JSON FROM input() WHERE getClientHTTPHeader('X-Hub-Signature-256') = 'sha256=' || hex(HMAC('SHA256', raw_blob, 'key')) FORMAT RawBLOB;

开发者：Mikhail f. Shiryaev。

新增字典函数 🍭

ClickHouse 有一项独特功能：字典
—。这类表通过专用数据结构进行快速键值查找，
结构涵盖哈希表、IP 范围、正则表达式树和逆地理编码，并可
使用自定义数据源，例如常规表或 Redis、Cassandra、MySQL、PostgreSQL
等外部数据库.

CREATE DICTIONARY taxi_zone_dictionary ( LocationID UInt16 DEFAULT 0, -- key Borough String, -- attributes Zone String, service_zone String ) PRIMARY KEY LocationID SOURCE(HTTP(URL 'https://datasets-documentation.s3.eu-west-3.amazonaws.com/nyc-taxi/taxi_zone_lookup.csv' FORMAT 'CSVWithNames')) LIFETIME(MIN 0 MAX 0) LAYOUT(HASHED_ARRAY()); SELECT dictGet('taxi_zone_dictionary', 'Borough', 2) == 'Brooklyn'; -- lookup by key

dictGetKeys 🍭

版本 25.12 新增函数 dictGetKeys
，可从值反向查找到一组键。

:) SELECT dictGetKeys('taxi_zone_dictionary', 'Borough', 'Brooklyn'); [2] -- there is only one Brooklyn, and it has id 2 in the dictionary

自动创建查询级缓存，使批量查找保持快速。

开发者：Nihal Z. Miaji

投影设置 🧁

可以使用投影为表提供不同排序顺序，
或维护预聚合数据以加快查询：

CREATE TABLE pageviews ( CounterID UInt32, UserID UInt64, EventTime DateTime, ... PROJECTION by_counters ( SELECT CounterID, count(), uniq(UserID) GROUP BY CounterID -- aggregating projection ) (WITH SETTINGS index_granularity = 128) ) ORDER BY (CounterID, UserID, EventTime)

版本 25.12 新增：可以为投影指定自定义 SETTINGS。
— CREATE 和 ALTER 语句均支持。

开发者：Amos Bird。

ALTER 时的索引行为 🍩

25.12 之前，无法 ALTER 二级索引所用的列：

:) CREATE TABLE test (s String, x UInt64, INDEX idx (x) TYPE minmax) ORDER BY s; :) ALTER TABLE test MODIFY COLUMN x Nullable(UInt64); Exception: Trying to ALTER `x` column which is a part of the index `idx`.

在 25.12 中，可以了！

由新设置控制：alter_column_secondary_index_mode =
'throw' | 'drop' | 'rebuild' | 'compatibility'

开发者：Raúl Marín。

S3Queue：添加标签和移动动作 🎈

通过 S3Queue 表引擎可持续消费 S3 文件。
还有对应的 AzureQueue 引擎。

CREATE TABLE queue (name String, value UInt32) ENGINE = S3Queue('s3://clickhouse-public-datasets/path/*.csv.gz') SETTINGS mode = 'unordered', after_processing = 'keep';

after_processing 动作：
— keep
— delete
— move (25.12)：将文件移动到其他路径或存储桶
— tag (25.12)：为文件附加标签（after_processing_tag_key/_value）

开发者：Murat Khairulin。

性能改进

自动并行副本 🛷

25.12 引入 automatic_parallel_replicas_mode,
，在运行时收集统计信息，并判断：
— 查询是否足够繁重，需要分布式执行；
— 查询是否很快，或包含大量网络传输；

开发者：Nikita Taranov。

排序时跳过数据 🍾

假设有以下查询：

SELECT * FROM table ORDER BY something LIMIT 100

它流式读取数据，并在内存中维护前 100 个结果，
我们已经为此提供了延迟读取、有序读取等多项优化……

版本 25.12 新增：利用已累积的前列结果的下界值，
在后续粒度读取时进行过滤，并快速跳过它们。

SET use_skip_indexes_for_top_k = 1, use_top_k_dynamic_filtering = 1;

演示。

开发者：Shankar Iyer。

更有效地应用数据跳过索引 🥧

索引能否使用混合 AND/OR 的复杂条件？

SELECT id FROM tab WHERE (v1 BETWEEN 10 AND 20 AND v2 BETWEEN 10 AND 20) OR (v1 BETWEEN 100 AND 2000 AND v2 BETWEEN 100 AND 2000) OR (v1 > 9000 AND v2 > 9000)

在 25.12 之前，只有主键能使用复杂条件。

从 25.12 起，所有类型的数据跳过索引都能使用复杂条件。

25.12 还加快了超大型 MinMax 索引的分析！

开发者：Shankar Iyer。

原地过滤 🍪

底层优化：过滤（WHERE/PREWHERE）之后不再引用原始列时，避免为列分配内存，并改善缓存局部性。

演示

开发者：Xiaozhe Yu。

更快的 JOIN 🎀

SELECT a FROM (SELECT a, b FROM table1) AS t1 INNER JOIN (SELECT a, b FROM table2) AS t2 ON t1.a = t2.a WHERE t1.b != 'wtf' AND t2.b != 'xyz'

两个条件都会作为过滤器下推到子查询……
但从 25.12 起，列 t2.b 会在连接之前就从数据块中移除。

使用 X-Ray 进行性能分析和跟踪 🎇

现在可以对 ClickHouse 代码库中的几乎任何函数进行插桩, 跟踪和性能分析，无需修改生产构建即可使用。

SYSTEM INSTRUMENT ADD `FunctionFactory::tryGet` LOG ENTRY 'Hi!'; SYSTEM INSTRUMENT ADD `QueryMetricLog::startQuery` SLEEP EXIT 0.5; SYSTEM INSTRUMENT ADD `QueryMetricLog::startQuery` PROFILE;

这是一项面向 ClickHouse 工程师的高级功能。

如果你感兴趣，欢迎参加 FOSDEM 2026 1 月 31 日的 LLVM 开发者分会场。

数据湖

Iceberg 表中的 ORDER BY ❄️

CREATE TABLE hits ( CounterID UInt32, EventTime DateTime, ... ) ENGINE = IcebergS3(...) ORDER BY (CounterID, EventTime DESC)

INSERT 时对数据片段排序，SELECT 利用该顺序优化读取。

很像 MergeTree！

ClickHouse 和 Spark 是仅有的两个利用 Iceberg 数据片段级排序的引擎。

开发者：Konstantin Vedernikov。
