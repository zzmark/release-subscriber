  ClickHouse 26.5 版本，2026-05-21。[演示文稿](https://presentations.clickhouse.com/2026-release-26.5/)，[视频](https://www.youtube.com/watch?v=P1IDAvsi7p8)

<h4 id="265-backward-incompatible-change">
  向后不兼容变更
</h4>

* 将 `date_time_input_format` 和 `cast_string_to_date_time_mode` 的默认值从 `basic` 改为 `best_effort`。此前无法解析非基础格式日期时间字符串（如 `2024 April 4`、`Apr 15, 2020 10:30:00`）的查询，现在默认可能解析成功。若要保留原有的严格解析行为，请将这些设置改回 `basic`（或使用 `compatibility`）。[#89334](https://github.com/ClickHouse/ClickHouse/pull/89334)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 现在禁止将元组元素命名为 `null`，因为它会与 Nullable 空值映射所使用的子列名冲突，导致子列解析出现歧义。[#98377](https://github.com/ClickHouse/ClickHouse/pull/98377)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `dynamic_disk_allow_from_env`、`dynamic_disk_allow_from_zk`、`dynamic_disk_allow_include` 设置，用于禁止在动态磁盘中使用 `from_env`、`from_zk`、`include`。这是一项向后不兼容变更，因为过去默认允许的行为现在默认被禁止。[#99138](https://github.com/ClickHouse/ClickHouse/pull/99138)（[Kseniia Sumarokova](https://github.com/kssenii)）。
* 不再支持基于已废弃 Arrow 实现的 Parquet 读写器，改为使用原生实现。[#100949](https://github.com/ClickHouse/ClickHouse/pull/100949)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 当同名的永久表和临时表 `t` 同时存在且未指定数据库时，`SHOW CREATE TABLE t` 现在优先选择临时表，与 `DESCRIBE TABLE` 的既有行为一致。此外，现已支持 `DESCRIBE TEMPORARY TABLE` 语法。[#100966](https://github.com/ClickHouse/ClickHouse/pull/100966)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 为限制 HTTP 连接在认证前占用的内存，将 `http_max_fields` 的默认值从 1,000,000 降至 1,000，并将 `http_max_field_name_size` 从 128 KB 降至 4 KB；同时新增 `http_max_request_header_size` 和 `http_headers_read_timeout` 设置。依赖原有较高限制的用户可以通过设置恢复旧值。[#103285](https://github.com/ClickHouse/ClickHouse/pull/103285)（[Sema Checherinda](https://github.com/CheSema)）。
* 为 `system.metric_log` 新增 `histograms` 嵌套列，在每行中记录所有已注册直方图指标的快照；新增 `system_metric_log_show_zero_values_in_histograms` 设置以控制是否输出零值。`system.histogram_metric_log` 表现已弃用。[#103770](https://github.com/ClickHouse/ClickHouse/pull/103770)（[Miсhael Stetsyuk](https://github.com/mstetsyuk)）。
* 在未显式指定时区的情况下，将值 `CAST` 为 `DateTime` 或 `DateTime64` 时，若源参数是带显式时区的 `DateTime`/`DateTime64`，现在会保留源参数的时区，与 `toDateTime`/`toDateTime64` 函数的行为一致。关闭 [#55072](https://github.com/ClickHouse/ClickHouse/issues/55072)。[#104433](https://github.com/ClickHouse/ClickHouse/pull/104433)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 移除 `kql` 表函数。请使用 `SET dialect = 'kusto'` 以 KQL 方言执行查询。[#105101](https://github.com/ClickHouse/ClickHouse/pull/105101)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 窗口函数 `RANK` 和 `DENSE_RANK` 现在会拒绝参数并抛出 `NUMBER_OF_ARGUMENTS_DOESNT_MATCH`，以符合 SQL 标准。此前，`RANK(x) OVER (ORDER BY id)` 等查询会被静默接受，参数则被忽略。若要恢复原有的宽松行为，请设置 `allow_rank_dense_rank_arguments = 1`。关闭 [#49526](https://github.com/ClickHouse/ClickHouse/issues/49526)。[#104324](https://github.com/ClickHouse/ClickHouse/pull/104324)（[Groene AI](https://github.com/groeneai)）。

<h4 id="265-new-feature">
  新功能
</h4>

* 新增 `max_bytes_ratio_before_external_join` 设置，与 `max_bytes_ratio_before_external_group_by` 和 `max_bytes_ratio_before_external_sort` 对应。它以可用内存的比例表示哈希连接溢写到磁盘的阈值；与绝对阈值 `max_bytes_before_external_join` 结合使用时，取两者中较小的结果。[#103862](https://github.com/ClickHouse/ClickHouse/pull/103862)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。`max_bytes_ratio_before_external_join` 现以 `0.5` 为默认启用值，同样与另外两个比例设置保持一致。当配置了内存限制，且右表数据超过系统可用内存的一半时，哈希连接会自动溢写并切换为 grace hash join。[#104285](https://github.com/ClickHouse/ClickHouse/pull/104285)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `filesystem` 表函数，可将目录结构表示为表，并使用 SQL 查询文件元数据和内容。最初由 @perst20 在 [#42039](https://github.com/ClickHouse/ClickHouse/pull/42039) 中实现。另见 [#42039](https://github.com/ClickHouse/ClickHouse/issues/42039)、[#50208](https://github.com/ClickHouse/ClickHouse/issues/50208)。[#53610](https://github.com/ClickHouse/ClickHouse/pull/53610)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 允许向 `arrayMap`、`arrayFilter` 等高阶函数直接传入函数名。例如，`arrayMap(negate, [1, 2, 3])` 现在等价于 `arrayMap(x -> negate(x), [1, 2, 3])`。[#101033](https://github.com/ClickHouse/ClickHouse/pull/101033)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `send_table_structure_on_insert_with_inline_data` 设置和 `--inline-insert-data` 客户端选项，让服务器能够通过原生协议自行解析内联 `INSERT` 数据，从而避免为接收表结构而进行一次往返，并提升大量小批次插入的性能。[#101034](https://github.com/ClickHouse/ClickHouse/pull/101034)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `tokenizeQuery` 和 `highlightQuery` 函数，用于 SQL 查询分词和语法高亮。`tokenizeQuery` 返回带字节偏移量和词元类型的词法分析结果；`highlightQuery` 返回基于解析器的语法高亮范围及高亮类别（关键字、标识符、函数、数字、字符串等）。[#101054](https://github.com/ClickHouse/ClickHouse/pull/101054)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `url_base` 设置，按照 RFC 3986 语义解析 `url` 表函数和 `URL` 表引擎中的相对 URL。[#101113](https://github.com/ClickHouse/ClickHouse/pull/101113)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* `LIMIT BY` 子句支持负数，可从每组的*末尾*而非开头选择行。例如，`LIMIT -2 BY id` 返回每个 `id` 的最后两行；同时支持负偏移（`LIMIT -1 OFFSET -1 BY id`）和正负混合（`LIMIT -2 OFFSET 1 BY id`）。[#103222](https://github.com/ClickHouse/ClickHouse/pull/103222)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* `json_value` 函数支持以 `tuple` 和 `array` 形式输出，提高一次查询多个 JSON 路径时的性能。[#78362](https://github.com/ClickHouse/ClickHouse/pull/78362)（[kevinyhzou](https://github.com/KevinyhZou)）。`JSON_VALUE`、`JSON_EXISTS` 和 `JSON_QUERY` 的 JSONPath 参数支持多路径 `Tuple`/`Array`，由 @KevinyhZou 实现。[#101102](https://github.com/ClickHouse/ClickHouse/pull/101102)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `kafka_autodetect_client_rack` 参数。启用后，可通过云平台设施发现可用区，并将其作为 `librdkafka` 的 `client.rack` 参数传递，以避免跨可用区通信。[#81323](https://github.com/ClickHouse/ClickHouse/pull/81323)（[Ilya Golshtein](https://github.com/ilejn)）。
* 为 `system.blob_storage_log` 新增 `Read` 事件类型，用于跟踪对象存储读取操作；由新设置 `enable_blob_storage_log_for_read_operations` 控制。[#96867](https://github.com/ClickHouse/ClickHouse/pull/96867)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 用户现在可以通过新的 `system.zookeeper_watches` 表查看 `clickhouse-server` 发出的 ZooKeeper watch。[#99277](https://github.com/ClickHouse/ClickHouse/pull/99277)（[Den Kalantaevskii](https://github.com/Diskein)）。
* 新增 `Shards` Profile Event，用于统计分布式查询涉及的分片数量，并对所有表求和。[#99470](https://github.com/ClickHouse/ClickHouse/pull/99470)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* `WASM` UDF 现在可声明为 `DETERMINISTIC`，从而参与常量折叠。[#100005](https://github.com/ClickHouse/ClickHouse/pull/100005)（[Vasily Chekalkin](https://github.com/bacek)）。
* 新增 `parallel_replicas_prefer_local_replica` 设置：禁用时，并行副本完全由负载均衡算法选择，因此即使 `max_parallel_replicas = 1`，查询也可以被定向至其他主机。[#100139](https://github.com/ClickHouse/ClickHouse/pull/100139)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `{disk,storage,http}_connections_rcvbuf` 和 `{disk,storage,http}_connections_sndbuf` 服务器设置，用于控制传出 HTTP 连接的 TCP 套接字缓冲区大小，使运维人员能够覆盖内核自动调优，并限制每个连接的内存占用。[#100478](https://github.com/ClickHouse/ClickHouse/pull/100478)（[Sema Checherinda](https://github.com/CheSema)）。
* 支持 `CREATE OR REPLACE MATERIALIZED VIEW`，采用与 `CREATE OR REPLACE TABLE` 相同的原子交换语义，适用于内部表、`TO` 表、`POPULATE`、`REFRESH` 和 `ON CLUSTER`。[#100539](https://github.com/ClickHouse/ClickHouse/pull/100539)（[DQ](https://github.com/il9ue)）。
* 新增 `s3_read_request_duration_microseconds` 和 `s3_read_request_bytes` 直方图指标，用于观测 S3 GET 请求的连接生命周期与消耗字节数，可在 `system.histogram_metrics` 和 Prometheus 端点中查看。[#102058](https://github.com/ClickHouse/ClickHouse/pull/102058)（[Sema Checherinda](https://github.com/CheSema)）。
* 新增 `Paimon`、`PaimonS3`、`PaimonAzure`、`PaimonHDFS` 和 `PaimonLocal` 表引擎，借助 Keeper 中的快照进度跟踪支持增量读取。增量模式仅返回上次已提交快照以来的新行；可通过 `paimon_target_snapshot_id` 读取指定快照增量，并通过 `max_consume_snapshots` 限制单次查询消费的快照数；后台元数据刷新周期可由 `paimon_metadata_refresh_interval_sec` 配置。需启用 `allow_experimental_paimon_storage_engine`。[#102343](https://github.com/ClickHouse/ClickHouse/pull/102343)（[XiaoBinMu](https://github.com/Binnn-MX)）。
* 新增 Kafka 表设置 `kafka_map_virtual_columns_on_write`。启用后，Kafka 表 schema 中名为 `_key`、`_timestamp`、`_headers.name` 和 `_headers.value` 的列会在 `INSERT` 时写入相应的 Kafka 消息键、时间戳和消息头，并从消息负载中排除。[#103243](https://github.com/ClickHouse/ClickHouse/pull/103243)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 为可刷新物化视图新增 `SYSTEM PAUSE VIEW [db.]name` 和 `SYSTEM PAUSE VIEWS` 查询。不同于 `SYSTEM STOP VIEW`，`SYSTEM PAUSE VIEW` 不会中断当前正在执行的刷新：本次刷新可以完成，仅阻止后续刷新。可使用 `SYSTEM START VIEW` 或 `SYSTEM START VIEWS` 恢复；这两个命令现在会统一清除停止与暂停状态。[#103252](https://github.com/ClickHouse/ClickHouse/pull/103252)（[Nikita Mikhaylov](https://github.com/nikitamikhaylov)）。
* 新增 `regexpPosition` 函数（PostgreSQL 兼容别名为 `regexpInstr` 和 `regexp_instr`），返回字符串中第 N 个正则匹配的字节位置。支持起始偏移、匹配后位置返回模式、正则标志和捕获组选择。[#104172](https://github.com/ClickHouse/ClickHouse/pull/104172)（[Abhinav Agarwal](https://github.com/aagarwal-gtr)）。
* 新增用于素性检测的 `isPrime` 和 `isProbablePrime` 函数。`isPrime` 对不超过 `UInt64` 的无符号整数返回精确结果；`isProbablePrime` 还支持 `UInt128` 和 `UInt256`，对这些更宽的类型，`0` 表示确定为合数，`1` 表示可能为质数。`isProbablePrime` 的可选第二参数 `rounds` 控制置信度（上限 `256`）；默认执行 `25` 轮，使随机合数的误判率低于 `10^-15`，且函数支持取消。[#104234](https://github.com/ClickHouse/ClickHouse/pull/104234)（[Nihal Z. Miaji](https://github.com/nihalzp)）。[#104639](https://github.com/ClickHouse/ClickHouse/pull/104639)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。[#104806](https://github.com/ClickHouse/ClickHouse/pull/104806)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 在 clickhouse 命令行工具中，`clear` 和 `/clear` 现在会清空终端，不再被误当作查询执行。[#104318](https://github.com/ClickHouse/ClickHouse/pull/104318)（[Tyler Hannan](https://github.com/tylerhannan)）。
* `file` 表函数在 `SELECT` 查询中可接受由路径组成的 `Array(String)`。[#104442](https://github.com/ClickHouse/ClickHouse/pull/104442)（[Yue](https://github.com/niyue)）。
* 为 `system.functions` 表新增 `deterministic` 和 `higher_order` 列。[#104479](https://github.com/ClickHouse/ClickHouse/pull/104479)（[Pedro Ferreira](https://github.com/PedroTadim)）。
* `bech32Encode` 新增可选编码变体参数（`bech32` / `bech32m`），`bech32Decode` 新增原始解码模式，用于非 SegWit 地址编码（如 Cosmos SDK、Injective、Osmosis）。[#98986](https://github.com/ClickHouse/ClickHouse/pull/98986)（[Yash](https://github.com/Onyx2406)）。
* 现在可写出此前仅支持输入的 `AvroConfluent` 格式，从而可以直接从 ClickHouse 生成带 Confluent Schema Registry 帧的 Avro 消息，例如写入 Kafka 时。schema 会自动注册到 registry；可使用新设置 `output_format_avro_confluent_subject` 指定 subject 名称。[#101935](https://github.com/ClickHouse/ClickHouse/pull/101935)（[János Benjamin Antal](https://github.com/antaljanosbenjamin)）。
* 新增 `prettyPrintJSON` 函数，将 JSON 字符串格式化为易读形式。适用于仪表板和报告等原本需要客户端额外美化 JSON 的场景。关闭 [#62523](https://github.com/ClickHouse/ClickHouse/issues/62523)。[#102594](https://github.com/ClickHouse/ClickHouse/pull/102594)（[Dmitry Prokofyev](https://github.com/prokofyevDmitry)）。
* 新增 `STRING_AGG`，作为 `groupConcat` 不区分大小写的别名，以兼容 PostgreSQL / SQL 标准。[#105125](https://github.com/ClickHouse/ClickHouse/pull/105125)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 现在可以在特定子查询上使用 `SETTINGS use_query_cache = true`，单独缓存各子查询结果，而不缓存整个外层查询。新设置 `query_cache_for_subqueries = true` 可将 `use_query_cache` 批量传播到所有子查询。注意：外层查询的 `use_query_cache` 不再自动传播到子查询。[#99804](https://github.com/ClickHouse/ClickHouse/pull/99804)（[Vincent Voyer](https://github.com/vvo)）。
* Web UI（`play.html`）的查询编辑器新增基于词法分析器的语法高亮，配色参考 `clickhouse-client`。[#105105](https://github.com/ClickHouse/ClickHouse/pull/105105)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。

* `WASM` UDF 现在可转换更多数值类型：将较小整数转换为较宽整数（如 `Int8` 到 `UInt64`），以及将任意整数转换为浮点数（如 `Int32` 到 `Float32`）。[#100435](https://github.com/ClickHouse/ClickHouse/pull/100435)（[Vasily Chekalkin](https://github.com/bacek)）。
* `DELETE FROM system.webassembly_modules` 查询支持 `LIKE` 函数。[#104397](https://github.com/ClickHouse/ClickHouse/pull/104397)（[Vladimir Cherkasov](https://github.com/vdimir)）。

* ArrowFlight SQL 服务器新增预处理语句功能。[#103047](https://github.com/ClickHouse/ClickHouse/pull/103047)（[Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)）。
* 提升 KQL 解析器（用于 Kusto 语言支持）的健壮性：在 KQL 解析器的不同阶段之间保留解析深度与回溯计数器，使复杂 KQL 查询的解析器限制能够被一致跟踪。[#103528](https://github.com/ClickHouse/ClickHouse/pull/103528)（[Yakov Olkhovskiy](https://github.com/yakov-olkhovskiy)）。

<h4 id="265-performance-improvement">
  性能改进
</h4>

* 通过 `file` 表函数或 `File` 表引擎读取本地 Parquet 文件时复用 Parquet footer 元数据缓存。此前仅对象存储后端会查询该缓存。[#104260](https://github.com/ClickHouse/ClickHouse/pull/104260)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 当排序键只引用连接后被保留一侧的列时，将 `ORDER BY ... LIMIT n` 下推穿过 `LEFT`/`RIGHT` JOIN，以限制连接前保留侧必须生成的行数。由新设置 `query_plan_top_k_through_join` 控制（默认启用）。[#104268](https://github.com/ClickHouse/ClickHouse/pull/104268)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 默认启用 `use_top_k_dynamic_filtering` 和 `use_skip_indexes_for_top_k`，提升 `ORDER BY ... LIMIT N` 查询性能。[#99537](https://github.com/ClickHouse/ClickHouse/pull/99537)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。默认将 `use_top_k_dynamic_filtering` 限制为仅用于定长排序列，以避免 `ORDER BY <变长列> LIMIT N` 中逐行比较阈值的成本高于 I/O 节省而造成性能回退。可通过新设置 `use_top_k_dynamic_filtering_for_variable_length_types` 恢复旧行为。[#104216](https://github.com/ClickHouse/ClickHouse/pull/104216)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 使用 `jemalloc` 的 oversize arena 功能减少缺页中断。[#103958](https://github.com/ClickHouse/ClickHouse/pull/103958)（[Nikita Taranov](https://github.com/nickitat)）。
* 限制 `UNION ALL` 中同时处于活动状态的 stream 数量，降低峰值内存占用。[#100176](https://github.com/ClickHouse/ClickHouse/pull/100176)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 小幅优化用户态页面缓存。[#100300](https://github.com/ClickHouse/ClickHouse/pull/100300)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。现在用户态页面缓存始终优于操作系统页面缓存。
