小而美的新功能

自然排序

新增 naturalSortKey 函数，可按人类直觉进行排序：

SELECT name FROM files ORDER BY name file1.txt file10.txt file100.txt file2.txt file20.txt

SELECT name FROM files ORDER BY naturalSortKey(name) file1.txt file2.txt file10.txt file20.txt file100.txt

可在查询的任意位置作为函数使用，例如用于 arraySort。演示。

开发者：Nazarii Piontko。

JSONExtract 支持 JSON 类型

-- native JSON data type: WITH '{"ClickHouse":{"version":"26.3"}}'::JSON AS s SELECT s.ClickHouse.version; -- String: WITH '{"ClickHouse":{"version":"26.3"}}' AS s SELECT JSONExtractString(s, 'ClickHouse', 'version') -- Since 26.3: WITH '{"ClickHouse":{"version":"26.3"}}'::JSON AS s SELECT JSONExtractString(s, 'ClickHouse', 'version')

开发者：Fisnik Kastrati。

JSON 的 has 函数

检查 JSON 列中是否存在指定路径，用法与 Map 类似：

SELECT * FROM events WHERE has(data, 'metrics.latency')

— 工作方式与 Map 类型的 has 类似。

开发者：DQ。

只读 MergeTree 表

新增 MergeTree 设置 table_readonly：

CREATE TABLE my_table (...) SETTINGS table_readonly = 1; -- ALTER TABLE my_table MODIFY SETTING table_readonly = 1; INSERT INTO my_table VALUES (1, 2, 3); -- Exception: Table is in readonly mode.

适用场景：归档或“封存”的表。

只读表不会运行后台线程。

开发者：Mathuranath Metivier。

— compact=1 — 折叠 Expression 步骤。

限制跳过不可用分片

允许跳过不可用分片时，可限制被跳过分片的数量：

SET skip_unavailable_shards = 1; SET max_skip_unavailable_shards_num = 5; SET max_skip_unavailable_shards_ratio = 0.1;

适用于超大规模集群、可观测性数据集，
以及跨地域联合集群的聚合场景。

开发者：Alexey Milovidov。

SQL 兼容性

部分函数现在可以省略括号：

SELECT NOW, CURRENT_DATE, CURRENT_TIMESTAMP;

NOT 运算符的优先级现已符合 SQL 标准：

NOT x IS NULL -- now parsed as NOT (x IS NULL)

SOME 关键字（ANY 的别名）：

SELECT * FROM t WHERE x = SOME (SELECT y FROM u)

带括号的表连接表达式：

SELECT * FROM (t1 CROSS JOIN t2) JOIN t3 ON ...

性能改进

TTL DELETE 支持纵向合并

后台合并可使用以下算法之一：
— 横向：读取包含所有列的数据块并进行合并；
— 纵向：先合并排序键列，再逐个读取并合并其他列；

对宽表而言，纵向合并占用的内存更少、处理更快，
因此通常是首选。

但部分合并类型和操作此前并不支持纵向合并。

从 26.3 起，TTL DELETE 操作也可使用纵向合并！

开发者：murphy-4o。

ANTI、SEMI、FULL JOIN 重排序

优化器现在可以交换 ANTI、SEMI 和 FULL JOIN 的两侧，
并依据统计信息作出选择：

SELECT * FROM large_table LEFT ANTI JOIN small_table USING (id)

— 此前只有 INNER 和 LEFT/RIGHT JOIN 支持重排序。
— 现在优化器可为所有 JOIN 类型自动选择更优的一侧。

在 26.3 中，此功能要求为表启用统计信息。

开发者：Hechem Selmi。

更高效的 S3Queue 更新

26.2：S3Queue 会列出前缀下的所有条目，以查找新文件

26.3：在 ordered 模式下，S3Queue 使用 StartAfter 参数

— 避免重复列出完整的前缀历史。
— 减少 ListObjects API 调用。
— 对历史较长的队列，可显著降低成本和延迟。

开发者：Venkata Vineel。

改进子列读取

更精确的大小计算，让大型 JSON 对象在只读取少量子列时，
内存用量最多可降至原来的 1/8。

开发者：Pavel Kruglov。

值得关注的功能

物化 CTE 🧪

CTE（WITH 子句中的子查询）现在可以只计算一次，
并将结果存入临时表：

SET enable_materialized_cte = 1; WITH top_users AS MATERIALIZED ( SELECT user_id, count() AS cnt FROM events GROUP BY user_id ORDER BY cnt DESC LIMIT 1000) SELECT * FROM top_users INNER JOIN (SELECT user_id FROM top_users WHERE ...) ...

演示

开发者：Dmitry Novik。

分片 Map

对 Map 列进行分桶序列化：

CREATE TABLE tab (id UInt64, m Map(String, UInt64)) ENGINE = MergeTree ORDER BY id SETTINGS map_serialization_version = 'with_buckets', max_buckets_in_map = 32;

— 根据 Map 大小，单键查找速度可提升 2–49 倍。
— 使用 map_serialization_version_for_zero_level_parts = 'basic'
  可使插入速度保持接近基线。

演示

开发者：Pavel Kruglov。

WebAssembly UDF 🧪

使用 WebAssembly 创建用户自定义函数：

INSERT INTO system.webassembly_modules (name, code) SELECT 'collatz', '...'; CREATE FUNCTION collatz_steps LANGUAGE WASM ARGUMENTS (n UInt32) RETURNS UInt32 FROM 'collatz' :: 'steps'; SELECT groupArray(collatz_steps(number::UInt32)) FROM numbers(1, 100);

— 可使用任何能编译为 WASM 的语言编写 UDF：
  Rust, C, C++, Go, Zig, ...
— 通过 Wasmtime 在沙箱中执行。
— 实验性功能。

开发者：Vladimir Cherkasov、Alexey Smirnov、Vasily Chekalkin。

默认启用异步插入

从 26.3 LTS 起，默认启用异步插入。

— ClickHouse 会自动批处理所有小批量插入。
— 大多数用户无需调整配置。
— 减少频繁小批量插入所创建的数据片段数量。

新增统一的去重机制，同时覆盖常规插入和异步插入， 包括涉及物化视图的插入。

开发者：Sema Checherinda。

ALP 编解码器 🧪

新增用于浮点数据的 ALP 压缩编解码器：

CREATE TABLE metrics ( timestamp DateTime, value Float64 CODEC(ALP, ZSTD) ) ENGINE = MergeTree ORDER BY timestamp;

ALP（Adaptive Lossless floating-Point compression，自适应无损浮点压缩）：
— 利用真实场景浮点数据的结构特征。
— 在许多工作负载中比 Gorilla 具有更高的压缩率。

开发者：Nazarii Piontko。

JSON 延迟类型提示 🧪

即时添加或修改 JSON 类型提示，
无需重写数据：

SET allow_experimental_json_lazy_type_hints = 1; ALTER TABLE events MODIFY COLUMN data JSON(metrics.count UInt64);

— 仅修改元数据，瞬间完成。
— 查询旧数据片段时应用类型提示。
— 在 INSERT 和后台合并期间将其物化。

开发者：tanner-bruce。

数据湖性能

在多核计算机上读取少量文件时，数据湖读取速度现在可提升数十倍。

适用于 Iceberg、Delta Lake、Hudi 以及所有对象存储读取。

开发者：Alexey Milovidov。

Parquet 元数据缓存

新增用于 Parquet 元数据（footer）的 SLRU 缓存：

— 常规查询的读取量最多可降低 2 倍。
— 对同一批 Parquet 文件反复查询时尤其有效。

SET use_parquet_metadata_cache;

默认启用。

通过 etag 跟踪文件变更，保证一致性。

开发者：Grant Holly。

Iceberg 元数据预取

Iceberg 表现在支持异步元数据预取：

CREATE TABLE my_iceberg (...) ENGINE = IcebergS3(...) SETTINGS iceberg_metadata_async_prefetch_period_ms = 60000; SELECT ... FROM my_iceberg SETTINGS iceberg_metadata_staleness_ms = 30000;

— 定期预填充元数据缓存。
— 如果缓存元数据足够新，SELECT 查询会直接使用，
 从而避免调用 Iceberg catalog。

开发者：Arsen Muk。
