<h3 id="267">
  ClickHouse 26.7 发布于 2026-07-22。[演示文稿](https://presentations.clickhouse.com/2026-release-26.7/)，[视频](https://www.youtube.com/watch?v=mKBNLaFOVDA)
</h3>

<h4 id="267-backward-incompatible-change">
  向后不兼容变更
</h4>

* 默认情况下，由用户 SQL 发起的 S3 访问不再解析服务器自身的云端凭据（环境变量、IMDS/IRSA、实例配置文件、AWS 配置文件、基于 `role_arn` 的 STS、GCP OAuth 元数据）；这类请求必须使用显式凭据或 `NOSIGN`。命名集合中的 `use_environment_credentials` 现默认为 `0`。若需恢复旧行为，可在请求中设置 `use_environment_credentials = 1`（或通过 `<s3>` 配置全局设置），并同时启用新增设置 `s3_allow_server_credentials_in_user_queries`（默认禁用）。显式提供的凭据以及运维人员在配置中预置的凭据不受影响。服务器启动或执行 `RESTORE` 时，如果持久化 `S3`/`S3Queue` 表、动态 S3 磁盘或 `DataLakeCatalog` 的定义需要解析此类受限凭据，现在会以匿名方式加载（重新配置凭据前不可访问），而不会中止启动；此行为由新增服务器设置 `s3_load_table_anonymously_if_credentials_restricted` 控制（默认启用）。[#106855](https://github.com/ClickHouse/ClickHouse/pull/106855) ([Raúl Marín](https://github.com/Algunenano))。
* `**/` glob（任意层级目录）现在也会匹配当前目录。此前，glob 模式中的 `**/` 未按特殊情况处理，因此 `data/**/file.txt` 无法匹配零层目录的 `data/file.txt`。[#97676](https://github.com/ClickHouse/ClickHouse/pull/97676) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 对存储在对象存储上的备份，无论是直接使用 `S3(...)`/`AzureBlobStorage(...)` 目标，还是使用以 S3 或 Azure 为后端的 `Disk(...)` 目标，`BACKUP` 与 `RESTORE` 均不再接受 `zip`/`zipx` 归档格式。Zip 需要通过随机定位读取中央目录，在对象存储上速度很慢；请改用 `tar.gz` 等基于 tar 的格式。[#101770](https://github.com/ClickHouse/ClickHouse/pull/101770) ([Yash](https://github.com/Onyx2406))。
* `DateTime64` 的支持范围从 `[1900-01-01, 2299-12-31]` 扩展至 `[0000-01-01, 9999-12-31]`。原范围以外的值现在会通过 cctz 正确计算，不再被钳制到边界。由于刻度以 `Int64` 存储，精度为 8 或 9 时范围仍较窄（纳秒精度的最大值仍为 `2262-04-11`）。向后兼容性方面，如果此前使用了超出旧范围的日期时间，并依赖旧范围内非常具体的饱和规则，需要注意结果现在会变为更准确的新值。[#107907](https://github.com/ClickHouse/ClickHouse/pull/107907) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* `AggregatingMergeTree` 现在会在建表时拒绝以下 Schema：某列既不是排序键的一部分，也不是聚合状态度量（`AggregateFunction`/`SimpleAggregateFunction`）。这类列在后台合并时会被静默折叠为任意值，导致对其执行 `GROUP BY` 或过滤的查询返回错误结果。可设置 `allow_dimensions_outside_sorting_key = 1` 恢复旧行为。关闭 [#751](https://github.com/ClickHouse/ClickHouse/issues/751)。[#108087](https://github.com/ClickHouse/ClickHouse/pull/108087) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 移除基于配置文件的工作负载调度设置（服务器配置中的 `resources` 和 `workload_classifiers` 段）。请改用 `CREATE RESOURCE` 与 `CREATE WORKLOAD` 查询；过时的配置段会被忽略并产生警告。[#108286](https://github.com/ClickHouse/ClickHouse/pull/108286) ([Sergei Trifonov](https://github.com/serxa))。
* ClickHouse 现在始终对同步和异步插入使用统一的插入去重哈希，旧的逐插入去重行为已移除。服务器设置 `insert_deduplication_version` 仅保留为迁移保护：如果设置为旧值（`old_separate_hashes` 或 `compatible_double_hashes`），服务器将拒绝启动。从曾使用旧值的版本升级时，应先运行支持 `compatible_double_hashes` 的过渡版本，该模式会同时写入旧哈希和统一哈希。对于复制表，至少运行 `replicated_deduplication_window_seconds` 所指定的时长（默认一小时；默认窗口会保留该时段内所有插入的统一哈希，足以覆盖一次插入重试循环）。对于 `non_replicated_deduplication_window` 大于 0 的非复制表，该窗口按插入次数而非时间计算，因此应至少以 `compatible_double_hashes` 模式运行相应次数的插入。随后移除该设置（或设为 `new_unified_hash`），再升级到此版本。[#108361](https://github.com/ClickHouse/ClickHouse/pull/108361) ([Sema Checherinda](https://github.com/CheSema))。如果从未设置过 `insert_deduplication_version`，可忽略此项。
* 移除长期处于弃用状态的函数 `snowflakeToDateTime`、`snowflakeToDateTime64`、`dateTimeToSnowflake` 和 `dateTime64ToSnowflake`。这些函数自 v24.6 起已分别由 `snowflakeIDToDateTime`、`snowflakeIDToDateTime64`、`dateTimeToSnowflakeID` 和 `dateTime64ToSnowflakeID` 取代，应改用后者。原先用于重新启用旧函数的设置 `allow_deprecated_snowflake_conversion_functions` 现已失效。[#108711](https://github.com/ClickHouse/ClickHouse/pull/108711) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 设置 `use_legacy_to_time` 现默认为 `0`，因此 `toTime` 会将值转换为 `Time` 数据类型，而不是把带时间的日期转换成一个固定日期。仍可使用 `toTimeWithFixedDate` 函数或设置 `use_legacy_to_time = 1` 获得旧行为。[#108729](https://github.com/ClickHouse/ClickHouse/pull/108729) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 朴素贝叶斯模型（供 `naiveBayesClassifier` 使用）现在配置为采用 `NAIVE_BAYES` 布局的字典，并在加载时由包含各类别预聚合 n-gram 计数的表构建。此前由服务器端 XML 配置引用序列化 `.bin` 模型文件的方式已不再支持，现有模型必须重建为字典。除 `naiveBayesClassifier` 外，新增三个函数：`naiveBayesClassifierWithProb` 返回预测类别及其概率，`naiveBayesClassifierWithAllProbs` 返回所有类别及对应概率，`naiveBayesNgrams` 使用与字典相同的方式将文本切分为 n-gram，以便从带标签的原始文本构建训练数据。此外还进行了多项性能优化：对于一个 9.7 MiB 的码点三元模型，内存占用减少约 49 倍（从 1.84 GiB 降至 38 MiB），加载和分类速度均提升约 11 倍。[#108773](https://github.com/ClickHouse/ClickHouse/pull/108773) ([Nihal Z. Miaji](https://github.com/nihalzp))。
* `hasColumnInTable` 函数不再接受可选的 `hostname`、`username` 和 `password` 参数来检查任意远程服务器上的列，仅保留 `hasColumnInTable(database, table, column)` 形式。被移除的远程模式存在安全风险：它允许任何用户向任意主机发起出站连接，会把凭据泄露到查询日志中，并且不受任何权限控制。[#110881](https://github.com/ClickHouse/ClickHouse/pull/110881) ([Alexey Milovidov](https://github.com/alexey-milovidov))。

<h4 id="267-new-feature">
  新功能
</h4>

* 新增 `EXPLAIN ANALYZE` 用于分析查询性能：它会实际执行查询，并以熟悉的查询计划格式展示真实执行指标。[#106586](https://github.com/ClickHouse/ClickHouse/pull/106586) ([Kirill Kopnev](https://github.com/Fgrtue))。[#110668](https://github.com/ClickHouse/ClickHouse/pull/110668) ([Kirill Kopnev](https://github.com/Fgrtue))。
* 投影定义现在支持 `WHERE` 子句。带 `WHERE` 的投影只会物化符合谓词的行；当查询的 `WHERE` 能够蕴含投影的 `WHERE` 时，优化器可根据成本选择使用该投影。[#102347](https://github.com/ClickHouse/ClickHouse/pull/102347) ([S Bala Vignesh](https://github.com/SBALAVIGNESH123))。
* 新增设置 `skip_unavailable_shards_mode`（也可作为 `Distributed` 引擎设置），用于控制启用 `skip_unavailable_shards` 后，远程分片抛出的哪些异常可以被静默忽略。[#79091](https://github.com/ClickHouse/ClickHouse/pull/79091) ([cjw](https://github.com/byte-sourcerer))。
* 新增 `groupFormat` 聚合函数：使用指定输出格式来格式化各分组中的行，并以字符串返回结果。[#93201](https://github.com/ClickHouse/ClickHouse/pull/93201) ([Yang Hu](https://github.com/wandersofb))。
* `kafka_sasl_mechanism` 新增支持值 `AWS_MSK_IAM`，使 ClickHouse 能够使用 IAM 角色向 Amazon MSK 认证，无需管理 SASL/SCRAM 凭据。[#96100](https://github.com/ClickHouse/ClickHouse/pull/96100) ([kalavt](https://github.com/kalavt))。
* 新增聚合函数组合器 `-Tuple`。它会分别对 `Tuple` 列的每个元素应用底层聚合函数，并返回保留元素名称的结果 `Tuple`：当 `t = (a, b)` 时，`sumTuple(t)` 返回 `(sum(a), sum(b))`。多参数聚合函数会为每个参数接收一个元组，并按位置配对：`corrTuple((a1, a2), (b1, b2))` 返回 `(corr(a1, b1), corr(a2, b2))`。不同于对数组使用 `-ForEach`，各元素可以采用不同类型，并且会保留每个元素的结果类型和名称。[#98190](https://github.com/ClickHouse/ClickHouse/pull/98190) ([RinChanNOW](https://github.com/RinChanNOWWW))。
* 文本索引现在支持 `postprocessor` 参数，即在分词后转换每个词元的任意表达式（例如 `lower`）。[#98939](https://github.com/ClickHouse/ClickHouse/pull/98939) ([Jimmy Aguilar Mena](https://github.com/Ergus))。[#108606](https://github.com/ClickHouse/ClickHouse/pull/108606) ([Jimmy Aguilar Mena](https://github.com/Ergus))。
* 新增系统表 `system.stemmers`，列出可供 `stem` 函数指定的全部语言。[#100611](https://github.com/ClickHouse/ClickHouse/pull/100611) ([Jimmy Aguilar Mena](https://github.com/Ergus))。
* 负数 `LIMIT` 现在支持 `WITH TIES`。[#100930](https://github.com/ClickHouse/ClickHouse/pull/100930) ([Nihal Z. Miaji](https://github.com/nihalzp))。
* 支持标准 SQL 后缀运算符 `AT TIME ZONE` 和 `AT LOCAL`，作为 `toTimeZone` 的语法糖。表达式 `expr AT TIME ZONE zone` 等价于 `toTimeZone(expr, zone)`，`expr AT LOCAL` 等价于 `toTimeZone(expr, timeZone())`。[#106092](https://github.com/ClickHouse/ClickHouse/pull/106092) ([lizepeng](https://github.com/lvzhipin03))。
* `URL` 表引擎和 `url` 表函数现在会根据 URL scheme 分派到相应后端：`file://` 由 `File` 引擎处理，`s3://`/`gs://`/`gcs://`/`oss://` 由 `S3` 处理，`az://`/`azure://`/`abfss://`/`abfs://` 由 `AzureBlobStorage` 处理，`hdfs://` 由 `HDFS` 处理，而 `http(s)://` 仍像以前一样由 `URL` 引擎处理。`url_base` 设置会在 scheme 分派前应用。仅分派默认 `url_scheme_mappers` 能解析的 S3 scheme；其他兼容 S3 的厂商 scheme（`cos`、`obs` 等）不会被分派，需要直接使用 `s3` 引擎或函数。[#106093](https://github.com/ClickHouse/ClickHouse/pull/106093) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 新增 `Remote` 和 `RemoteSecure` 表引擎，它们分别是 `remote` 和 `remoteSecure` 表函数的持久化版本。除了 `CREATE TABLE ... AS remote(...)`，现在也可以使用 `CREATE TABLE ... ENGINE = Remote('addresses', db, table, ...)`。[#106189](https://github.com/ClickHouse/ClickHouse/pull/106189) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 新增不依赖引擎的 `SYSTEM STOP`、`SYSTEM START`、`SYSTEM PAUSE`、`SYSTEM CANCEL` 和 `SYSTEM REFRESH` 命令，以及服务器级的 `... ALL BACKGROUND` 形式，通过统一接口控制 `Kafka`、`RabbitMQ`、`NATS`、`S3Queue`/`AzureQueue` 表和可刷新物化视图的后台活动；对于可刷新物化视图，它们是现有 `SYSTEM ... VIEW` 命令的别名。为支持对 NATS 的这些控制，JetStream 表现在只在成功插入后确认消息（至少一次语义；此前消息在投递时自动确认，插入失败可能丢失）。新增 `nats_wait_for_flush_interval` 设置（默认 `false`，保留原低延迟行为），可让一次消费周期保持到完整 flush 间隔结束，而不是队列清空后立即 flush。新增 `nats_commit_on_select` 设置，使直接对 JetStream 表执行 `SELECT` 时会消费（确认）读取的消息。[#107476](https://github.com/ClickHouse/ClickHouse/pull/107476) ([Samuel Krempaský](https://github.com/NIKTONIKTO717))。
* `mysql`、`postgresql` 和 `sqlite` 表函数及表引擎现在可接受用户查询（而非表名），并将其原样传给外部数据库；查询可写成子查询 `(SELECT ...)` 或 `query('SELECT ...')`。结果表结构由查询结果推断，且该表只读。解决 [#46758](https://github.com/ClickHouse/ClickHouse/issues/46758)。基于 [Denis Vidiaev](https://github.com/the-devid) 的初始实现（[#79652](https://github.com/ClickHouse/ClickHouse/pull/79652)）。[#107740](https://github.com/ClickHouse/ClickHouse/pull/107740) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* ClickHouse Web UI（Play）新增标签页，可同时处理多个查询。标签页及其标题、参数、活动状态和小型结果快照会在重新加载后保留（大型结果和图像结果不会恢复），并与浏览器历史记录和 URL 集成，还可以使用鼠标滚轮切换。[#107826](https://github.com/ClickHouse/ClickHouse/pull/107826) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 引入 `QueryRunner` 表引擎。插入 `QueryRunner` 表的记录表示该引擎要执行的查询。此引擎可用于异步执行查询、批量执行生成的查询、将查询定向到远程集群，以及进行基准测试、模糊测试和影子流量测试。[#107888](https://github.com/ClickHouse/ClickHouse/pull/107888) ([Miсhael Stetsyuk](https://github.com/mstetsyuk))。
* 新增 `GeoJSON` 输出格式，用于写入 [GeoJSON](https://geojson.org/) `FeatureCollection` 文档，每行生成一个 feature。唯一的地理类型列（`Point`、`LineString`、`MultiLineString`、`Polygon`、`MultiPolygon`、`Ring` 或 `Geometry`）成为各 feature 的 `geometry`；名为 `id` 的列成为 feature `id`；其余列成为 feature `properties`。若仅有一个名为 `properties` 的对象类型列（`JSON`、`Map` 或命名 `Tuple`），则直接写为 `properties` 对象。`Ring` 会写为单环 `Polygon`。新增且默认启用的 `format_geojson_validate_geometry` 设置控制读写时是否拒绝并非有效 GeoJSON 形状的几何对象，例如少于四个点的 `Polygon` 或未闭合的 `Polygon` 环。此外，`GeoJSON` 输入格式现在将 `id` 列推断为 `Nullable(String)` 而非 `String`，因此缺少 `id` 或显式包含 `"id": null` 的 feature 会读为 `NULL`，并与空字符串 `""` 区分。基于 [Mark Needham](https://github.com/mneedham) 的初始实现（[#98124](https://github.com/ClickHouse/ClickHouse/pull/98124)）。[#108065](https://github.com/ClickHouse/ClickHouse/pull/108065) ([Nihal Z. Miaji](https://github.com/nihalzp))。
* 新增 `dotProductTransposed` 函数（别名 `scalarProductTransposed`），用于计算 `QBit` 列与参考向量之间的近似内积，补充现有的 `L2DistanceTransposed` 和 `cosineDistanceTransposed` 函数。[#108100](https://github.com/ClickHouse/ClickHouse/pull/108100) ([Alexey Milovidov](https://github.com/alexey-milovidov))。新增量化转置距离函数 `cosineDistanceTransposedQuantized`、`L2DistanceTransposedQuantized` 和 `dotProductTransposedQuantized`，它们对包含 `quantizeBFloat16ToInt8` Lloyd-Max 编码的 `QBit(Int8)` 操作，并即时反量化存储编码。浮点参考向量作为全精度查询，以 `Float32` 精度比较（`Float64` 查询会缩窄）；`Array(Int8)` 参考向量本身也会反量化，以计算对称的量化对量化距离。[#109405](https://github.com/ClickHouse/ClickHouse/pull/109405) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* `QBit` 数据类型新增可选的 stride 参数（`QBit(T, dimension, stride)`），将各组维度存储在独立流中，使向量搜索能够高效地只读取前若干维度（例如用于 Matryoshka 嵌入）。转置距离函数接受可选的第四个 `used_dims` 参数，以读取更少的维度。[#108103](https://github.com/ClickHouse/ClickHouse/pull/108103) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* `QBit` 数据类型新增对 `Int8` 元素类型的支持，可存储量化的 8 位整数向量并对其执行转置距离向量搜索（`L2DistanceTransposed`、`cosineDistanceTransposed`）。[#108105](https://github.com/ClickHouse/ClickHouse/pull/108105) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 新增函数 `randomHadamardTransform(vector[, seed[, output_dims]])`：对浮点向量执行确定性的随机 Hadamard 变换。这是一种保持范数的正交旋转，适合在量化前预处理嵌入；截断时还可用作 Johnson–Lindenstrauss / 下采样随机 Hadamard 随机投影。[#108227](https://github.com/ClickHouse/ClickHouse/pull/108227) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 支持通过字典定义中的 `dictionary_lazy_load` 设置为各字典分别配置延迟加载，并覆盖全局 `dictionaries_lazy_load` 服务器设置，从而让部分字典延迟加载、其他字典立即加载。[#108314](https://github.com/ClickHouse/ClickHouse/pull/108314) ([Miсhael Stetsyuk](https://github.com/mstetsyuk))。
* 新增内置文档搜索页面，可通过 HTTP 接口的 `/docs` 路径访问。该页面可即时搜索 `system.documentation` 表并呈现参考文档，包括语法高亮、数学公式和交叉链接。[#108345](https://github.com/ClickHouse/ClickHouse/pull/108345) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 新增函数 `xxHash64Spark`，它以种子 `42` 为 `String` 和 `NULL` 输入计算与 Spark 兼容的 `xxHash64` 值，并返回 `Int64`。[#108436](https://github.com/ClickHouse/ClickHouse/pull/108436) ([Lalit Yadav](https://github.com/lalitium))。
* `ALTER USER`、`ALTER ROLE` 和 `ALTER SETTINGS PROFILE` 现在接受 `SET name = value` 作为 `MODIFY SETTING name = value` 的别名。它会就地修改单项设置并保留其余设置，不同于会替换整个设置列表的裸 `SETTINGS` 子句，因此不易意外清除用户的其他设置。[#108722](https://github.com/ClickHouse/ClickHouse/pull/108722) ([Groene AI](https://github.com/groeneai))。
* 支持使用 `ALTER TABLE ... MODIFY CONSTRAINT [IF EXISTS] name CHECK expr` 就地修改现有约束的表达式。[#108768](https://github.com/ClickHouse/ClickHouse/pull/108768) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* Web UI：新增逐列配色开关（列标题中的 🌈 图标），可在条形图、热力图、分类和无可视化之间切换。所选模式会记录在 URL 和浏览器历史记录中。[#108873](https://github.com/ClickHouse/ClickHouse/pull/108873) ([Alexey Milovidov](https://github.com/alexey-milovidov))。

<h4 id="267-performance-improvement">
  性能改进
</h4>

* `JOIN` 现在可以使用左侧表的主键索引或跳数索引裁剪 granule。由设置 `enable_join_runtime_filters_index_analysis` 控制。[#109085](https://github.com/ClickHouse/ClickHouse/pull/109085) ([Shankar Iyer](https://github.com/shankar-iyer))。
* 对可直接序列化类型的向量进行序列化和反序列化时，现在使用一次缓冲区 I/O 调用，而不再逐个处理元素。[#89842](https://github.com/ClickHouse/ClickHouse/pull/89842) ([Jimmy Aguilar Mena](https://github.com/Ergus))。
* 优化反向字典查找：`WHERE dictGet(dict, attr, key_expr) = value` 等常量等值谓词现在会直接常量折叠为键过滤器（`key_expr = const`、`key_expr IN [...]` 或 `WHERE 0`），而不再重写为 `IN (SELECT ... FROM dictionary(...))` 子查询；`dictGetKeys` 的常量路径现在也会并行执行。[#91164](https://github.com/ClickHouse/ClickHouse/pull/91164) ([Nihal Z. Miaji](https://github.com/nihalzp))。
* 新增设置 `merge_tree_generic_exclusion_search_max_steps`，限制通用排除搜索算法分析每个数据片段主键索引时使用的步数。预算会优先用于剩余的最大键范围，因此即使预算很小也能裁剪大部分数据；未完全分析的范围会整体读取，所以查询结果仍正确，但可能读取更多数据粒度。该限制为宽松限制：最多可超出 `merge_tree_coarse_index_granularity` 步，再加上片段已被划分出的每个范围各一步（例如由查询条件缓存划分）。默认值 0 表示步数无限制。[#92779](https://github.com/ClickHouse/ClickHouse/pull/92779) ([Michael Jarrett](https://github.com/EmeraldShift))。
* 在 `Distributed` 表之上的视图中使用 `ORDER BY` 和 `LIMIT` 的查询现在会采用合并有序流优化：外层 `ORDER BY`/`LIMIT` 被下推到简单视图的内部查询，使各分片在本地排序数据，再由协调器合并预排序流，而非执行全量排序。[#94102](https://github.com/ClickHouse/ClickHouse/pull/94102) ([matanper](https://github.com/matanper))。
* 默认启用 `optimize_or_like_chain`。解决 [#87779](https://github.com/ClickHouse/ClickHouse/issues/87779)。[#94517](https://github.com/ClickHouse/ClickHouse/pull/94517) ([Alexey Milovidov](https://github.com/alexey-milovidov))。
* 将轮转后且无 TTL 的非复制 `MergeTree` 系统日志表标记为 `table_readonly`，避免不必要的后台操作。`MergeTree` 的 `table_readonly` 设置现在还会抑制普通 `MergeTree` 表上的所有后台工作，包括常规合并、TTL（`DELETE`/`MOVE`/重新压缩）合并、重新压缩合并、后台变更和后台片段移动；除已拒绝的插入、变更和 `OPTIMIZE` 外，还会拒绝会修改分区的命令（`ATTACH`/`MOVE`/`DROP`/`DROP DETACHED`/`FETCH`/`REPLACE PARTITION`，以及将 `MOVE PARTITION ... TO TABLE` 移入该表）。因此，带 TTL 的 `table_readonly` 表在启用此设置期间不再回收过期数据。[#95079](https://github.com/ClickHouse/ClickHouse/pull/95079) ([Mathuranath Metivier](https://github.com/matt-metivier))。
* 改进服务器拥有大量用户时从 `system.users` 获取单个用户记录的性能。[#96699](https://github.com/ClickHouse/ClickHouse/pull/96699) ([Alistair Evans](https://github.com/alistairjevans))。
* 使用并行副本按序读取时，现在采用与本地读取相同的逻辑，将表拆分为 `max_threads` 个部分，从而提高并行度。[#101434](https://github.com/ClickHouse/ClickHouse/pull/101434) ([Nikita Taranov](https://github.com/nickitat))。
* 当主键列同时也是分区键的输入列时，`MergeTree` 表的主键分析现在会利用分区 minmax 索引边界裁剪更多数据粒度。例如，对于带 `ORDER BY (id, event_time)` 和 `PARTITION BY toYYYYMM(event_time)` 的 `MergeTree` 表，ClickHouse 会在主键索引分析期间使用 `event_time` 上的分区 minmax 索引，以做出信息更充分的数据粒度裁剪决策。由新增且默认启用的 `use_partition_minmax_for_primary_key_pruning` 设置控制。[#103480](https://github.com/ClickHouse/ClickHouse/pull/103480) ([UnamedRus](https://github.com/UnamedRus))。
* 为使用 Top-K 动态过滤（`ORDER BY ... LIMIT n`）的查询启用查询条件缓存。缓存项按 Top-K 计划参数分区，因此相同查询会复用缓存的 `WHERE` 过滤结果，而不同的 `LIMIT`、排序列或排序方向会生成新的缓存项。[#104478](https://github.com/ClickHouse/ClickHouse/pull/104478) ([Alexey Milovidov](https://github.com/alexey-milovidov))。

* 修复哈希连接物化右侧列时的错误时区处理。关闭 [#111033](https://github.com/ClickHouse/ClickHouse/issues/111033)。[#111074](https://github.com/ClickHouse/ClickHouse/pull/111074) ([Yarik Briukhovetskyi](https://github.com/yariks5s))。
* 修复了使用更宽的 `FixedString` 常量比较来过滤 `String`（或较窄的 `FixedString`）键或 minmax 跳数索引时（例如 `toFixedString('abc', 257) = string_col`），`count()` 结果错误和行被丢弃的问题。主键和 minmax 裁剪此前会根据以 NUL 填充的常量构建范围，错误跳过匹配的数据粒度。 [#111106](https://github.com/ClickHouse/ClickHouse/pull/111106) ([Groene AI](https://github.com/groeneai)).
* 修复异步 `Native` 格式插入，使单个缓冲条目在 `ALTER ... MODIFY COLUMN` 后变得不兼容时，不再导致整个批次失败。关闭 [#111064](https://github.com/ClickHouse/ClickHouse/issues/111064)。[#111108](https://github.com/ClickHouse/ClickHouse/pull/111108) ([Mikhail f. Shiryaev](https://github.com/Felixoid))。
* 修复使用其他类型的对象执行字典 `CREATE OR REPLACE` 的问题：替换已提交后会以 `CANNOT_DETACH_DICTIONARY_AS_TABLE` 失败，并遗留孤儿 `_tmp_replace_*` 表。[#111142](https://github.com/ClickHouse/ClickHouse/pull/111142) ([Nikolay Degterinsky](https://github.com/evillique))。
* 修复右侧列上的 `WHERE` 筛选允许查询规划器把 `Join` 引擎表上的 `ANY` 连接改写为 `SEMI` 或 `ANTI` 时出现 `INCOMPATIBLE_TYPE_OF_JOIN` 的问题。`Join` 引擎表具有不可更改的固定声明严格度，因此现在会拒绝对此类表进行转换。[#111362](https://github.com/ClickHouse/ClickHouse/pull/111362) ([Groene AI](https://github.com/groeneai))。
* 修复了输入数据解析为零行时（例如空 JSON 文档或不含要素的 GeoJSON `FeatureCollection`），`format` 表函数不返回任何列的问题。现在会返回具有正确列的空结果，而不是抛出 `NOT_FOUND_COLUMN_IN_BLOCK`。关闭 [#111390](https://github.com/ClickHouse/ClickHouse/issues/111390)。 [#111428](https://github.com/ClickHouse/ClickHouse/pull/111428) ([Groene AI](https://github.com/groeneai)).

* Sanitizer 构建现在会将 sanitizer 报告捕获到全局缓冲区 `sanitizer_report`，使核心转储分析器能从核心转储读取它。[#109333](https://github.com/ClickHouse/ClickHouse/pull/109333) ([Miсhael Stetsyuk](https://github.com/mstetsyuk))。

* 使用 LLVM-libc 提供的 SIMD `memcmp`/`memcpy`/`memmove`/`memset`/`bcmp`/`memmem` 实现。 [#107566](https://github.com/ClickHouse/ClickHouse/pull/107566) ([Konstantin Bogdanov](https://github.com/thevar1able)). 修复了支持 AVX-512 的机器上，`-O0` 调试版本（`-DDEBUG_O_LEVEL=0`）中 `memmove` 静默损坏数据的问题。 [#110904](https://github.com/ClickHouse/ClickHouse/pull/110904) ([Konstantin Bogdanov](https://github.com/thevar1able)).
* 移除整个代码库及随附第三方库中对 `curl` 库的使用。[#108296](https://github.com/ClickHouse/ClickHouse/pull/108296) ([Konstantin Bogdanov](https://github.com/thevar1able))。
* 将 `mariadb-connector-c` 更新至 3.4.9。[#108328](https://github.com/ClickHouse/ClickHouse/pull/108328) ([Konstantin Bogdanov](https://github.com/thevar1able))。

* 修复 macOS 上事务 `COMMIT` 挂起的问题。[#108375](https://github.com/ClickHouse/ClickHouse/pull/108375) ([Raúl Marín](https://github.com/Algunenano))。
* 新增 `COMPRESS_DEBUG_SECTIONS` CMake 选项，用于压缩目标文件中的 DWARF 调试节（`-gz`）；在编译器支持时会自动启用，以缩小 Debug 构建目录。最终二进制文件保持不压缩，因此不影响运行时堆栈跟踪符号化。 [#109306](https://github.com/ClickHouse/ClickHouse/pull/109306) ([Murphy](https://github.com/murphy-4o)). 随附的 LLVM 工具链现在使用 zlib 构建，因此其 clang 支持 `-gz=zlib`，并补充了缺失的 `clang++-21` 符号链接。 [#109596](https://github.com/ClickHouse/ClickHouse/pull/109596) ([Murphy](https://github.com/murphy-4o)).
