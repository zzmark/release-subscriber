小而实用的功能

groupFormat

一个聚合函数，使用任意输出格式格式化每个分组中的行，
并以字符串返回结果：

SELECT user, groupFormat('Markdown')(action, ts) AS history FROM events GROUP BY user; -- a rendered Markdown table per user SELECT id, groupFormat('JSONEachRow')(*) FROM t GROUP BY id;

— 支持所有输出格式：CSV、JSON、Vertical、XML 等。
— 非常适合将分组数据传给 LLM、Webhook 和报表。

开发者：Yang Hu。

-Tuple 组合器

一次性对 Tuple 的每个元素应用聚合函数：

SELECT sumTuple((clicks, views, purchases)) FROM events; -- (1234, 56789, 42) — one sum per element SELECT corrTuple((a1, a2), (b1, b2)); -- (corr(a1, b1), corr(a2, b2)) — arguments paired by position -- Note: this was already possible SELECT COLUMNS('^metric_') APPLY sum FROM table;

— 不同于用于数组的 -ForEach，各元素可以具有不同类型。
— 结果会保留元素的名称和类型。

开发者：RinChanNOW。

投影中的 WHERE

投影现在可以仅物化符合谓词的行：

ALTER TABLE hits ADD PROJECTION errors ( SELECT ts, status, url WHERE status >= 400 ORDER BY status ); -- reads the tiny projection: 4 granules instead of 10M rows SELECT count() FROM hits WHERE status >= 400;

— 当查询的 WHERE 能够蕴含投影的 WHERE 时，
 优化器会根据成本选择该投影。
— 无需单独建表，即可用数据子集获得更快的执行速度。

开发者：S Bala Vignesh。

统一 URL 访问

url 表函数与 URL 引擎现在会
根据 URL scheme 分派到正确的后端：

SELECT * FROM url('file://data/hits.csv'); -- File SELECT * FROM url('s3://bucket/data/*.parquet'); -- S3 SELECT * FROM url('gs://bucket/table.parquet'); -- S3 (GCS) SELECT * FROM url('az://container/blob.csv'); -- Azure SELECT * FROM url('hdfs://nn:8020/path'); -- HDFS

— 使用一个函数读取所有来源。
— http(s):// 保持原有行为。
— s3、gs 等会使用环境凭据。

开发者：Alexey Milovidov。

eval 🧪

一个能够根据表达式构造查询字符串并执行的表函数：

SET allow_experimental_eval_table_function = 1; SELECT * FROM eval( 'SELECT number FROM numbers(' || toString(2 + 1) || ')'); -- 0, 1, 2 -- the argument can also be a subquery, not wrapped in a string — -- e.g., generate a query that sums every numeric column of a table: SELECT * FROM eval(( SELECT 'SELECT ' || arrayStringConcat(groupArray('sum(' || name || ')'), ', ') || ' FROM metrics' FROM system.columns WHERE table = 'metrics' AND type LIKE '%Int%'));

— 无需外部脚本即可执行动态 SQL。

开发者：Yue Ni、Alexey Milovidov。

Remote 与 RemoteSecure 引擎

remote 表函数现在有了持久化版本：

CREATE TABLE events_on_prod ENGINE = Remote('prod:9000', default, events); -- no column list needed: the structure is inferred from the remote table SELECT count() FROM events_on_prod; -- reads remotely INSERT INTO events_on_prod VALUES …; -- writes remotely -- Note: this was already possible: CREATE TABLE events_on_prod AS remote('prod:9000', default, events);

— 相当于指向另一台服务器上表的永久“符号链接”。
— RemoteSecure 通过 TLS 提供同样的能力。
— 支持集群地址：Remote('host{1..3}:9000', …)。

开发者：Alexey Milovidov。

向外部数据库转发查询

mysql、postgresql 和 sqlite 可以接收查询而不是表名，
并将查询原样传给外部数据库：

SELECT * FROM postgresql('host:5432', 'db', query($$ SELECT date_trunc('week', day) AS w, count() FROM pageviews GROUP BY w $$), 'user', 'pass'); -- runs inside PostgreSQL, with PostgreSQL functions SELECT * FROM sqlite('db.sqlite', (SELECT customer, sum(amount) FROM orders GROUP BY customer)); -- subquery form

— 结果结构根据查询推断，且只读。
— 在远端完成聚合，只传输结果。

开发者：Denis Vidiaev、Alexey Milovidov。

向量搜索

QBit 改进

一种用于向量嵌入的数据类型，
支持在运行时调整搜索精度。
自 26.2 起可用于生产环境：

CREATE TABLE vectors ( id UInt64, name String, ... vec QBit(BFloat16, 1536) ) ORDER BY ();

SELECT id, name FROM vectors ORDER BY L2DistanceTransposed(vec, target, 10) LIMIT 10;

QBit

它采用位切片数据布局：
每个数值按位拆分。
例如，对 1536 维 BFloat16 向量，
会存储 16 个子列，分别包含所有维度的第 1 至第 16 位。

查询时可以指定读取多少个最高有效位。

例如，可以只读取
16 位中的 10 位。

QBit：Int8 量化

QBit 现在支持 Int8，每次查询都可在运行时选择从二值（1 位）到完整 8 位的量化精度。

它可以存储任意 Int8 编码。新增的 quantizeBFloat16ToInt8 与 dequantizeInt8ToBFloat16 函数可在 Float 和 Int8 之间进行优化转换，尽量降低高斯分布向量坐标的误差。

CREATE TABLE images (id UInt64, emb QBit(Int8, 2048)) …; INSERT INTO images SELECT id, quantizeBFloat16ToInt8(embedding * sqrt(2048)) FROM src; -- scale unit-normalized embeddings by sqrt(dim) and convert to Int8 SELECT id FROM images ORDER BY cosineDistanceTransposedQuantized(emb, target, 4) LIMIT 10; -- reads only the top 4 bit-planes — half the I/O of 8-bit

开发者：Alexey Milovidov。

QBit：分组步幅存储

可选的 stride 参数将维度分组，每组的每个位平面 在磁盘上保存为独立数据流：QBit(Int8, 1024, 256)：

维度 1–256 257–512 513–768 769–1024
第 1 位（符号）
第 2 位
第 3 位
第 4 位
第 5–8 位

… ORDER BY cosineDistanceTransposedQuantized(emb, target, 4, 256) … -- 4 bits × first 256 dims: reads the 4 green streams of 32 — 3% of a Float32 column

可以只读取前 N 个维度，适合 MRL（Matryoshka Representation Learning）嵌入，在速度与召回率之间灵活权衡。

开发者：Alexey Milovidov。

随机 Hadamard 旋转

为提高向量搜索质量，可以在量化前对 N 维空间应用随机旋转。

旋转相当于乘以正交矩阵。正交矩阵种类很多，而矩阵乘法的计算成本较高。

Hadamard 矩阵是一类乘法速度更快的正交矩阵，并且足以表示伪随机旋转。

ClickHouse 现在提供伪随机旋转函数：

SELECT randomHadamardTransform(vec);

开发者：Alexey Milovidov。

随机 Hadamard 旋转

向量量化流水线的基础组件：

SELECT randomHadamardTransform([1., 2., 3., 4.]::Array(Float32)); -- [0, 2, 1, -5] — an orthogonal, norm-preserving rotation SELECT randomHadamardTransform(v, seed); -- different rotation SELECT randomHadamardTransform(v, seed, 256); -- truncate to 256 dims

— 将信息均匀分散到各维度，先旋转再量化，可减少标量量化损失。
— 截断形式等价于 Johnson–Lindenstrauss 随机投影。
— 结果具有确定性：相同种子会产生相同旋转。

开发者：Alexey Milovidov。

量化编解码器 🧪

在全精度向量旁存储紧凑的量化副本：

CREATE TABLE vecs (id UInt32, v Array(BFloat16) CODEC(Quantized('rabitq', 384))) …; -- methods: int8, rabitq (1-bit), turboquant (2-bit), mrl, pq SET vector_search_use_quantized_codes = 1; SELECT id FROM vecs ORDER BY L2Distance(v, […]) LIMIT 10;

— 无需索引的两阶段暴力搜索：先扫描较小的量化数据流，
 再用全精度对候选项重新评分。
— 第一阶段的 I/O 最多减少 8 倍（1 位编码缩小 16 倍）。

开发者：Shankar Iyer。

文本搜索

短语匹配的词元位置

— 短语判断可直接由索引完成：

JOIN 性能

右表就是索引

JOIN 可以利用右侧值，通过左表的主键或跳数索引
裁剪数据粒度：

SET enable_join_runtime_filters_index_analysis = 1; SELECT … FROM facts JOIN lookup ON facts.id = lookup.id; -- the ids from `lookup` become an index condition on `facts`

实测：1 亿行表与 100 行表连接：
 读取的数据粒度：12216 → 100（减少 122 倍），
 耗时：0.177 s → 0.022 s（提升 8 倍）。

开发者：Shankar Iyer。

紧凑行引用

哈希连接右侧现在对所有键类型都使用紧凑的
8 字节索引行引用：

— ALL 连接的哈希表条目现在与 ANY 连接一样小。
— 对 1 亿至 3 亿行连接的基准测试显示：耗时中位数降低 12%，
 峰值内存减少 15%；UInt64 键的 INNER 连接快 21%，内存减少 38%。

测试：1 亿 × 1.5 亿行 parallel_hash INNER JOIN：

26.6: 14.4 GB，0.84 秒。
26.7: 8.0 GB，0.66 秒。

开发者：Harikrishnan Prabakaran。

DPsub JOIN 重排序

一种新的 JOIN 顺序优化算法：
基于子集的动态规划：

SET query_plan_optimize_join_order_algorithm = 'dpsub';

— 考虑所有 JOIN 顺序，找出最优计划。
— 优化开销低于 dpsize。
— 与 dpsize、dphyp 不同，支持非内连接。
— 算法可串联：'dpsub,greedy'，按顺序尝试；
 若某算法无法处理查询，则回退到下一算法。

开发者：Fisnik Kastrati。

更多性能改进

JIT 编译的正则表达式引擎

简单正则表达式现在会通过 LLVM 编译为原生代码：

SELECT count() FROM logs WHERE match(line, '^[a-z]+[0-9]+@example[0-9]+\\.com$');

— 适用于 match、extract、extractAll、replaceRegexpOne/All 和 LIKE。
— compile_regular_expressions 默认启用；不支持的模式
 会透明回退到 RE2。

测试：对 2000 万个字符串执行 match()：

26.6: 2.7 秒。
26.7: 1.1 秒。

开发者：Alexey Milovidov。

融合 GROUP BY 与 ORDER BY LIMIT

当 GROUP BY 键与 ORDER BY 键及表排序键匹配时，
LIMIT 会下推至按序聚合：

SELECT site, avg(dur) FROM visits GROUP BY site ORDER BY site LIMIT 10 SETTINGS optimize_aggregation_in_order = 1; -- stops reading as soon as 10 groups are complete

测试：2 亿行：

26.6: 0.23 秒。
26.7: 0.036 秒（快 6.4 倍！）

此外：按序 DISTINCT 快 2 倍，按序 LIMIT BY 快 1.4 倍
（可更快扫描有序流中连续相等的键）。

开发者：Konstantin Bogdanov、Nihal Z. Miaji。

查询条件缓存会记住哪些数据范围满足 WHERE，

— 通过 File 引擎读取的本地 Parquet 文件；
 对象存储此前已支持，S3 使用 ETag 作为缓存键。

直接在 SQL 中使用任意编程语言编写 UDF。
“驱动程序”会在 CREATE 时将其编译为可执行 UDF：

CREATE FUNCTION collatz_steps ARGUMENTS (n UInt64) RETURNS UInt64 ENGINE = GVisorC AS $$ uint64_t steps = 0; while (n > 1) { n = (n % 2 == 0) ? n / 2 : 3 * n + 1; ++steps; } return steps; $$; SELECT number, collatz_steps(number) FROM numbers(1, 10);

— C 函数体会被编译并在沙箱化 Docker 容器中运行；
 项目提供 GVisorC、DockerC 和 UnsafeC 驱动作为示例。
— 驱动由运维人员声明，函数在服务器重启后仍保留。

开发者：Daniil Timižev、Alexey Milovidov。

使用外推格里高利历。

开发者：Alexey Milovidov。

ZXC 编解码器 🧪

一种新的非对称 LZ 编解码器：压缩率优于 LZ4，
解压速度与 LZ4 相当：

CREATE TABLE logs (line String CODEC(ZXC)) …;

编解码器压缩后大小压缩比全量扫描
LZ41.28 GiB3.730.21 s
ZXC1.15 GiB4.160.21 s
ZSTD0.67 GiB7.161.05 s

— 压缩速度较慢（约为 LZ4 的一半），这是有意的取舍：写入时付出一次成本，
 每次读取都能受益，非常适合读取密集型列。

开发者：Alexey Milovidov。

SZ3 与 ALP 编解码器

SZ3 🧪：面向浮点数、误差有界的有损压缩：

v Float64 CODEC(SZ3('ALGO_INTERP_LORENZO', 'ABS', 0.001)) -- sensor data, 50M rows: ZSTD 353 MiB → SZ3 22 MiB (16x) -- with the default settings: 2.1 MiB (168x)

ALP 🧪：现在会在两种方案之间自动选择：

price Float64 CODEC(ALP) -- AUTO: picks STD or RD per block m Float64 CODEC(ALP(RD)) -- force "Real Doubles" -- decimal-like data: ALP ratio 3.74 vs ZSTD 2.42 — and it is lossless

— 两者都需要设置 allow_experimental_codecs = 1。

开发者：Konstantin Vedernikov、Alexey Milovidov、Nazarii Piontko。

ALP 算法：Azim Afroozeh、Leonardo Kuffó、Peter Boncz，CWI（https://ir.cwi.nl/pub/33334）

QueryRunner

一种会执行所插入查询的表引擎：

CREATE TABLE shadow (query String) ENGINE = QueryRunner SETTINGS cluster = 'staging', shard = 'random', threads = 4; INSERT INTO shadow SELECT query FROM system.query_log WHERE type = 'QueryFinish'; -- replay production traffic on the staging cluster

— 即发即忘：支持异步或同步模式，执行结果会被丢弃。
— 用于影子流量、基准测试、模糊测试、批量执行生成的查询，
 以及将查询定向到远程集群。
— 通过 SQL SECURITY INVOKER / DEFINER / NONE 控制访问权限。

开发者：Miсhael Stetsyuk。
