索引投影的新语法

25.12:

CREATE TABLE pageviews ( CounterID UInt32, UserID UInt64, EventTime DateTime, PROJECTION by_time ( SELECT _part_offset ORDER BY EventTime ) ) ORDER BY (CounterID, UserID, EventTime)

Tuple 现在可以是 Nullable

我们一直允许 Tuple 包含 Nullable 类型。

从 26.1 起，Tuple 本身也可以是 Nullable。

:) SET allow_experimental_nullable_tuple_type = 1; :) CREATE TABLE test (id UInt32, data Nullable(Tuple(String, Int64))); :) INSERT INTO test VALUES (1, ('hello', 42)), (2, NULL); :) SELECT * FROM test ┌─id─┬─data─────────┐ │ 1 │ ('hello',42) │ │ 2 │ ᴺᵁᴸᴸ │ └────┴──────────────┘

QBit 晋升至 Beta 阶段

一种用于向量嵌入的数据类型，
支持在运行时调整搜索精度。

CREATE TABLE vectors ( id UInt64, name String, ... vec QBit(BFloat16, 1536) ) ORDER BY ();

SELECT id, name FROM vectors ORDER BY L2DistanceTransposed(vector, target, 10) LIMIT 10;

26.1 中新增函数：cosineDistanceTransposed。

开发者：Raufs Dunamalijevs。

数组上的文本索引

可以像往常一样使用 Array(String) / Array(FixedString) 列：

CREATE TABLE tab ( key UInt64, val Array(String), INDEX idx(val) TYPE text( tokenizer = 'splitByNonAlpha', preprocessor = lower(val)) );

并在 Array 列中进行搜索：

SELECT count() FROM tab WHERE hasAllTokens(val, 'clickhouse');

有趣的新特性

文本索引中的 sparseGrams 分词器

CREATE TABLE stackoverflow.posts ( ... Body String, INDEX idx_body Body TYPE text( tokenizer = sparseGrams(3, 20, 5), preprocessor = lower(Body)) ) ORDER BY (PostTypeId, toDate(CreationDate), CreationDate)

与 ngrams 类似，但除了短 n-gram 外，还会加入部分选定的更长 n-gram（n+1、n+2……）。

搜索时，它可以从搜索字符串中选取最长的 n-gram，并忽略已被覆盖的较短 n-gram。这样可使用数量更少、区分度更高且更稀有的词元进行搜索。

开发者：Anton Popov、Konstantin Vedernikov。

示例：在 68 GB 的 StackOverflow 帖子中搜索代码：

SELECT Tags FROM stackoverflow.posts_ngrams WHERE Body LIKE '%(*(void(*)())0)()%' AND NOT empty(Tags) ORDER BY Tags

使用 sparseGrams 分词器：51 ms。

含物化视图的异步插入去重

异步插入（通过 async_insert 启用）会收集 多个并发客户端的数据，并将其作为单个批次写入，从而高效处理频繁的小批量插入。

异步插入还可通过 async_insert_deduplicate 设置提供幂等性。它既可以使用插入数据的哈希，也可以使用自定义幂等令牌。
因此可以安全地重试 INSERT，同时保持恰好一次语义。

从 26.1 版本起，恰好一次语义扩展至
附加到表上的所有物化视图。

开发者：Sema Checherinda。
