略显枯燥的安全功能

外部数据的 READ 和 WRITE 授权

在 25.6 及以前版本：

GRANT S3 ON *.* TO user

在 25.7 中：

$ cat config.d/read_write_grants.yaml access_control_improvements: enable_read_write_grants: true

GRANT READ, WRITE ON S3 TO user

允许限制对外部数据源的读取或写入，
例如 S3、URL、File 等。

开发者：Artem Brustovetskii。

参数化 CREATE USER 查询

SET param_username = 'test123'; CREATE USER {username:Identifier};

开发者：Diskein。

性能改进

加快简单聚合

如果查询仅包含 count() 聚合函数，
将使用优化后的代码路径。

示例： SELECT RegionID, count() FROM hits GROUP BY RegionID ORDER BY count() DESC LIMIT 10

25.6: 42 ms, 2.39 billion rows/s.
25.7: 32 ms, 3.11 billion rows/s.

开发者：Amos Bird。

异步日志

$ cat config.d/logger_async.yaml logger: async: true # This is the default in 25.7, but can be disabled

日志记录不再因写入而阻塞，在输出到终端或慢速磁盘时可提高速度，尤其有利于短查询。

clickhouse-benchmark --query " SELECT count() FROM hits WHERE AdvEngineID != 0" 

25.6: 225 QPS, 14.5 billion rows/sec.
25.7: 255 QPS, 16.4 billion rows/sec.

开发者：Raúl Marín。

JOIN 优化

Hash JOIN 的底层优化：

— 优化 RIGHT 和 FULL JOIN

— 优化包含多个 OR 条件的 JOIN

— 让 INNER JOIN 与 IN 运算符一样快

— 更精确地为结果分配内存

开发者：Nikita Taranov。

默认启用分布式 INSERT SELECT

在同一集群内，从一张 Distributed 表插入到另一张 Distributed 表时，SELECT 和 INSERT 流水线都会在所有机器上并行运行。

如果启用 enable_parallel_replicas ，在同一集群内从一张 Replicated 表插入到另一张 Replicated 表时，也会跨机器并行执行。

开发者：Igor Nikonov。

一些有趣的功能

轻量级更新

完整功能的 UPDATE 语句：

UPDATE my_table SET col1 = val1, col2 = val2, ... WHERE condition UPDATE hits SET Title = 'Updated Title' WHERE EventDate = today(); UPDATE wikistat SET hits = hits + 1, time = now() WHERE path = 'ClickHouse';

开发者：Anton Popov。

轻量级更新

支持 MergeTree, ReplacingMergeTree, CollapsingMergeTree,
，包括 Replicated 表。

CREATE TABLE hits (...) ENGINE = MergeTree SETTINGS enable_block_number_column = 1, enable_block_offset_column = 1; SET allow_experimental_lightweight_update = 1;

开发者：Anton Popov。

轻量级更新

UPDATE 的性能类似于
使用相同列和条件的 INSERT SELECT。

UPDATE 创建一个 补丁数据片段 ，引用被修改的记录。
补丁数据片段在读取和后台合并期间应用。

更新之后的 SELECT 性能：

比即时应用变更操作快两倍 。
相较完全更新后的数据，仅增加 20% 的开销。

开发者：Anton Popov。
