性能改进

最优表排序

MergeTree 表的物理存储顺序
由其 ORDER BY 键定义。

CREATE TABLE hits (CounterID UInt32, UserID UInt64, EventTime DateTime, URL String) ORDER BY (CounterID, UserID);

它有三个用途：
— 提供 索引 用于范围查询（可指定为 PRIMARY KEY）；
— 提供 合并键 用于 AggregatingMergeTree 或 ReplacingMergeTree 等合并模式；
— 通过聚集存放数据 提高压缩率 ；

能否自动选择获得最佳压缩效果的顺序？

开发者：Igor Markelov。

最优表排序

CREATE TABLE hits (CounterID UInt32, UserID UInt64, EventTime DateTime, URL String) ENGINE = MergeTree ORDER BY (CounterID, UserID) SETTINGS optimize_row_order = true;

— 按 ORDER BY 键排序后，它将自动对数据进一步排序，
  尽力获得最优压缩率！

演示

开发者：Igor Markelov。

插入时跳过二级索引的选项

加快 INSERT，并将二级索引
的计算推迟到后台合并时：

SET materialize_skip_indexes_on_insert = 0; SET materialize_statistics_on_insert = 0;

存在大量索引时很有用。

不会显著影响 SELECT 性能。

开发者：Anton Popov。

Hilbert 曲线

新函数： hilbertEncode, hilbertDecode.

类似于 mortonEncode, mortonDecode，但使用不同的曲线。

当两个键相似且希望混合它们的顺序时使用：

CREATE TABLE t (x UInt32, y UInt32, ...) ORDER BY hilbertEncode(x, y);

开发者：Artem Mustafin
