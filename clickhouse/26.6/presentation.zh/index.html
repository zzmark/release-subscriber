小而美的功能

ALTER TABLE … ADD ENUM VALUES

追加新的 Enum 值，无需重新输入所有现有值：

CREATE TABLE events (x Enum8('a' = 1, 'b' = 2)) ...; -- Before: ALTER ... MODIFY COLUMN x Enum8('a'=1,'b'=2,'c'=3,'d'=4) ALTER TABLE events MODIFY COLUMN x ADD ENUM VALUES('c' = 3, 'd' = 4); -- x is now Enum8('a' = 1, 'b' = 2, 'c' = 3, 'd' = 4)

— 纯元数据变更：即时完成，无需重写数据。
— 不会再误漏已有值。

开发者：Ilya Golshtein。

数值格式控制

控制文本输出的精度参数和小数点：

SELECT formatReadableSize(1234567890, 4); -- 1.1498 GiB (default precision is 2: 1.15 GiB) SELECT 1/3 SETTINGS output_format_float_precision = 4; -- 0.3333 SELECT 5.0 SETTINGS output_format_always_write_decimal_point… = 1; -- 5. (keep the decimal point even for whole numbers)

— formatReadableSize / formatReadableQuantity / formatReadableDecimalSize 接受可选的精度参数。

开发者：Antonio Filipovic、phulv94、Ilya Yatsishin。

级联可刷新物化视图

可刷新物化视图现在可由另一个 RMV 的刷新触发：

CREATE MATERIALIZED VIEW base REFRESH EVERY 1 HOUR ENGINE = MergeTree ORDER BY day AS …; CREATE MATERIALIZED VIEW rollup REFRESH DEPENDS ON base ENGINE = … AS SELECT day, sum(x) FROM base GROUP BY day;

开发者：Michael Kolupaev。

控制 projection 物化

两个新的 MergeTree 设置将 projection 构建与 INSERT 解耦：

CREATE TABLE ... SETTINGS materialize_projections_on_insert = 0; -- INSERTs skip building projection parts → faster ingestion CREATE TABLE ... SETTINGS materialize_projections_on_merge = 1; -- a merge rebuilds a projection missing from all its source parts

— 包含大量 projection 的表可更快写入；
  projection 改在合并期间构建。

开发者：Christoph Wurm。

IP 前缀配额

以子网而非单个地址作为配额键：

CREATE QUOTA q KEYED BY ip_address IPV4_PREFIX_BITS 24 FOR INTERVAL 1 hour MAX queries = 1000; -- every client in a /24 shares one quota bucket CREATE QUOTA q6 KEYED BY ip_address IPV6_PREFIX_BITS 64 …;

— 一次对整个网络范围实施速率限制。
— 可配合 IP_ADDRESS 和 FORWARDED_IP_ADDRESS 键使用。
— 对 IPv6 尤其有用。

开发者：Aditya Chopra。

PNG 输出格式

将查询结果渲染为图像。每行对应一个像素（r、g、b 或 v），
像素坐标（x、y）可隐式生成或显式定义：

WITH number DIV 1024 AS y, number MOD 1024 AS x, L2Norm((x - 512, y - 512)) / 512 AS radius, 60 AS stripe_size, round((atan2(x - 512, y - 512) / pi() * 180 + exp(radius) * 90) / stripe_size) * stripe_size AS alpha, radius <= 1 ? abs(1 - (radius - 0.5) * (radius - 0.5) * 4) : 0 AS a, colorOKLCHToSRGB((0.7, 0.15, alpha)) AS rgb SELECT rgb.1::UInt8 AS r, rgb.2::UInt8 AS g, rgb.3::UInt8 AS b, a FROM numbers(1048576) FORMAT PNG SETTINGS output_format_image_terminal_mode = 'kitty'

— Web UI 会直接显示图像。
— 适合生成热力图、迷你图和程序化艺术。

开发者：Maksim Dergousov。

SQL 兼容性

date_part 与 EXTRACT

date_part('unit', expr)
— PostgreSQL 风格的 EXTRACT(unit FROM expr) 简写：

SELECT date_part('year', toDateTime('2026-06-25 10:30:00')); -- 2026 SELECT date_part('doy', toDate('2026-06-25')); -- 176 (day of year) SELECT date_part('dow', toDate('2026-06-25')); -- 4 (day of week)

— 支持 PostgreSQL 的全部扩展单位：epoch、dow、doy、isodow、isoyear、century、decade、millennium。
— 还支持 EXTRACT(TIMEZONE_HOUR / TIMEZONE_MINUTE FROM dt)
 和 EXTRACT(… FROM INTERVAL n …)。

开发者：Alexey Milovidov、Vinayak Joshi。

其他函数与名称

新增更多 SQL 标准和 PostgreSQL 写法：

SELECT LOCALTIMESTAMP; -- now() → DateTime SELECT LOCALTIME; -- current time of day → Time SELECT SESSION_USER; -- alias of currentUser()

— 这些是保留字常量，无需括号。
— 让更多迁移查询和 BI 工具生成的 SQL 直接可用。

开发者：Thomas Cabral、Takumi Hara。

更多兼容性别名

min_by / max_by：面向 PostgreSQL、BigQuery 的 argMin、argMax 别名：

SELECT min_by(user, score), max_by(user, score) FROM t; -- aliases of argMin / argMax

REGEXP_SUBSTR：面向 Oracle/MySQL/Snowflake 的 regexpExtract 别名：

SELECT REGEXP_SUBSTR('order 12345 shipped', '[0-9]+'); -- 12345

“这些别名很蠢，真正的工程师都使用 ClickHouse 原始名称。”—— Changelog

ALTER TABLE MODIFY COLUMN x UInt32 NULL; -- same as Nullable(UInt32)

开发者：Joey Yu、Alexey Milovidov、Takumi Hara。

数组的 SOME / ALL

右侧使用数组字面量的 PostgreSQL 数组量词：

SELECT 3 = SOME([1, 2, 3]); -- 1 → rewritten to has(...) SELECT 5 > ALL([1, 2, 3]); -- 1 → arrayAll lambda SELECT 2 <> ALL([1, 3, 5]); -- 1

ANY / SOME / ALL 的子查询形式仍会降级为 IN / NOT IN。

开发者：Alexey Milovidov。

按名称模式选择列

使用 * LIKE 和 * ILIKE 选择列，无需逐一列出：

SELECT * ILIKE '%user%' FROM events; -- user_id, user_name, ... (case-insensitive) SELECT t.* ILIKE '%id', count() FROM t GROUP BY ALL; -- qualified form works too

类似 * MATCH 'regexp' 和 COLUMNS('regexp')，
但使用 SQL 风格 LIKE 模式，而不是正则表达式。

开发者：Yue Ni。

LIKE 中的 ESCAPE

定义自定义转义字符，使 % 和 _ 可作为字面字符：

SELECT '50% off' LIKE '50!% off' ESCAPE '!'; -- 1 (the !% matches a literal percent sign) SELECT 'a_b' LIKE 'a!_b' ESCAPE '!'; -- 1 (the !_ matches a literal underscore)

— SQL 标准语法，PostgreSQL、MySQL 等也支持。

开发者：Ilya Yatsishin。

性能改进

ClickHouse Keeper 提速 2 倍

一系列 Keeper 改进使整体速度提升到原来的两倍以上：

— 改进请求批处理。
— 以流水线方式向 leader 发送消息。
— 以流水线方式追加日志。
— 将快照 I/O 移至后台线程（nuraft_use_bg_thread_for_snapshot_io）。
— 降低应用接收快照时的峰值内存。

在 keeper-bench 的真实工作负载下：

26.5：2899 RPS，延迟 41.4 ms
26.6：7230 RPS，延迟 18.3 ms

开发者：Michael Kolupaev、Antonio Andelic、Mikhail Filimonov。

更轻、更快的查询启动

简单查询的单次查询开销显著降低：

SELECT count() FROM hits; -- parsing + analysis + planning ~50% faster from a single connection

更多分析器优化，且均默认启用：

— 在分析期间缓存标识符解析结果。
— 快速分析深度嵌套子查询。
— 加快深度嵌套函数调用的解析。
— 加快对变化中访问控制实体的处理。

对 1200 列表执行深度嵌套的 SELECT *：
 分析耗时 1.46 s → 0.023 s  （约 64 倍），26.5 对比 26.6。

开发者：Raúl Marín、Dmitry Novik、Max Justus Spransy、Azat Khuzhin。

更快的主键分析

长主键或高基数主键过去会拖慢索引分析。

现在默认启用 use_lightweight_primary_key_index_analysis：

— 对较长的主键，分析时间取决于查询实际用于过滤的列，
 而不再取决于键的长度。
 扩展排序键现在几乎不会增加索引分析成本。

— 对高基数键，分析仅处理具有选择性的内存前缀，
 无需加载完整键。

开发者：Nihal Z. Miaji。

更快的排序

通用比较排序现在采用 ipnsort
和 driftsort 的 C++ 移植实现：

— 加快非数值列上的 ORDER BY 和稳定排序。
— 消除输入已反向排序时的最坏情况。
— 使用先进、自适应且经过充分验证的算法。

单线程对 2000 万个字符串执行 ORDER BY：
 7.1 s → 5.9 s  （约 1.2 倍），26.5 对比 26.6。

开发者：Alexey Milovidov。

更快的 GROUP BY 与 JOIN

— 面向高基数、均匀分布键的分片聚合
 （enable_sharding_aggregator = 1）：对键进行哈希，把行分散到不同线程，
 每个线程聚合互不重叠的子集，无需合并阶段。
— 对字符串键 GROUP BY 执行哈希表预取，速度提高约 8%。
— 合并大型两级聚合状态（如 groupArray）时降低峰值内存。
— 更高效地处理聚合中的 Nullable 列。
— 在 HashJoin 和 Set 中使用紧凑的 keys32 / keys64 方法。

实测：3 亿行高基数 GROUP BY，16 线程：
  enable_sharding_aggregator: 2.31 s → 1.87 s.

开发者：Nihal Z. Miaji、Le Zhang、Yuri Fedoseev、Nikita Taranov。

LIMIT BY 的多项优化

LIMIT BY 新增一系列优化，全部默认启用：

— 执行 ORDER BY 时，如果 LIMIT BY 键是排序键前缀，
 则在每个并行排序 stream 内执行 LIMIT BY。
— 按主键顺序流式执行 LIMIT N BY cols，每个 stream 只需 O(1) 内存。
— 当分区是键的函数时，按分区并行应用 LIMIT BY。
— 删除冗余或单射键表达式
  (LIMIT 5 BY toString(x) → LIMIT 5 BY x).

实测：对 5000 万行 MergeTree 执行 LIMIT 3 BY g（g 位于排序键中）：
 内存 86 MiB → 22 MiB（约 4 倍），耗时 0.15 s → 0.09 s。

开发者：Nihal Z. Miaji。

JOIN 优化

JOIN 规划器与运行时新增一批改进，大多默认启用：

— 默认启用 enable_join_transitive_predicates，
 可跨 JOIN 下推推导出的谓词，无额外成本地过滤两侧。
— 构建侧 FixedHashMap 同时用作探测侧运行时过滤器。
— JOIN 后接高选择性 LIMIT、TopN 或另一个 JOIN 时，延迟创建 selector / replication index。
— ASOF JOIN 现在可使用 parallel_hash。
— HashJoin 使用紧凑 keys32 / keys64，并为单行探测提供快速路径。
— 动态规划连接重排现在支持并行副本。

开发者：A. Gololobov、N. Taranov、H. Selmi、Xiaozhe Yu、G. Maher。

值得关注的功能

持续查询 🧪

永不结束的 SELECT，这是迈向流式查询的第一步。 追加 STREAM 后，查询会随着新行插入持续输出：

SET enable_streaming_queries = 1; SELECT id, msg FROM live_events STREAM; -- blocks, keeps streaming

应用场景：对事件流执行过滤和实时告警。

使用 cursor 的高级用法：

SELECT _block_number AS bn, _block_offset AS bo, id, msg FROM events STREAM CURSOR {'all': {'block_number': 2, 'block_offset': 0}}

开发者：Mikhail Artemenko。

多阶段分布式查询执行 🧪

实验性分布式规划器把查询计划拆成由 exchange 连接的多个阶段，
并将计划片段发送到 worker 节点：

— 支持 scatter / broadcast / gather / shuffle exchange。
— 支持分布式 shuffle、broadcast hash join、shuffle 聚合和分布式排序。
— 阶段间数据通过 TCP 或对象存储中的临时文件流式传输。
— 每台主机可运行多个 worker（stateless_worker_port / streaming_exchange_port）。

通过新设置 make_distributed_plan 控制。

开发者：Alexander Gololobov。

工作负载内存预留

工作负载调度器原本已管理 CPU、I/O 和并发， 现在也能管理内存：

CREATE RESOURCE memory (MEMORY RESERVATION); CREATE WORKLOAD all; CREATE WORKLOAD prod IN all SETTINGS max_memory = '100G'; CREATE WORKLOAD reports IN all SETTINGS max_memory = '20G'; CREATE WORKLOAD vasya IN reports SETTINGS weight = 1; CREATE WORKLOAD petya IN reports SETTINGS weight = 2; -- route a query to a workload: SELECT … SETTINGS workload = 'prod'; -- reserve memory before processing: SET reserve_memory = '5G';

开发者：Sergei Trifonov。

假设性索引 + EXPLAIN WHATIF

无需实际构建，即可回答“如果有这个跳数索引会怎样？”：

CREATE HYPOTHETICAL INDEX idx_level ON logs (level) TYPE set(2) GRANULARITY 4; EXPLAIN WHATIF SELECT count() FROM logs WHERE level = 'error';

Baseline (PK + partition + existing indexes): marks: 612, 19.56 MiB With idx_level (set, hypothetical): status: applicable marks: 200 (was 612) est_bytes: 6.39 MiB skip_ratio: 67.3% Estimation: empirical, sampled 5/5 parts

— 作用域为当前会话，可在 system.hypothetical_indexes 中查看。
基于数据调整索引。

开发者：Yarik Briukhovetskyi。

aiEmbed 🧪

通过 LLM API 在 ClickHouse 内部生成文本嵌入：

SELECT aiEmbed('qwen3-8b', review_text) AS embedding FROM reviews LIMIT 10; -- Array(Float32) per row, ready for cosineDistance / vector search

— 不离开 SQL 即可构建语义搜索或 RAG 流水线。
— 配合新的量化函数构建紧凑向量索引。
— 实验性功能，需要配置嵌入服务提供方和模型。

开发者：George Larionov。

量化函数

将嵌入分量压缩到 8 位及以下的标量编解码器：

SELECT quantizeBFloat16ToInt8(1.5::BFloat16); -- 107 SELECT dequantizeInt8ToBFloat16(quantizeBFloat16ToInt8(1.5::BFloat16)); -- 1.5 (near-lossless round-trip)

— 256 级高斯 Lloyd–Max 量化器，每个分量占一个字节。
— 通过截断位得到 Int4 / Int2 / 二进制编码，以召回率换取更小体积。
— 将向量索引缩小 4 倍或更多，降低相似度搜索成本。

开发者：Alexey Milovidov。
