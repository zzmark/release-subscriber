<h4 id="266-backward-incompatible-change">
  向后不兼容变更
</h4>

* 移除 `allow_experimental_query_deduplication` 功能。该功能长期处于实验状态，缺少测试且不会获得支持（最初的测试不稳定，已在 [#49579](https://github.com/ClickHouse/ClickHouse/pull/49579) 中移除）。[#99398](https://github.com/ClickHouse/ClickHouse/pull/99398)（[Igor Nikonov](https://github.com/devcrafter)）。
* 基于 XRay 的 `SYSTEM INSTRUMENT` 功能现在使用 `arguments`，不再使用 `parameters`：`system.instrumentation.parameters` 列更名为 `arguments`，`SYSTEM INSTRUMENT ADD ... HANDLER PARAMETERS ...` 语法更名为 `SYSTEM INSTRUMENT ADD ... HANDLER ARGUMENTS ...`。使用旧列名或旧语法的查询与自动化脚本必须改用新名称；旧名称不再受支持。[#103854](https://github.com/ClickHouse/ClickHouse/pull/103854)（[Pablo Marcos](https://github.com/pamarcos)）。
* 设置 `show_data_lake_catalogs_in_system_tables` 更名为 `show_remote_databases_in_system_tables`，适用范围也有所扩大：当其值为 0（默认值）时，除了数据湖目录外，`MySQL` 和 `PostgreSQL` 数据库也会从 `system.tables`、`system.columns` 和 `system.completions` 中隐藏。旧设置名保留为别名。[#104416](https://github.com/ClickHouse/ClickHouse/pull/104416)（[Pablo Marcos](https://github.com/pamarcos)）。
* 默认 x86 构建的目标架构由 x86-64-v2（SSE4.2）改为 x86-64-v3（AVX2）。这要求 CPU 支持 AVX2（Intel Haswell 或更新架构、AMD Excavator 或更新架构）。如果 CPU 不支持 AVX2，请使用以基础 x86-64 为目标的 `amd64compat` 构建。[#105019](https://github.com/ClickHouse/ClickHouse/pull/105019)（[Raúl Marín](https://github.com/Algunenano)）。
* `min`/`max` 聚合函数和 `minmax` 索引现在会拒绝嵌套的 `Dynamic`/`Variant`。此前只检查顶层的 `Dynamic`/`Variant`。关闭 [#104747](https://github.com/ClickHouse/ClickHouse/issues/104747)。[#105468](https://github.com/ClickHouse/ClickHouse/pull/105468)（[Pavel Kruglov](https://github.com/Avogar)）。
* `icebergHash` 和 `icebergBucket` 现在会明确报错并拒绝 `Int128`、`UInt128`、`Int256`、`UInt256` 与 `Decimal256` 参数。此前它们会静默截断更宽的值，从而产生哈希冲突。Iceberg 规范只为 32/64 位整数及精度不超过 38 的十进制数定义了哈希；对于处于相应范围内的值，如需保持原行为，请转换为 `Int64` 或 `Decimal128`。[#105866](https://github.com/ClickHouse/ClickHouse/pull/105866)（[Raúl Marín](https://github.com/Algunenano)）。
* CLI 新增对查询回显的细粒度控制。`--echo` 选项现在接受可选的布尔值，并可在交互模式和批处理模式中使用。新选项 `--echo-formatted` 与 `--echo-query-id` 分别控制是否格式化回显的查询，以及是否输出 `query_id`。`--hilite`/`--highlight` 现在也会控制回显查询的高亮。相应地，`--echo` 现在是布尔值选项，因此紧跟在裸 `--echo` 后面的定位查询会被当作其取值；请改用 `--echo --query "..."` 或 `--echo=false`。[#106191](https://github.com/ClickHouse/ClickHouse/pull/106191)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 移除实验性 KQL（Kusto）函数 `array_sort_asc`、`array_sort_desc`，以及它们的 SQL 后端 `kql_array_sort_asc`、`kql_array_sort_desc`。这些函数仍属实验性、实现质量较低，并引发了正确性和解析器问题。使用这些名称的查询现在会返回 `UNKNOWN_FUNCTION`。[#108101](https://github.com/ClickHouse/ClickHouse/pull/108101)（[Groene AI](https://github.com/groeneai)）。
* 当源表在所请求分区中没有任何 part 时，`ALTER TABLE ... REPLACE PARTITION ... FROM ...` 不再静默删除目标分区数据。此前这类请求会移除目标分区，却不写入任何替代数据，存在误操作导致数据丢失的风险。现在默认以 `BAD_ARGUMENTS` 拒绝该操作。若要恢复旧的静默清空行为，请将新设置 `allow_replace_partition_from_empty_source` 设为 `1`，或将 `compatibility` 设为 `26.5` 或更低版本；若要显式删除目标数据，请使用 `ALTER TABLE ... DROP PARTITION`。[#104939](https://github.com/ClickHouse/ClickHouse/pull/104939)（[Groene AI](https://github.com/groeneai)）。
* 服务器设置 `insert_deduplication_version` 的默认值由 `compatible_double_hashes` 改为 `new_unified_hash`。插入去重现在作用于整个插入块（每次插入），而不是逐个 part/partition：重试同一次插入仍会被去重；但两个不同插入即使生成相同 part，也不会再被跨插入去重；对相同行重新排序后插入，也不会再被去重。设置 `insert_deduplication_version = compatible_double_hashes` 可恢复旧行为。对于直接从默认使用 `old_separate_hashes` 的版本升级的实例，应先使用 `compatible_double_hashes` 运行，直至最长的相关去重窗口过去，再依赖 `new_unified_hash`。[#107886](https://github.com/ClickHouse/ClickHouse/pull/107886)（[Sema Checherinda](https://github.com/CheSema)）。

<h4 id="266-new-feature">
  新功能
</h4>

* 新增对 `MergeTree` 表持续查询的支持，通过一系列快照读取实现。这是迈向通用流式查询支持的第一步。[#105114](https://github.com/ClickHouse/ClickHouse/pull/105114)（[Mikhail Artemenko](https://github.com/Michicosun)）。
* 新增假设性（what-if）跳数索引。使用 `CREATE HYPOTHETICAL INDEX ... ON t (expr) TYPE ...` 定义会话级虚拟跳数索引，再通过 `EXPLAIN WHATIF SELECT ...` 在不物化索引的情况下估算其数据跳过比例与成本。已定义的索引可在新表 `system.hypothetical_indexes` 中查看。[#104608](https://github.com/ClickHouse/ClickHouse/pull/104608)（[Yarik Briukhovetskyi](https://github.com/yariks5s)）。
* `clickhouse-server` 新增内嵌的 `/schema` Web UI，用于可视化表、物化视图、可刷新物化视图、字典、分布式表和普通视图之间的依赖关系图。[#105276](https://github.com/ClickHouse/ClickHouse/pull/105276)（[Nikita Mikhaylov](https://github.com/nikitamikhaylov)）。
* 新增 `PNG` 输出格式，可将查询结果直接渲染为 PNG 图像。[#74691](https://github.com/ClickHouse/ClickHouse/pull/74691)（[Maksim Dergousov](https://github.com/m7kss1)）。
* 新增基于环境变量检测调用 `clickhouse-client` 或 `clickhouse-local` 的 AI 编码代理（Claude Code、Cursor、Codex、Gemini CLI、Goose 等）的能力。检测结果会记录到 `system.query_log`、`system.query_thread_log` 和 `system.processes` 的新列 `client_agent` 中。[#106619](https://github.com/ClickHouse/ClickHouse/pull/106619)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增系统表 `system.documentation`，将系统中各类统一组件（函数、表引擎、数据类型、设置、格式等）的内嵌参考文档汇集到一张表中，并以 Markdown 形式呈现文档。[#107463](https://github.com/ClickHouse/ClickHouse/pull/107463)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `GeoJSON` 输入格式，用于读取 [GeoJSON](https://geojson.org/) `FeatureCollection` 文档；每个 feature 生成一行，包含 `id`（`String`）、`geometry`（`Geometry`）和 `properties`（`Nullable(JSON)`）列。`Point`、`LineString`、`MultiLineString`、`Polygon` 与 `MultiPolygon` 几何会读入 ClickHouse 原生 `Geometry` 类型。由于 `Geometry` 类型无法表示 `GeometryCollection` 和 `MultiPoint`，默认会抛出异常；也可通过 `input_format_geojson_unsupported_geometry_handling` 设置将其存为 `NULL`。为 [#91533](https://github.com/ClickHouse/ClickHouse/issues/91533) 作出贡献。[#98124](https://github.com/ClickHouse/ClickHouse/pull/98124)（[Mark Needham](https://github.com/mneedham)）。
* 新增直接通过 SQL 提供 Mapbox Vector Tiles 的函数：`MVTEncodeGeom` 将几何投影到滑动地图瓦片的像素空间并进行裁剪；`MVTEncode` 将一组已投影几何聚合为单图层瓦片的二进制字节；`MVTBoundingBox` / `MVTBoundingBoxMercator` 返回瓦片边界框，用于限制参与查询的行。支持点、线和多边形几何，也可通过 PostGIS 别名 `ST_AsMVTGeom` 和 `ST_AsMVT` 使用。[#106107](https://github.com/ClickHouse/ClickHouse/pull/106107)（[Saarthak Gupta](https://github.com/saarthak2002)）。
* `clickhouse-local` 现在支持 `SYSTEM START LISTEN` 和 `SYSTEM STOP LISTEN` 查询，可将其转变为接受 TCP 与 HTTP 连接的服务器。[#101143](https://github.com/ClickHouse/ClickHouse/pull/101143)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* `clickhouse-client` 和 `clickhouse-local` 新增交互式 `help` 命令。输入 `help <name>`（也可使用 `/help`、`man`、`/man`）会显示函数、表引擎、数据类型、格式、设置或其他组件的文档，并在终端中以 Markdown 和语法高亮 SQL 呈现。名称存在歧义时会显示所有匹配项；找不到时则会建议相近名称。[#108042](https://github.com/ClickHouse/ClickHouse/pull/108042)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 支持写入 Azure Data Lake Storage Gen2。[#105406](https://github.com/ClickHouse/ClickHouse/pull/105406)（[Konstantin Vedernikov](https://github.com/scanhex12)）。
* 新增 `RowBinaryWithNamesAndTypesAndDefaults` 格式，更好地支持 schema 演进。[#105736](https://github.com/ClickHouse/ClickHouse/pull/105736)（[Mark Zitnik](https://github.com/mzitnik)）。
* 在 `ALTER TABLE` 查询中实现 `ADD ENUM VALUES`，向现有 `Enum` 类型追加新值时无需重新列出全部已有枚举值。[#93830](https://github.com/ClickHouse/ClickHouse/pull/93830)（[Ilya Golshtein](https://github.com/ilejn)）。
* 可刷新物化视图现在支持 `REFRESH DEPENDS ON`，可由另一个 RMV 的刷新触发，而非按时间调度。（此前已有 `REFRESH EVERY ... DEPENDS ON`，但无法可靠用于此场景。）参见 `CREATE MATERIALIZED VIEW` 文档。[#104440](https://github.com/ClickHouse/ClickHouse/pull/104440)（[Michael Kolupaev](https://github.com/al13n321)）。
* 支持通过 `* LIKE '<pattern>'` 和 `* ILIKE '<pattern>'` 按名称模式选择列，也支持 `table.* LIKE '<pattern>'`、`table.* ILIKE '<pattern>'` 等带限定符形式。`LIKE` 区分列名大小写，`ILIKE` 不区分大小写。[#104569](https://github.com/ClickHouse/ClickHouse/pull/104569)（[Yue Ni](https://github.com/niyue)）。
* 新增 `ESCAPE` 语法，可在 `LIKE` 模式中定义自定义转义字符，从而将 `%` 和 `_` 作为字面字符而非通配符处理。[#99774](https://github.com/ClickHouse/ClickHouse/pull/99774)（[Ilya Yatsishin](https://github.com/qoega)）。
* 新增 `MergeTree` 表设置 `materialize_projections_on_insert` 与 `materialize_projections_on_merge`。当 `materialize_projections_on_insert = 0` 时，`INSERT` 会跳过 projection part 的构建，可提高具有大量 projection 的表的插入吞吐量；当 `materialize_projections_on_merge = 1` 时，若全部源 part 都缺少某个 projection，合并会重新构建它，使 projection 可在合并期间而非插入期间生成。合并仍只会组合具有相同 projection 集合的 part。[#100993](https://github.com/ClickHouse/ClickHouse/pull/100993)（[Christoph Wurm](https://github.com/cwurm)）。
* 新增不可变的 `MergeTree` 设置 `allow_tuple_element_aggregation`，默认关闭。启用后，`SummingMergeTree`、`AggregatingMergeTree` 和 `CoalescingMergeTree` 会在合并时递归展开 `Tuple` 列，并像处理顶层列一样独立聚合每个叶子元素：`SummingMergeTree` 对其求和，`AggregatingMergeTree` 合并其聚合函数状态，`CoalescingMergeTree` 保留最后一个非 NULL 值。该设置必须在建表时指定，不支持它的引擎会静默忽略。[#98039](https://github.com/ClickHouse/ClickHouse/pull/98039)（[johnjing](https://github.com/JingYanchao)）。
* 新增函数 `quantizeBFloat16ToInt8` 和 `dequantizeInt8ToBFloat16`：这是一种标量编解码器，使用 256 级高斯 Lloyd-Max 量化器将嵌入分量压缩到 8 位，并可通过截断位提取 Int4、Int2 或二进制编码。[#108102](https://github.com/ClickHouse/ClickHouse/pull/108102)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增函数 `arrayTopK` 与 `arrayBottomK`：`arrayTopK(k, array)` 按降序返回最大的 K 个元素；`arrayBottomK(k, array)` 按升序返回最小的 K 个元素。[#104563](https://github.com/ClickHouse/ClickHouse/pull/104563)（[Vitaly Baranov](https://github.com/vitlibar)）。
* 新增系统表 `system.iceberg_files`，用于公开 `Iceberg` 表的逐文件元数据；每张表当前快照中的每个数据文件或删除文件对应一行。关闭 [#98777](https://github.com/ClickHouse/ClickHouse/issues/98777)。[#104415](https://github.com/ClickHouse/ClickHouse/pull/104415)（[Asya Shneerson](https://github.com/asya-ch)）。
* 新增 `system.constraints` 表，提供所有表中全部 `CHECK` 与 `ASSUME` 约束的信息，包括约束名称、类型和表达式。[#105337](https://github.com/ClickHouse/ClickHouse/pull/105337)（[Pedro Ferreira](https://github.com/PedroTadim)）。
* 新增 `system.dictionary_layouts` 表，列出可用的字典布局及其内嵌文档（`description`、`syntax`、`examples`、`introduced_in`、`related`）。[#106182](https://github.com/ClickHouse/ClickHouse/pull/106182)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `system.dictionary_sources` 表，列出可用的字典数据源及其内嵌文档（`description`、`syntax`、`examples`、`introduced_in`、`related`）。[#106184](https://github.com/ClickHouse/ClickHouse/pull/106184)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `system.data_skipping_index_types` 表，列出可用的数据跳过索引类型及其内嵌文档（`description`、`syntax`、`examples`、`introduced_in`、`related`）。[#106186](https://github.com/ClickHouse/ClickHouse/pull/106186)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `system.disk_types` 表，列出可用的磁盘类型及其内嵌文档（`description`、`syntax`、`examples`、`introduced_in`、`related`）。[#106187](https://github.com/ClickHouse/ClickHouse/pull/106187)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 实现 `SYSTEM RESTART DISK <name>`：该命令会重新加载磁盘的内存元数据，并重新扫描位于该磁盘上的只读副本表的数据 part。这样，共享 `plain_rewritable` 存储上的只读副本便可按需看到另一台服务器写入的数据，无需等待 `refresh_parts_interval` 或重启服务器。[#106645](https://github.com/ClickHouse/ClickHouse/pull/106645)（[Jordi Villar](https://github.com/jrdi)）。
* 现在支持 PostgreSQL 风格的 `expr OP SOME(array)` / `expr OP ALL(array)`（右侧不是子查询）：对于 `=`/`<>` 会重写为 `has` / `NOT has`，其他比较运算符则重写为 `arrayExists` / `arrayAll` lambda。数组形式不接受 `ANY`，因为 `any` 同时也是聚合函数；请使用 `SOME`。`ANY`/`SOME`/`ALL` 的子查询形式仍会降级为 `IN` / `NOT IN`。[#105129](https://github.com/ClickHouse/ClickHouse/pull/105129)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增两种 `load_balancing` 策略 `hostname_longest_common_prefix` 和 `hostname_longest_common_suffix`，优先选择主机名与发起方主机名具有最长公共前缀（或后缀）的副本。数据中心编码在主机名前缀或后缀、且数字片段长度不固定时，现有 `nearest_hostname` 与 `hostname_levenshtein_distance` 可能选错副本，这两种策略可解决该问题。[#107360](https://github.com/ClickHouse/ClickHouse/pull/107360)（[Denny \[Innervate DBA\]](https://github.com/den-crane)）。
* `system.session_log` 表新增 TLS 客户端证书信息（主体、序列号、颁发者和有效期），提升基于证书认证的可观测性。[#107679](https://github.com/ClickHouse/ClickHouse/pull/107679)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 为 `S3` 基于角色的访问新增可选 `external_id` 凭据。[#106941](https://github.com/ClickHouse/ClickHouse/pull/106941)（[Elian Gidoni](https://github.com/eliangidoni)）。
* 新增 `S3Queue` 设置 `after_processing_move_preserve_path`。与 `after_processing='move'` 和 `after_processing_move_prefix` 一同启用时，已处理对象移动到目标前缀下仍会保留完整源路径，而不是展平为只有文件名。[#105354](https://github.com/ClickHouse/ClickHouse/pull/105354)（[Asya Shneerson](https://github.com/asya-ch)）。
* 新增服务器设置 `message_queue_disable_insertion`，用于禁止消息队列引擎（`Kafka`、`RabbitMQ`、`NATS`）向所附加的物化视图插入数据，适用于只读副本场景。[#104911](https://github.com/ClickHouse/ClickHouse/pull/104911)（[JIaQi Tang](https://github.com/JiaQiTang98)）。
* 新增 `LOCALTIME` 和 `LOCALTIMESTAMP`（SQL 标准 / PostgreSQL 语法）。`LOCALTIMESTAMP` 是 `now()` 的别名（返回 `DateTime`）；`LOCALTIME` 以 `Time` 值返回当前一天中的时间。[#106139](https://github.com/ClickHouse/ClickHouse/pull/106139)（[Thomas Cabral](https://github.com/thomas-cabral)）。
* 新增 `date_part('unit', expr)`，作为 `EXTRACT(unit FROM expr)` 的语法糖。支持所有标准时间间隔类型，以及 PostgreSQL 扩展项（`epoch`、`dow`、`doy`、`isodow`、`isoyear`、`century`、`decade`、`millennium`）。[#105127](https://github.com/ClickHouse/ClickHouse/pull/105127)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增兼容 PostgreSQL 的 `EXTRACT(TIMEZONE_HOUR FROM dt)` 与 `EXTRACT(TIMEZONE_MINUTE FROM dt)`，用于获取时区偏移的小时和分钟部分；并新增 `EXTRACT(<unit> FROM INTERVAL n <unit>)` / `date_part('<unit>', INTERVAL n <unit>)`，用于从时间间隔中提取数值。[#106227](https://github.com/ClickHouse/ClickHouse/pull/106227)（[Vinayak Joshi](https://github.com/vinayakj592)）。
* 为 `argMin` 和 `argMax` 新增聚合别名 `min_by` 与 `max_by`。[#105712](https://github.com/ClickHouse/ClickHouse/pull/105712)（[Joey Yu](https://github.com/itsjoeoui)）。这些别名很蠢，真正的工程师会使用 ClickHouse 原本的名称。
* 新增 `REGEXP_SUBSTR`，作为 `regexpExtract` 不区分大小写的别名，以兼容 Oracle/MySQL/Snowflake。[#105122](https://github.com/ClickHouse/ClickHouse/pull/105122)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 新增 `SESSION_USER`，作为 `currentUser()` 不区分大小写的别名，以兼容 PostgreSQL / SQL 标准。[#106081](https://github.com/ClickHouse/ClickHouse/pull/106081)（[Takumi Hara](https://github.com/takumihara)）。
* `ALTER TABLE ... ADD/MODIFY COLUMN` 支持尾随的 `NULL` / `NOT NULL` 修饰符，与 `CREATE TABLE` 保持一致。[#106150](https://github.com/ClickHouse/ClickHouse/pull/106150)（[Takumi Hara](https://github.com/takumihara)）。
* 现在可以使用 h3 的 `h3PolygonToCellsWithContainment` 函数调用其新算法；该算法支持基于中心点、完全包含和重叠三种包含模式。[#104455](https://github.com/ClickHouse/ClickHouse/pull/104455)（[Youssef Kadry](https://github.com/yousefQadry)）。
* 使用 `IP_ADDRESS` 或 `FORWARDED_IP_ADDRESS` 作为键时，新增 `IPV4_PREFIX_BITS` 与 `IPV6_PREFIX_BITS` 标志。[#89270](https://github.com/ClickHouse/ClickHouse/pull/89270)（[Aditya Chopra](https://github.com/adityachopra29)）。
* `formatReadableTimeDelta` 现在接受除 `Month` 和 `Year` 之外其他类型的 `INTERVAL` 表达式作为输入。[#64315](https://github.com/ClickHouse/ClickHouse/pull/64315)（[Francisco J. Jurado Moreno](https://github.com/Beetelbrox)）。

<h4 id="266-experimental-feature">
  实验性功能
</h4>

* 多阶段分布式查询执行：规划器把查询计划拆成多个阶段，各阶段通过 scatter / broadcast / gather / shuffle 交换相连，并将计划片段分派给工作节点。阶段间数据通过 TCP 流式传输，或经共享对象存储中的临时文件传递；该路径支持分布式 shuffle 与广播哈希连接、shuffle 聚合和分布式排序。该功能仍属实验性，默认关闭。[#106020](https://github.com/ClickHouse/ClickHouse/pull/106020)（[Alexander Gololobov](https://github.com/davenger)）。实验性分布式查询计划引擎（`make_distributed_plan`）现在可为每个 worker 使用不同的任务分派与流式交换端口，可在 `<remote_servers>` 中通过每个副本的 `stateless_worker_port` 和 `streaming_exchange_port` 配置。未设置时仍使用原服务器级端口（`stateless_worker_client.port` 和 `distributed_query.streaming_exchange.port`），从而可在同一主机运行多个 worker。[#107885](https://github.com/ClickHouse/ClickHouse/pull/107885)（[Alexander Gololobov](https://github.com/davenger)）。
* 为内连接新增实验性 `dphyp` 连接重排算法，可作为 `query_plan_optimize_join_order_algorithm` 设置的选项；同时新增 `query_plan_optimize_join_order_max_searched_plans` 设置，用于限制连接顺序搜索规模，超过上限时回退到算法链中的下一个算法。设为 `0` 可保留此前不设上限的搜索行为。[#98798](https://github.com/ClickHouse/ClickHouse/pull/98798)（[Alexander Gololobov](https://github.com/davenger)）。
* 新增 `aiEmbed` 函数，可在 ClickHouse 内调用 LLM API 生成嵌入向量。[#102922](https://github.com/ClickHouse/ClickHouse/pull/102922)（[George Larionov](https://github.com/george-larionov)）。
* 新增实验性 Linux OOM 金丝雀：这是一个牺牲型子进程，Linux OOM killer 会优先于主服务器进程终止它。通过 `oom_canary_enable` 启用后，它会清理分配器缓存、取消查询、取消合并，并在 `system.crash_log` 中记录事件，从而缓解内存压力。OOM 响应需要 cgroup v2 `memory.events` 提供 OOM-kill 证据。[#101942](https://github.com/ClickHouse/ClickHouse/pull/101942)（[Peng](https://github.com/fastio)）。
* `/webterminal` Web 终端界面现已成为生产功能并默认启用，由新的服务器设置 `enable_webterminal` 控制；原 `allow_experimental_webterminal` 设置已弃用，但为向后兼容仍会生效。若要禁用该端点，请将 `enable_webterminal` 设为 `false`。[#106255](https://github.com/ClickHouse/ClickHouse/pull/106255)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* PromQL HTTP 端点现在支持通过 URL 查询参数指定数据库和表（`database=`、`table=` 或 `table=db.table`）。此前隐式回退到 `default.prometheus` 表的行为已移除：若处理器配置和 URL 均未指定表，处理器会返回 `The time series table name is not set`。若要保留旧行为，请配置 `<table>default.prometheus</table>`，或在 URL 中传入 `table=...`。[#107553](https://github.com/ClickHouse/ClickHouse/pull/107553)（[Vitaly Baranov](https://github.com/vitlibar)）。
* `prometheusQuery` 与 `prometheusQueryRange` 表函数新增对 PromQL `histogram_quantile` 函数的支持，可基于由 `le` 标签标识的经典 Prometheus 直方图桶计算分位数。[#103477](https://github.com/ClickHouse/ClickHouse/pull/103477)（[Joe Smith](https://github.com/Yasumoto)）。
* 文本索引新增倒排列表延迟应用模式。通过 `SET allow_experimental_text_index_lazy_apply = 1` 和 `SET text_index_posting_list_apply_mode = 'lazy'` 启用后，倒排列表会采用基于游标的方法，按打包块粒度按需解码，而不是完整物化为 Roaring Bitmap，从而降低选择性文本索引查询的内存占用和 CPU 时间。[#100035](https://github.com/ClickHouse/ClickHouse/pull/100035)（[Peng](https://github.com/fastio)）。

* 允许在主 HTTP 端口挂载 Prometheus 处理器，并可指定可选前缀。[#104975](https://github.com/ClickHouse/ClickHouse/pull/104975)（[James Cunningham](https://github.com/JTCunning)）。

<h4 id="266-performance-improvement">
  性能改进
</h4>

* 对 Keeper 进行多项改进，使整体速度提高约 2 倍，包括改进批处理、向 leader 流水线发送消息，以及流水线追加日志。[#101757](https://github.com/ClickHouse/ClickHouse/pull/101757)（[Michael Kolupaev](https://github.com/al13n321)）。
* 降低简单 `SELECT` 查询在解析、分析和规划阶段的逐查询开销。例如，通过单个连接执行 `SELECT count() FROM hits` 的速度提高约 50%。[#104513](https://github.com/ClickHouse/ClickHouse/pull/104513)（[Raúl Marín](https://github.com/Algunenano)）。
* 优化长主键和高基数主键的主键索引分析。对于长主键，索引分析耗时现在主要取决于查询过滤条件的复杂度（实际使用的键列），而非主键长度；因此，若查询只过滤少数列，扩展排序键几乎不会增加索引分析开销。对于高基数主键，ClickHouse 只在内存中保留有选择性的键列前缀而不加载尾部列；索引分析现在也只处理该内存前缀，不再处理整个键。此优化默认启用，可通过新设置 `use_lightweight_primary_key_index_analysis` 关闭。关闭 [#65103](https://github.com/ClickHouse/ClickHouse/issues/65103)。[#91836](https://github.com/ClickHouse/ClickHouse/pull/91836)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 默认 x86 构建的目标架构由 x86-64-v2（SSE4.2）改为 x86-64-v3（AVX2）。这要求 CPU 支持 AVX2（Intel Haswell 或更新架构、AMD Excavator 或更新架构）。若 CPU 不支持 AVX2，请使用面向基础 x86-64 的 `amd64compat` 构建。[#105019](https://github.com/ClickHouse/ClickHouse/pull/105019)（[Raúl Marín](https://github.com/Algunenano)）。
* 通用比较排序改用 `ipnsort` 和 `driftsort`（稳定排序），它们是 Rust 标准库排序实现的 C++ 移植版。该变更加速非数值列上的 `ORDER BY` 与稳定排序，并消除了逆序输入下的一种最坏情况。[#106650](https://github.com/ClickHouse/ClickHouse/pull/106650)（[Alexey Milovidov](https://github.com/alexey-milovidov)）。
* 针对均匀分布的高基数键新增 `GROUP BY` 优化：对分组键进行哈希，将行分散到不同线程，使每个线程聚合互不重叠的键子集，无需合并阶段。设置 `enable_sharding_aggregator = 1` 可启用。[#104233](https://github.com/ClickHouse/ClickHouse/pull/104233)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 为字符串键 `GROUP BY` 查询启用哈希表预取，使高基数字符串聚合性能提升约 8%。[#101007](https://github.com/ClickHouse/ClickHouse/pull/101007)（[Le Zhang](https://github.com/damahua)）。
* 合并带有大型聚合状态（如 `groupArray`）的部分两级聚合结果时，改为在合并过程中逐步释放每个 bucket 的源状态，而不是一直保留到合并结束，从而降低峰值内存占用。[#102330](https://github.com/ClickHouse/ClickHouse/pull/102330)（[Yuri Fedoseev](https://github.com/yurifedoseev)）。
* 优化 `Enum` `DataType` 的内存表示。对于包含 `Enum` 类型的表，`Enum` 部分的内存占用最多可降低至原来的十分之一。按值（数字）取名称的耗时相当或更快；按名称搜索略慢，但这种访问方向较少使用。[#95668](https://github.com/ClickHouse/ClickHouse/pull/95668)（[Ilya Yatsishin](https://github.com/qoega)）。
* 新增标识符解析缓存，避免查询分析期间重复解析标识符。[#88043](https://github.com/ClickHouse/ClickHouse/pull/88043)（[Max Justus Spransy](https://github.com/maxjustus)）。
* 提升宽表查询的分析性能：不需要时避免计算列节点哈希（该哈希包含整个源表表达式）。分析约有 1200 列的表上的嵌套 `SELECT *` 子查询时，速度现在提高约 50 倍。[#106957](https://github.com/ClickHouse/ClickHouse/pull/106957)（[Dmitry Novik](https://github.com/novikd)）。
* 从函数解析缓存中移除冗余的查询树哈希，加快包含大量函数调用或深层嵌套函数调用的查询分析。[#107516](https://github.com/ClickHouse/ClickHouse/pull/107516)（[Dmitry Novik](https://github.com/novikd)）。
* 修复复制型访问存储在大量访问实体（行策略、角色、配额、设置配置文件）同时变更时，登录和查询启动长时间停顿的问题。各实体缓存现在每批通知只重新计算一次，而不是每个变更实体各计算一次，消除了可能持有访问锁数分钟的二次方级工作量。[#107672](https://github.com/ClickHouse/ClickHouse/pull/107672)（[Azat Khuzhin](https://github.com/azat)）。
* 在 probe 端将哈希连接的 `FixedHashMap` 共享为连接运行时过滤器。当 build 端哈希表本身是（或可转换为）`FixedHashMap` 时，会将其发布为运行时过滤器，替代 `BuildRuntimeFilterStep` 原本会安装的 `Set`/`BloomFilter`。由新设置 `join_runtime_filter_from_fixed_hash_table` 控制（默认 `true`）。[#105640](https://github.com/ClickHouse/ClickHouse/pull/105640)（[Xiaozhe Yu](https://github.com/wudidapaopao)）。
* 当 `JOIN` 后跟选择性较高的 `LIMIT`、`TopN` 或另一个 `JOIN` 时，延迟应用 selector 与 replication 索引。使用 `query_plan_min_columns_for_join_lazy_indexing` 设置控制启用延迟 selector 索引所需的 payload 列数（0 表示禁用优化）；使用 `query_plan_max_limit_for_join_lazy_indexing` 控制适用该优化的 `LIMIT` 上限。[#106566](https://github.com/ClickHouse/ClickHouse/pull/106566)（[Hechem Selmi](https://github.com/m-selmi)）。
* 并行副本现在允许使用 DP（动态规划）JOIN 重排。[#105889](https://github.com/ClickHouse/ClickHouse/pull/105889)（[Nikita Taranov](https://github.com/nickitat)）。
* 改进 JOIN 使用运行时过滤器时的查询计划（`enable_join_runtime_filters` 默认开启）：连接重排成本模型现在可以透过右子树上的 `WindowTransform`（以及其他保持行数的计划步骤），使用底层行数和逐列 NDV，而不是回退到无统计信息状态。[#107229](https://github.com/ClickHouse/ClickHouse/pull/107229)（[UnamedRus](https://github.com/UnamedRus)）。
* 通过批量输出，对 RIGHT 和 FULL JOIN 中未连接行的输出进行去虚拟化。[#105679](https://github.com/ClickHouse/ClickHouse/pull/105679)（[Hechem Selmi](https://github.com/m-selmi)）。
* `HashJoin` 支持打包的 `keys32` 和 `keys64` 方法。[#107202](https://github.com/ClickHouse/ClickHouse/pull/107202)（[Nikita Taranov](https://github.com/nickitat)）。
* `Set` 支持打包的 `keys32` 和 `keys64` 方法。[#107564](https://github.com/ClickHouse/ClickHouse/pull/107564)（[Nikita Taranov](https://github.com/nickitat)）。
* 更高效地处理聚合中的 Nullable 列。[#106015](https://github.com/ClickHouse/ClickHouse/pull/106015)（[Nikita Taranov](https://github.com/nickitat)）。
* 提升 `LIMIT BY` 查询性能。[#103349](https://github.com/ClickHouse/ClickHouse/pull/103349)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 当 `LIMIT BY` 的列是 `ORDER BY` 的前缀时，在 `Sort` 期间于每个并行排序流内部执行 `LIMIT BY`，从而加速 `ORDER BY ... LIMIT BY` 查询。这样可减少流经最终排序合并及后续管线步骤的行数。该优化由新设置 `query_plan_push_limit_by_into_sort` 控制（默认启用）。[#104000](https://github.com/ClickHouse/ClickHouse/pull/104000)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 当 `<cols>` 是表排序键的前缀，或经 `WHERE col = const` 固定前导列后成为前缀时，加速 `SELECT ... LIMIT N BY <cols>` 查询。启用后，`MergeTree` 按主键顺序读取数据，`LIMIT BY` 先以流式方式过滤，每个排序流仅使用 O(1) 内存并滤除大部分数据，最后再对缩减后的数据执行普通 `LIMIT BY` 得出最终结果。由新设置 `optimize_limit_by_in_order` 控制（默认启用）。[#105135](https://github.com/ClickHouse/ClickHouse/pull/105135)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 在分区 `MergeTree` 表上并行地于各分区流内部执行 `LIMIT BY`，不再先将全部流合并为一个再应用限制，从而加快 `LIMIT BY` 查询。当分区表达式是 `LIMIT BY` 列的确定性函数、不会有 `LIMIT BY` 分组跨越两个分区时适用。由新设置 `allow_limit_by_partitions_independently` 控制（默认启用）。[#105126](https://github.com/ClickHouse/ClickHouse/pull/105126)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 通过移除冗余键表达式来加速 `LIMIT BY`：若某个键是其他键的确定性函数，则将其删除（如 `LIMIT 5 BY x, f(x)` 变为 `LIMIT 5 BY x`）；若某个键的函数是单射，则以其参数替代该函数（如 `LIMIT 5 BY toString(x)` 变为 `LIMIT 5 BY x`）。这样每行需要求值的表达式更少、成本更低。由新设置 `optimize_limit_by_function_keys` 和 `optimize_injective_functions_in_limit_by` 控制，二者默认启用。[#106818](https://github.com/ClickHouse/ClickHouse/pull/106818)（[Nihal Z. Miaji](https://github.com/nihalzp)）。
* 以使用硬件 CRC32C 的内核替代逐 chunk 列哈希，从而加速分片聚合、`grace_hash` 连接分桶和并行窗口分区。[#106538](https://github.com/ClickHouse/ClickHouse/pull/106538)（[Harikrishnan Prabakaran](https://github.com/harikrishnan94)）。
* 通过 x86-64-v4/v3 多目标自动向量化，优化数组参数的 `L1Distance`、`L2Distance`、`L2SquaredDistance`、`LinfDistance` 和 `cosineDistance`。对于非常量数组参数，除使用运行时指数 `std::pow` 的 `LpDistance` 外，以上函数现均可使用编译器向量化内核。`L2Distance` 与 `cosineDistance` 现有的 AVX-512 和 Sapphire Rapids `BFloat16` 常量参数快速路径保持不变。[#101310](https://github.com/ClickHouse/ClickHouse/pull/101310)（[Peng](https://github.com/fastio)）。
* 提升 `{Norm}Distance` 与 `dotProduct` 函数的性能。[#106007](https://github.com/ClickHouse/ClickHouse/pull/106007)（[Nikita Taranov](https://github.com/nickitat)）。

* 使用 `default-engine-native-tls` feature 构建 `delta-kernel-rs`，使其 HTTP 客户端 `reqwest` 可以复用 ClickHouse 已链接的 OpenSSL。这只是部分启用 `native-tls`：`object_store` 仍强制使用 `reqwest/rustls-tls-native-roots`，因此 `reqwest` 最终同时包含 `native-tls` 和 `rustls` 后端。MSan 下目前仍禁用 `delta-kernel-rs`，因为 `ring` 仍会通过 `object_store` 编译进来，既包括经 `rustls` 的间接依赖，也包括 AWS 请求 HMAC 签名的直接依赖；其手写汇编不会生成 MSan 所需符号，上游跟踪见 [arrow-rs-object-store#585](https://github.com/apache/arrow-rs-object-store/pull/585)。[#96856](https://github.com/ClickHouse/ClickHouse/pull/96856)（[Austin Bonander](https://github.com/abonander)）。
