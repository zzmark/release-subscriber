实用小功能

所有表都有 _table 虚拟列

CREATE TABLE a (s String) ORDER BY (); CREATE TABLE b (s String) ORDER BY (); INSERT INTO a VALUES ('Hello'); INSERT INTO b VALUES ('World'); -- This already worked: SELECT *, _table FROM merge('^(a|b)$'); -- This is new in 25.8: SELECT *, _table FROM a UNION ALL SELECT *, _table FROM b; ┌─s─────┬─_table─┐ 1. │ Hello │ a │ 2. │ World │ b │ └───────┴────────┘

开发者：Xiaozhe Yu。

使用外部磁盘存储临时数据

包含大型 GROUP BY、ORDER BY 或 JOIN 操作的查询，
在内存无法容纳临时数据时，可使用磁盘空间。

25.8 之前，ClickHouse 只能使用本地类型的磁盘
存储临时数据。

从 25.8起，任意磁盘类型均可存储临时数据，包括 S3,
，这对临时、无磁盘的机器尤其有用。

额外好处：临时数据会自动压缩！

开发者：Azat Khuzhin。

集成 Arrow Flight 🧪

Arrow Flight — 是一种通过 GRPC 以 Apache Arrow 格式
交换数据的协议。

它保持数据的列式表示，因此适合列式数据库（类似 ClickHouse 原生协议）。

现在 ClickHouse 可以查询其他 Arrow Flight 数据源
，使用的是 arrowflight 表函数。

ClickHouse 本身也可以作为 Arrow Flight 服务器 运行。

开发者：zakr600、Vitaly Baranov。

集成 Arrow Flight 🧪

Arrow Flight 服务器 ，位于 ClickHouse 中。

$ cat config.d/flight.yaml arrowflight_port: 6379 arrowflight: enable_ssl: true ssl_cert_file: '/etc/clickhouse-server/cert.pem' ssl_key_file: '/etc/clickhouse-server/key.pem'

同时支持 put 和 get 命令。

开发者：zakr600、Vitaly Baranov。

集成 Arrow Flight 🧪

Arrow Flight 客户端 ，位于 ClickHouse 中。

SELECT * FROM arrowflight('localhost:6379', 'dataset');

CREATE TABLE table_name ENGINE = ArrowFlight('localhost:6379', 'dataset');

开发者：zakr600、Vitaly Baranov。

Hash 输出格式

想快速计算查询结果的校验和？

:) SELECT number FROM numbers(10) FORMAT Hash c1df5386c5a4dfee17eee0e351914c83

返回对顺序敏感的 128 位哈希值。

使用场景：检查查询是否返回相同结果。

开发者：Robert Schulze。

按 Hive 风格分区写入

允许按表示分区键值的目录拆分数据。

CREATE TABLE test (year UInt16, country String, counter UInt8) ENGINE = AzureBlobStorage(account_name = 'devstoreaccount1', ..., format = 'Parquet', partition_strategy = 'hive') PARTITION BY (year, country);

新增 partition_strategy 参数，可切换
'hive' 与原有的 'wildcard' 模式。

开发者：Arthur Passos。

按 Hive 风格分区写入

允许按表示分区键值的目录拆分数据。

:) INSERT INTO test VALUES (2020, 'Zimbabwe', 1), (2021, 'Brazil', 2); :) SELECT _path, * FROM test; ┌─_path───────────────────────────────────────────────────────┬─year─┬─country──┬─counter─┐ 1. │ data/year=2020/country=Zimbabwe/7351305360873664512.parquet │ 2020 │ Zimbabwe │ 1 │ 2. │ data/year=2021/country=Brazil/7351305360894636032.parquet │ 2021 │ Brazil │ 2 │ └─────────────────────────────────────────────────────────────┴──────┴──────────┴─────────┘

额外好处：
— 可以决定是否将分区列写入数据文件；
— hive 分区策略还使 SELECT 能访问分区列；

枯燥的安全功能

针对 S3 特定 URL 授权

25.6 及之前：

GRANT S3 ON *.* TO user

25.7：

GRANT READ, WRITE ON S3 TO user

25.8：

GRANT READ ON S3('s3://foo/.*') TO user

允许受限使用 S3 存储桶，防止数据外泄。

开发者：Artem Brustovetskii。

直到不久前，此功能还仅在 ClickHouse Cloud.
25.8 起，所有 ClickHouse 用户均可使用。

Azure 的推测性重试

问题： 偶尔出现延迟尖峰， 高达 5 秒、10 秒、15 秒……

原因：AWS S3 和 Azure 是复杂的分布式系统，各有自己的特殊行为。

几年前已通过以下方法解决 AWS 和 GCP 的这个问题：
— 建立多个连接，访问多个端点；
— 轮换端点，更均匀地分配负载；
— 一到软超时就发起第二个请求；
— 积极执行多次重试；

Azure 的推测性重试

问题： 偶尔出现延迟尖峰， 高达 5 秒、10 秒、15 秒……

问题已解决：

  1. 将 Azure SDK 的 HTTP 客户端替换为我们自己的实现。
  2. 复用与 AWS S3 相同的积极重试逻辑。

结果：

— 延迟尖峰消失了！

开发者：Alexander Sapin。

通过二级索引更快过滤

如何决定读取和应用索引的顺序？

25.8 起，按索引大小读取和应用，
也就是说， 先处理轻量索引.

大小按磁盘上的压缩数据计算，
对每个数据片段独立决策。

因此有机会以更低的成本过滤数据！
向表中添加重量级索引，
不会影响主要依赖另一轻量索引过滤的查询。

开发者：Maruth Goyal。

相关子查询进入 Beta 阶段

— 是依赖外部作用域列的子查询。

SELECT * FROM users AS u1 WHERE EXISTS ( SELECT * FROM users2 AS u2 WHERE u1.age = u2.age)

可以出现在多种上下文：EXISTS、IN、标量……

在 25.4 中，我们支持了位于 WHERE 子句中、使用 EXISTS 运算符的相关子查询。

在 25.5 中，我们支持 标量相关子查询 ，位于 WHERE 子句中，
以及相关子查询 出现在 SELECT 中！

现在无需修改查询，即可覆盖 TPC-H 测试套件。

开发者：Dmitry Novik。
