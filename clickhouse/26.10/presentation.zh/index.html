小巧实用的功能

函数组合运算符

在需要 lambda 的位置传入函数流水线：

SELECT arrayMap(lower | reverse, ['Hello', 'World']); -- ['olleh', 'dlrow'] SELECT arrayMap(plus(_, 1) | multiply(_, 2), [1, 2, 3]); -- [4, 6, 8] SELECT arrayMap(_1 * 2 + 1, [1, 2, 3]); -- [3, 5, 7] SELECT arrayMap(_1 + _2, [1, 2], [10, 20]); -- [11, 22]

— _, _1, _2 ……是参数占位符。
— 在查询分析期间解析为普通 lambda。

INSERT INTO events SELECT number FROM numbers(60000); -- Quota for user `ingest` for 60s has been exceeded: -- written_rows = 120000/100000. (QUOTA_EXCEEDED)

忽略顺序的查询规范化

即使列顺序发生变化，也可按查询形态归类工作负载：

SELECT normalizedQueryHash('SELECT a, b FROM t GROUP BY a, b') = normalizedQueryHash('SELECT b, a FROM t GROUP BY b, a'); -- 0 SELECT normalizedQueryHashUnordered('SELECT a, b FROM t WHERE x = 1 GROUP BY a, b') = normalizedQueryHashUnordered('SELECT b, a FROM t WHERE x = 42 GROUP BY b, a'); -- 1 SELECT normalizedQueryHashUnordered(query) AS shape, count(), sum(query_duration_ms) FROM system.query_log GROUP BY shape ORDER BY 3 DESC LIMIT 10;

— 对词元哈希值求和：与顺序无关。
— 有意采用有损方式：a - b 和 b - a 具有相同形态。

兼容 SQL 的整数除法

在 ClickHouse 中，7 / 2 一直等于 3.5。而在 PostgreSQL 中等于 3.

SELECT 7 / 2, -7 / 2, 7 / 2.0; -- 3.5 -3.5 3.5 SET sql_compatible_division_for_integers = 1; SELECT 7 / 2, -7 / 2, 7 / 2.0; -- 3 -3 3.5 (truncated toward zero) SELECT 1 / 0; -- Division by zero (ILLEGAL_DIVISION)

— 最高支持 Int256；溢出和除零会抛出异常。
— 默认关闭。已存储的定义保留其创建时
　采用的语义。

GROUP BY 的 Top-K 动态筛选

GROUP BY k ORDER BY k LIMIT n 和 GROUP BY k LIMIT n 维护一个 top-K 堆。现在会将其边界传递给表扫描：

递归查询中的物化 CTE

辅助 CTE 只计算一次，每个递归步骤都读取同一快照：

WITH RECURSIVE hubs AS MATERIALIZED ( SELECT src FROM edges GROUP BY src ORDER BY count() DESC LIMIT 100000), reach AS ( SELECT 1::UInt32 AS v, 0 AS depth UNION ALL SELECT e.dst, depth + 1 FROM reach JOIN edges AS e ON e.src = reach.v WHERE depth < 8 AND e.dst IN (SELECT src FROM hubs)) SELECT depth, count() FROM reach GROUP BY depth;

示例：未物化：1.49 秒。   MATERIALIZED: 0.80 秒。

— 不只是更快：非确定性的辅助查询（LIMIT 存在并列值时）
　在每个步骤中都使用同一集合。

开发者： Zach Naimon.

实验性功能

LATERAL JOIN 🧪

在 FROM 中引用其左侧表的子查询：

SET allow_experimental_lateral_join = 1; SELECT c.CounterID, t.SearchPhrase, t.c FROM (SELECT CounterID FROM hits GROUP BY CounterID ORDER BY count() DESC LIMIT 3) AS c JOIN LATERAL ( SELECT SearchPhrase, count() AS c FROM hits WHERE hits.CounterID = c.CounterID AND SearchPhrase != '' GROUP BY SearchPhrase ORDER BY c DESC LIMIT 2 ) AS t ON true;

— 标准的“每组前 N 项”模式（MS SQL Server 中称为 CROSS APPLY）。
— INNER 和 LEFT。去相关后：对所有外部行只执行一次，
  LIMIT 转为 LIMIT BY，再进行哈希连接。

FileLog 改进

CREATE TABLE app_logs (level String, msg String) ENGINE = FileLog('/var/lib/clickhouse/user_files/app/*.log', 'JSONEachRow'); -- reads app.log, skips app.log.1, app.log.2.gz; -- a file renamed by rotation is read to the end SYSTEM RESET FILELOG app_logs; -- all files again SYSTEM RESET FILELOG app_logs FILE 'app.log' OFFSET 27; SYSTEM RESET FILELOG app_logs FILE 'app.log' TO END; -- only new data
