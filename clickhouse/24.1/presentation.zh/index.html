合并的内存优化

降低了 横向 合并算法的内存消耗
（例如合并包含逐列 TTL 表达式的表）：

— 在一张含 30 列、100 个数据片段的表上，
  内存占用对比为 4.5 GiB 对比 9.1 GiB!

降低了 纵向 合并算法的内存消耗
（当存在大型值时减小数据块大小）：

— 在一张含 Array(String) 的表上，每个数组有 1000 个 50 字节的元素，
  内存占用对比为 90 MiB 对比 4.57 GiB!

开发者：Anton Popov。

FINAL 优化

FINAL — 在 SELECT 查询中即时应用合并逻辑。

适用于 Replacing-、Collapsing-、Aggregating-、Summing-，
以及其他 MergeTree 表。

可实现唯一主键的行为，以及 OLTP 数据库中的 UPSERT、REPLACE、INSERT IGNORE 行为。

可在查询中显式指定：
SELECT ... FROM table FINAL
或通过设置启用： SET final = 1

缺点：SELECT 会 变慢.

FINAL 优化

用于 ReplacingMergeTree 的纵向算法。

类似于后台合并使用的纵向算法，
— 具有更好的缓存局部性。

Ahrefs 生产查询的示例：

23.12: 8.7 秒
24.1: 3.2 秒.

开发者：Duc Canh Le。

Variant 数据类型

一种能够存储不同类型值的新数据类型。

示例： Variant(UInt64, String, Array(UInt64))

:) CREATE TABLE test (v Variant(UInt64, String, Array(UInt64))) ENGINE = Memory; :) INSERT INTO test VALUES (NULL), (42), ('Hello, World!'), ([1, 2, 3]); :) SELECT v FROM test; ┌─v─────────────┐ │ ᴺᵁᴸᴸ │ │ 42 │ │ Hello, World! │ │ [1,2,3] │ └───────────────┘

开发者：Pavel Kruglov。

允许创建包含不兼容类型的 Array、 Map，
