GROUPING SETS

GROUP BY 修饰符：

— WITH TOTALS;

— WITH ROLLUP;

— WITH CUBE;

— GROUPING SETS;

开发者：Dmitriy Novik、taylor12805、Maksim Sipliviy。

GROUPING SETS

GROUP BY 修饰符：

（演示）

GROUPING SETS

— WITH TOTALS:
  添加一行汇总值；

— WITH ROLLUP;
  按键的所有前缀聚合：
  对于 k1、k2，按 ()、(k1)、(k1, k2) 聚合；

— WITH CUBE;
  按键的所有子集聚合；
  对于 k1、k2，按 ()、(k1)、(k2)、(k1, k2) 聚合；

— 新增： GROUPING SETS;
  按任意键集合聚合；
  是以上所有方式的一般化形式；

GROUPING SETS

即将推出：

— GROUPING 函数，用于区分不同分组集。

— rollup_use_null 设置，用于兼容标准。

灵活的内存限制

此前版本：

— 固定的 max_memory_usage，默认设为 10 GB；
— max_memory_usage_for_user 可以设置；
— 超出内存限制时抛出异常；

从 22.5 起：

— max_memory_usage 默认不设置；
— 新增设置 memory_overcommit_ratio_denominator, memory_overcommit_ratio_denominator_for_user;

开发者：Dmitriy Novik。

灵活的内存限制

从 22.5 起：

— max_memory_usage 默认不设置；

— 新增设置 memory_overcommit_ratio_denominator,
  memory_overcommit_ratio_denominator_for_user;

— 内存不足时，
  将终止“超额使用”程度最高的查询；

— 其他查询的最长等待时间为
  memory_usage_overcommit_max_wait_microseconds;

— max_memory_usage 和 max_memory_usage_for_user
  可以充当硬性限制；

开发者：Dmitriy Novik。

灵活的内存限制

简而言之：

只要没有较小的查询需要内存，
大型查询就可以充分使用可用内存。

开发者：Dmitriy Novik。

性能优化

对排序比较器进行 JIT 编译。

适用于 ORDER BY、INSERT INTO MergeTree 和 Merge JOIN。

SELECT * FROM test ORDER BY value

— 0 rows in set. Elapsed: 5.299 sec. Processed 100.00 million rows, 1.70 GB (18.87 million rows/s., 320.81 MB/s.)

性能优化

SET compile_sort_description=1; SELECT * FROM test ORDER BY value

— 0 rows in set. Elapsed: 4.131 sec. Processed 100.00 million rows, 1.70 GB (24.21 million rows/s., 411.50 MB/s.)
— 性能提升 30%！

开发者：Maksim Kita。
