小巧而实用的功能

stem 函数

stem 函数现已脱离实验性阶段，
并可处理所有类字符串类型的整列数据：

SELECT stem('searching', 'en') -- 'search' SELECT stem(['running', 'jumps', 'flying'], 'en') -- ['run', 'jump', 'fli']

支持 String、FixedString、Array([Fixed]String)、
Nullable、LowCardinality 和 Const 参数。

适合在全文搜索前对词元进行规范化。

开发者：Jimmy Aguilar Mena。

更智能的 INSERT 块合并

兼容性设置 use_strict_insert_block_limits 下，
min/max_insert_block_size_rows/bytes 采用新行为：

— 将插入块合并为更接近 max_insert_block_size_* 的数据块；
— 减少频繁小批量插入产生的小数据部件；
— 降低写放大，减少后台合并。

为保证兼容性，默认仍保留旧行为。

开发者：Kirill Kopnev。

更美观的 EXPLAIN

EXPLAIN PLAN pretty=1 现在以更易读的形式输出表达式，
展示顶层输出列和每一步的输出列，
并为 JOIN 标注估算行数和执行位置。

EXPLAIN PLAN pretty=1 SELECT URL, count() FROM hits WHERE URL LIKE '%google%' GROUP BY URL ORDER BY count() DESC LIMIT 10;

— 输出更直观，便于理解查询计划。
— 对包含多个 JOIN 和聚合的计划尤其有用。

开发者：Kirill Kopnev。

不区分大小写的列名匹配

针对输入格式：

新增设置 input_format_column_name_matching_mode：

SET input_format_column_name_matching_mode = 'ignore_case'; INSERT INTO t (UserID, Country) FROM INFILE 'data.csv' FORMAT CSVWithNames; -- Matches userid, USERID, UserID, ... in the CSV header.

模式：match_case（默认）、ignore_case、auto。

从异构来源摄取 CSV、TSV 或 Parquet 文件时非常实用。

开发者：manerone。

arrayAutocorrelation

计算数值数组在各个滞后量下的归一化自相关：

SELECT arrayAutocorrelation([1, 2, 3, 4, 5, 4, 3, 2, 1]) -- [1, 0.625, 0.166..., -0.25, ...] SELECT arrayAutocorrelation(values, 10) FROM metrics

— 支持整数、浮点数和 Decimal 数组类型。
— 可选的 max_lag 参数用于控制结果长度。
— 适合时间序列分析和季节性检测。

开发者：Wenyu Chen。

arrayTranspose

转置二维数组（矩阵）：

SELECT arrayTranspose([[1, 2, 3], [4, 5, 6]]) -- [[1, 4], [2, 5], [3, 6]]

可方便地在行优先与列优先数组之间转换，
处理 groupArray 结果，以及为机器学习流水线准备数据。

开发者：Vitaly Baranov。

obfuscateQuery

新增 SQL 函数，返回查询的混淆形式 —
替换标识符和字面量，同时保留查询结构：

SELECT obfuscateQuery( 'SELECT name, count() FROM users WHERE age > 18 GROUP BY name')

— 与 clickhouse-format --obfuscate 工具采用相同逻辑，
 现在也能以函数形式调用。
— 便于公开分享查询，同时避免泄露 Schema 细节。
— 可与 normalizedQueryHash 配合进行查询分析。

开发者：Xuewei Wang。

highlight

用 HTML 标签包裹搜索词的匹配项：

SELECT highlight('ClickHouse is fast', ['fast', 'click']) -- <em>Click</em>House is <em>fast</em> SELECT highlight(text, ['error', 'warn'], '<mark>', '</mark>')

— ASCII 不区分大小写匹配。
— 自动合并重叠的匹配项。
— 支持自定义开始/结束标签。

可与文本索引良好配合，用于构建搜索界面。

开发者：Peng。

按规范化查询哈希实施配额

防止失控的查询模式冲击公共端点：

CREATE QUOTA q1 KEYED BY normalized_query_hash FOR INTERVAL 1 minute MAX queries = 100, read_bytes = '100G'; CREATE QUOTA q2 FOR INTERVAL 1 minute MAX queries_per_normalized_hash = 100;

— NORMALIZED_QUERY_HASH：为每种独特查询形态设置独立配额。
— QUERIES_PER_NORMALIZED_HASH：限制任一查询模式
 在一个时间区间内的执行次数。

开发者：Alexey Milovidov。

hasPhrase / matchPhrase

短语搜索 — 匹配连续的词元序列：

SELECT * FROM logs WHERE hasPhrase(message, 'connection refused')

— 词元必须按顺序连续出现。
— 默认使用暴力匹配。
— 列上的文本索引可加速短语搜索：

CREATE TABLE logs (..., message String, INDEX msg_idx message TYPE text(tokenizer = 'ngrams') GRANULARITY 1)

开发者：Elmi Ahmadov。

Web UI 改进

内置的 play.html 在 26.4 中获得了多项改进：

— 参数化查询：为 {name:Type} 占位符显示输入框。
— 多查询模式：一次并行运行多条查询。
— TOTALS 行：渲染为表格页脚。
— 表格侧边栏按引擎显示不同的图标。
— 限制单元格高度，点击后可在查看器中浏览完整内容。

开发者：Alexey Milovidov。

SQL 兼容性

NATURAL JOIN

按所有同名列执行连接，并在结果中对这些列去重：

SELECT * FROM customers NATURAL JOIN orders -- joins on every column with the same name in both tables

— 自动按名称匹配列。
— 共享列在输出中只出现一次。
— ClickHouse 现已支持这一标准 SQL 语法。

开发者：Peter Nguyen。

OVERLAY 语法

使用 PLACING / FROM / FOR 关键字的 SQL 标准 OVERLAY 语法：

SELECT OVERLAY('Hello world' PLACING 'SQL' FROM 7 FOR 5) -- 'Hello SQL'

— overlay 函数此前已经存在。
— 本次加入 SQL:2003 中基于关键字的语法糖。
— 可直接兼容 PostgreSQL 等其他引擎。

开发者：Desel72。

SET TIME ZONE

SET session_timezone 的 SQL 标准别名：

SET TIME ZONE 'Europe/Amsterdam'; SELECT now(); -- now reported in Amsterdam time

可直接兼容 PostgreSQL 的会话设置。

开发者：phulv94。

将 VALUES 用作表表达式

26.3:

SELECT * FROM VALUES((1, 'a'), (2, 'b'), (3, 'c'))

26.4：兼容 PostgreSQL 的“标准”语法：

SELECT * FROM (VALUES (1, 'a'), (2, 'b'), (3, 'c'))

— 无需 CSV 或外部数据源即可方便地使用临时数据。
— 可作为普通子查询使用，并支持 JOIN、过滤等操作。

开发者：Desel72。

EXTRACT — PostgreSQL 时间单位

EXTRACT 运算符现在支持 PostgreSQL 风格的时间单位：

EPOCH, DOW, DOY, ISODOW, ISOYEAR, WEEK, CENTURY, DECADE, MILLENNIUM

SELECT EXTRACT(EPOCH FROM now()) AS epoch, EXTRACT(DOW FROM today()) AS day_of_week, EXTRACT(WEEK FROM today()) AS iso_week, EXTRACT(CENTURY FROM today()) AS century;

另外，EXTRACT(WEEK FROM date) 不再抛出异常 —
现在会按预期返回 ISO 周数。

开发者：Alexey Milovidov。

复合 INTERVAL 字面量

使用 TO 范围限定符的 SQL 标准时间间隔：

SELECT now() + INTERVAL '1:30' HOUR TO MINUTE; SELECT now() + INTERVAL '5 12:30:00' DAY TO SECOND; SELECT INTERVAL '2-6' YEAR TO MONTH;

— 内部会拆解为多个单一单位时间间隔之和。
— PostgreSQL、Oracle 和 DB2 用户对此语法会很熟悉。

开发者：Desel72。

性能改进

JSON 列上的索引

MergeTree 跳数索引现在可通过 JSONAllPaths
作用于一组 JSON 路径：

ALTER TABLE events ADD INDEX paths_idx JSONAllPaths(data) TYPE bloom_filter GRANULARITY 1;

— 支持的类型：bloom_filter、tokenbf_v1、ngrambf_v1 和 text（倒排索引）。
— 若数据粒度中不存在查询所过滤的 JSON 路径，即可跳过该粒度。

开发者：Pavel Kruglov。

JSONAllValues + 文本索引

新增函数 JSONAllValues，以 Array(String)
形式返回 JSON 列中的每一个叶子值：

SELECT JSONAllValues(data) FROM events -- ['42', 'click', '2026-04-30', ...]

在其上建立文本索引后，针对 JSON 子列的过滤条件
会自动使用该索引：

ALTER TABLE events ADD INDEX vals JSONAllValues(data) TYPE text(tokenizer='ngrams') GRANULARITY 1; SELECT * FROM events WHERE data.event_type = 'click'; -- The text index is used to skip granules.

开发者：Anton Popov。

默认启用统计信息

从 26.4 开始，新表会默认启用基础统计信息：

auto_statistics_types = 'minmax, uniq' materialize_statistics_on_insert = false

— 为每个适用的列创建 minmax 和 uniq 统计信息。
— 在后台合并期间构建，不会增加插入开销。
— 优化器可将其用于谓词选择率估算、JOIN 重排序，
 以及新的基于 min/max 的数据部件裁剪优化。

开发者：Han Fei。

LIKE 可使用文本索引

LIKE 查询现在可由文本索引加速：

ALTER TABLE logs ADD INDEX msg_idx message TYPE text(tokenizer='ngrams') GRANULARITY 1; SELECT * FROM logs WHERE message LIKE '%timeout%error%'; -- Granules without both terms are skipped.

— 适用于能够从 LIKE 表达式中提取的子字符串模式。
— 此外，文本索引现已正式可用（GA），不再需要兼容性标志。

开发者：Elmi Ahmadov。

分布式索引分析

对于包含大量分片的超大集群，发起节点可在读取数据前
跨整个集群执行主索引分析。

26.4 带来两项改进：

— 在分区裁剪之后执行索引分析，
 使具有大量分区的重型集群能更快跳过无关分片。
— 修复谓词包含 IN 子查询时的二次方级膨胀。

效果：在超大规模部署中降低高选择性查询的延迟。

开发者：Azat Khuzhin、Anton Popov。

含分支的正则表达式可使用索引

主键裁剪现在能够识别
具有共同字面前缀的正则表达式分支：

SELECT * FROM events WHERE match(id, '^(abc-1|abc-2|abc-3)'); -- The common prefix 'abc-' is used for primary key pruning.

— 检测 (...|...|...) 中共享的字面前缀。
— 不存在共享前缀时回退为不执行裁剪。

开发者：Yash。

更快的 Float ↔ String 转换

26.4 重写了 Float 到 String 转换的热点路径：

— 以 zmij 取代 dragonbox，Float → String 提速 1.5–3 倍。
— 扩展 itoa 快速路径，对较大的整数值浮点数
 采用与 dragonbox 兼容的舍入方式。
— Int128/UInt128 → String：以展开内层循环的 Barrett 约减
 取代软件除法。

大型聚合以及导出为文本格式时，性能提升尤为明显。

开发者：Raúl Marín。

更快的 COUNT DISTINCT

重写了 uniqExact（由 COUNT(DISTINCT) 使用）
的并行合并：

— 使用批量并行合并，取代各线程的顺序合并。
— 避免为较小的中间状态创建多余线程。
— 在多核机器上显著加速高基数的 COUNT(DISTINCT)。

开发者：Jiebin Sun。

一些
有趣的功能

JOIN 溢写到磁盘 🧪

哈希连接和并行哈希连接在达到内存限制时，
现在会自动溢写到磁盘：

SET max_bytes_before_external_join = '4G'; SELECT * FROM orders LEFT JOIN customers USING (customer_id) -- Once the hash side exceeds 4 GB, join converts to grace hash join.

— 透明回退，查询和结果均保持不变。
— 运行时转换为 grace hash join。
— 大型 JOIN 不再因超出内存限制而失败。

开发者：János Benjamin Antal。

Arrow Flight SQL

ClickHouse 现在可通过 Arrow Flight SQL 提供查询服务，
它是 Apache Arrow 的高吞吐列式 gRPC 协议。

将其配置为独立监听器：

$ cat config.d/arrow.yaml arrowflight_port: 9005

import pyarrow.flight as flight client = flight.FlightClient("grpc://localhost:9005") ticket = flight.Ticket(b"SELECT * FROM system.numbers LIMIT 10") reader = client.do_get(ticket) print(reader.read_all())

开发者：Yakov Olkhovskiy。

AI 函数 🧪

直接从 SQL 调用 LLM 端点（OpenAI、Anthropic）：

SELECT aiGenerate('Summarize this in one line: ' || review) FROM product_reviews LIMIT 10;

在此基础上构建的高阶辅助函数：

SELECT aiClassify(text, ['bug', 'feature', 'question']) FROM tickets; SELECT aiExtract(article, 'people, organizations, dates') FROM news; SELECT aiTranslate(message, 'English') FROM logs;

— 提供商在服务端配置，密钥绝不会泄露到客户端。

开发者：George Larionov。

数据湖

Iceberg：移除孤立文件 🧪

删除未被任何有效快照引用的文件，从而回收空间：

ALTER TABLE my_iceberg EXECUTE remove_orphan_files;

— 遍历快照图，确定仍在使用的数据文件集合。
— 从对象存储中移除其余文件。
— 与此前发布的 EXECUTE expire_snapshots(...) 配套使用。

二者结合后，ClickHouse 能够原地完整维护 Iceberg 表。

开发者：murphy-4o。

Delta Lake 虚拟列裁剪

Delta Lake 现在可使用虚拟列上的谓词裁剪数据文件：

SELECT * FROM my_delta WHERE _partition = 'country=DE/year=2026'; -- Only files in matching partitions are scanned.

— 减少打开的文件数量和对象存储请求次数。
— 原理与分区裁剪相同，但通过虚拟列应用。

开发者：Konstantin Vedernikov。

Iceberg：Unity Catalog 与路径改进

针对 Iceberg 写入的一系列修复和改进：

— 更好地支持写入 Unity Catalog。
— 更清晰地区分存储路径与元数据路径的抽象。
— 表现在会将位置记录为 URL 或绝对路径。
— 以兼容 Spark 的方式处理 version-hint.txt。
— 位置删除不再依赖路径推断启发式规则。
— 加入 Azure 与 Local Catalog 的跨引擎互操作测试。

此外重新设计 Catalog 插入接口，使设置更加清晰，
旧的 storage_* 选项现已弃用。

开发者：Daniil Ivanik、Konstantin Vedernikov。
