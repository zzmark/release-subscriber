小而实用的功能

system.codecs

ClickHouse 使用 编解码器 压缩和加密数据。

ClickHouse 编解码器可在列级或表级应用，
也可根据数据大小或 TTL 应用。

新系统表 codecs 提供其内部信息及内嵌文档。

演示。

开发者：Jimmy Aguilar Mena。

比特币地址函数

Bech32 — 一种基于 Base32 的比特币地址编码。

示例： bc1qc7slrfxkknqcq2jevvvkdgvrt8080852dfjewde450xdlk4ugp7szw5tk9

两个新函数：
— bech32Encode(hrp, payload) — 返回编码后的地址；
— bech32Decode(address) — 返回由人类可读部分和载荷组成的元组；

开发者：George Larionov。

Well-Known Binary 函数

WKT （Well-Known Text）和 WKB （Well-Known Binary）
— 是表示几何数据的标准格式。

20.5：几何数据类型：Point、Ring、Polygon、MultiPolygon……

21.4：用于 WKT的函数：wkt、readWKTPoint、readWKTPolygon……

25.5：从 Parquet 读取 WKB 数据

25.6：用于以下格式的函数： WKB

演示。

开发者：Konstantin Vedernikov。

SELECT 的单一快照

ClickHouse 为查询提供一定的事务（ACID）保证。

SELECT 从表中读取时，会在查询分析时获取该表的 快照 。该快照不受并发执行的 INSERT/ALTER/DELETE/DROP 查询影响。

25.5：为查询中的不同子查询
和表引用分别获取快照。

25.6：当启用
设置 enable_shared_storage_snapshot_in_query 时，所有对该表的引用共享单一快照。

演示。

开发者：Amos Bird。

Parquet 中的 JSON

SELECT '{"database": "ClickHouse", "is_it_good": true}'::JSON AS data INTO OUTFILE 'test.parquet'

ClickHouse 以列式存储提供完善的 JSON 支持。

Parquet 没有完整的 JSON 支持，
它将 JSON 存为带注解的字符串。

25.5：Parquet 中带 JSON 注解的字符串读取为 String。

25.6：Parquet 中带 JSON 注解的字符串读取为 JSON，
ClickHouse 中的 JSON 写入 Parquet 时也带有正确的注解。

开发者：Nihal Z. Miaji。

新的分词器

函数 tokens 将字符串拆分为多个部分。

它支持不同的分词算法：

SELECT tokens('Hello, world!'); SELECT tokens('Hello, world!', 'default'); SELECT tokens('Hello, world!', 'split');

版本 25.6 引入了新算法 split，适合处理日志。

演示

开发者：Elmi Ahmadov、Robert Schulze。

PromQL 函数

ClickHouse 目前尚不支持 PromQL。

相关实现正在开发中，我们需要函数来支持
它的全部能力。

在 25.6中新增的聚合函数：
timeSeriesInstantDeltaToGrid, timeSeriesInstantRateToGrid, timeSeriesRateToGrid, timeSeriesResampleToGridWithStaleness, timeSeriesDeltaToGrid, timeSeriesLastTwoSamples

SELECT timeSeriesDeltaToGrid( start_ts, end_ts, step_seconds, window_seconds)(timestamp, value)

开发者：Alexander Gololobov。

数据库的自定义磁盘

磁盘 — 是 ClickHouse 中的文件系统抽象，
允许将表数据存储在远程对象存储中
（S3、GCS、Azure、HDFS、静态 Web 服务器等）。

ClickHouse 25.6 不仅允许将表数据，
还允许将 数据库元数据 存储在自定义磁盘上！

这是在无状态服务器上管理数据库所需的能力。

注意：这些数据库不能在多台服务器之间共享。

开发者：Tuan Pham Anh。

性能改进

加快分布式查询

通过并行处理网络传输数据块
的序列化和压缩工作来实现。

示例： SELECT SearchPhrase, count() AS c FROM hits WHERE SearchPhrase != '' GROUP BY SearchPhrase ORDER BY c DESC LIMIT 10

25.5：0.601 秒。
25.6：0.322 秒。

开发者：Nikita Taranov。

并发查询的工作负载调度器

工作负载调度器已经支持多种资源类型：
CPU 使用量、磁盘读取和写入。

新的 QUERY 资源类型允许按并发运行的查询数量进行调度：

CREATE RESOURCE query (QUERY); CREATE WORKLOAD all; CREATE WORKLOAD production IN all SETTINGS max_concurrent_threads = 100, max_queries_per_second = 10, max_burst_queries = 20; CREATE WORKLOAD analytics IN production SETTINGS max_concurrent_threads = 60, weight = 9; CREATE WORKLOAD ingestion IN production; SET workload = 'analytics';

开发者：Sergei Trifonov。
