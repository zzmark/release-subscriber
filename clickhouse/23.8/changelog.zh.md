<h4 id="backward-incompatible-change-4">
  向后不兼容变更
</h4>

* 如果动态磁盘包含名称，应在磁盘函数参数中使用 `disk = disk(name = 'disk_name'`, ...) 指定。此前版本的 `disk = disk_<disk_name>(...)` 写法不再受支持。 [#52820](https://github.com/ClickHouse/ClickHouse/pull/52820) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 以大于 1 的 `--concurrency` 调用 `clickhouse-benchmark` 时，现在并行建立连接。此前从欧洲向美国建立 1000 个并发连接时几乎无法使用。修正高延迟连接的 QPS 计算。向后不兼容变更：移除 `clickhouse-benchmark` 的 JSON 输出选项。此前使用该选项的用户，可改为从 `system.query_log` 提取 JSON 格式数据。 [#53293](https://github.com/ClickHouse/ClickHouse/pull/53293) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 移除 `system.text_log` 的 `microseconds` 列和 `system.metric_log` 的 `milliseconds` 列，因为已有 `event_time_microseconds` 列，这些列属于冗余。 [#53601](https://github.com/ClickHouse/ClickHouse/pull/53601) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 弃用元数据缓存功能。它是实验性功能，我们从未使用过，而且存在危险：[#51182](https://github.com/ClickHouse/ClickHouse/issues/51182)。移除系统表 `system.merge_tree_metadata_cache`。本版本仍可使用元数据缓存，但它将很快被移除。关闭 [#39197](https://github.com/ClickHouse/ClickHouse/issues/39197)。 [#51303](https://github.com/ClickHouse/ClickHouse/pull/51303) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 禁用 TLS 连接中的 3DES 支持。 [#52893](https://github.com/ClickHouse/ClickHouse/pull/52893) ([Kenji Noguchi](https://github.com/knoguchi)).

<h4 id="performance-improvement-4">
  性能改进
</h4>

* 支持 Parquet 过滤器下推。读取 Parquet 文件时，根据 WHERE 条件及各列的最小/最大值跳过行组（文件中的数据块）。特别是文件大致按某列排序时，对该列小范围过滤的查询会快得多。 [#52951](https://github.com/ClickHouse/ClickHouse/pull/52951) ([Michael Kolupaev](https://github.com/al13n321)).
* 在 Parquet 中通过批量合并小行组优化读取。关闭 [#53069](https://github.com/ClickHouse/ClickHouse/issues/53069)。 [#53281](https://github.com/ClickHouse/ClickHouse/pull/53281) ([Kruglov Pavel](https://github.com/Avogar)).
* 优化多数输入格式中对文件进行计数的性能。关闭 [#44334](https://github.com/ClickHouse/ClickHouse/issues/44334)。 [#53637](https://github.com/ClickHouse/ClickHouse/pull/53637) ([Kruglov Pavel](https://github.com/Avogar)).
* 在 `url`/`file`/`hdfs` 表函数读取前，按文件名/路径过滤。 [#53529](https://github.com/ClickHouse/ClickHouse/pull/53529) ([Kruglov Pavel](https://github.com/Avogar)).
* 为 AArch64、PowerPC、SystemZ、RISC-V 启用 JIT 编译。 [#38217](https://github.com/ClickHouse/ClickHouse/pull/38217) ([Maksim Kita](https://github.com/kitaisreal)).
* 新增 `rewrite_count_distinct_if_with_count_distinct_implementation` 设置，使用 `count_distinct_implementation` 重写 `countDistinctIf`。关闭 [#30642](https://github.com/ClickHouse/ClickHouse/issues/30642)。 [#46051](https://github.com/ClickHouse/ClickHouse/pull/46051) ([flynn](https://github.com/ucasfl)).
* 通过并行执行合并前的转换，加快 `uniq` 和 `uniqExact` 聚合函数状态的合并。 [#50748](https://github.com/ClickHouse/ClickHouse/pull/50748) ([Jiebin Sun](https://github.com/jiebinn)).
* 使用大量变长键时，优化可空字符串键的聚合性能。 [#51399](https://github.com/ClickHouse/ClickHouse/pull/51399) ([LiuNeng](https://github.com/liuneng1994)).
* 为分析器新增利用原像优化时间过滤的处理阶段。在 ICX 设备（Intel Xeon Platinum 8380 CPU，80 核、160 线程）上的 SSB 性能实验表明，启用实验性分析器时，这可使 QPS 几何平均值提升 8.5%。 [#52091](https://github.com/ClickHouse/ClickHouse/pull/52091) ([Zhiguo Zhou](https://github.com/ZhiguoZh)).
* 在 `uniqExact`（COUNT DISTINCT）函数中，如果所有哈希集合均为单层，则优化其合并。 [#52973](https://github.com/ClickHouse/ClickHouse/pull/52973) ([Jiebin Sun](https://github.com/jiebinn)).
* `Join` 表引擎不再克隆包含所有列的哈希连接数据结构。 [#53046](https://github.com/ClickHouse/ClickHouse/pull/53046) ([Duc Canh Le](https://github.com/canhld94)).
* 实现不依赖 Apache Arrow 库的原生 `ORC` 输入格式，以提升性能。 [#53324](https://github.com/ClickHouse/ClickHouse/pull/53324) ([李扬](https://github.com/taiyang-li)).
* 仪表盘会通知服务器压缩数据，这有利于通过较慢网络连接展示较大时间范围。例如，包含 86400 个点的图表未压缩时可能为 1.5 MB，使用 `br` 压缩后仅 60 KB。 [#53569](https://github.com/ClickHouse/ClickHouse/pull/53569) ([Alexey Milovidov](https://github.com/alexey-milovidov)).
* 提高 BACKUP 和 RESTORE 的线程池利用率。 [#53649](https://github.com/ClickHouse/ClickHouse/pull/53649) ([Nikita Mikhaylov](https://github.com/nikitamikhaylov)).
* 启动时并行加载文件系统缓存元数据，由缓存设置 `load_metadata_threads` 控制，默认为 1。与 [#52037](https://github.com/ClickHouse/ClickHouse/issues/52037) 相关。 [#52943](https://github.com/ClickHouse/ClickHouse/pull/52943) ([Kseniia Sumarokova](https://github.com/kssenii)).
* 改进 `move_primary_key_columns_to_end_of_prewhere`。 [#53337](https://github.com/ClickHouse/ClickHouse/pull/53337) ([Han Fei](https://github.com/hanfei1991)).
* 优化与 ClickHouse Keeper 的交互。此前调用方可以多次注册同一监听回调，每个条目都会占用内存，且同一回调会被调用多次，没有太大意义。调用方原本需要自行避免重复添加监听；现在通过 shared\_ptr 传入监听回调时，会在内部完成去重。 [#53452](https://github.com/ClickHouse/ClickHouse/pull/53452) ([Alexander Gololobov](https://github.com/davenger)).
* 为 file/s3/url/hdfs/azure 函数缓存文件行数，用于计数。由 `use_cache_for_count_from_files` 设置启用或禁用，默认启用。延续 [https://github.com/ClickHouse/ClickHouse/pull/53637](https://github.com/ClickHouse/ClickHouse/pull/53637) 的工作。 [#53692](https://github.com/ClickHouse/ClickHouse/pull/53692) ([Kruglov Pavel](https://github.com/Avogar)).
* 更细致的线程管理使 S3 表函数处理大量文件的速度提升超过约 \~25%。 [#53668](https://github.com/ClickHouse/ClickHouse/pull/53668) ([pufit](https://github.com/pufit)).
