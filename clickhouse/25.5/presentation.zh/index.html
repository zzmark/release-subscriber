几个小功能

字符串熵

两个新函数：
— stringBytesUniq — 字符串中不同字节的数量；
— stringBytesEntropy — 字节分布的香农熵；

判断字符串的随机程度。

SELECT round(stringBytesEntropy(randomString(10000)), 2) AS res ┌──res─┐ 1. │ 7.98 │ -- close to 8 bit per character └──────┘

演示。

开发者：Sachin Kumar Singh。

SparseGrams

对 ngrams 的扩展：以确定的方式，将少量更长的 低频子串 添加到 n-gram 集合中。

新函数： sparseGrams, sparseGramsUTF8,
sparseGramsHashes, sparseGramsHashesUTF8.

演示。

这是一种加速文本和代码搜索的优雅算法。

开发者：Konstantin Vedernikov。

Parquet 中的地理类型

Parquet 文件可以包含以 WKB 编码的几何数据。

此前的 ClickHouse 版本将这些数据识别为二进制字符串。

从 25.5 版本开始，它们会被推断为 ClickHouse 中的 Point, LineString, MultiLineString, Polygon 或 MultiPolygon 类型。

演示。

开发者：Konstantin Vedernikov。

clickhouse-local 中的隐式表

处理来自标准输入的文件时，可以省略 FROM 子句：

ch -q "name, price + tax ORDER BY 2 DESC" < data.csv ch -q "arrayJoin(members.login), org_name" < data.json ch -q "arrayJoin(json.members.login), json.org_name " --input-format JSONAsObject < data.json

SELECT 也可以省略。

这使 clickhouse-local 可以作为 jq的替代工具（更快、功能更丰富）。

演示。

开发者：Alexey Milovidov。

TRUNCATE ALL TABLES LIKE

可以进一步限定： TRUNCATE ALL TABLES FROM db LIKE '%pattern%'

开发者：Yarik Briukhovetskyi。

数据湖改进

支持分桶分区

用于 Iceberg 表的分区裁剪。

示例：AWS Athena 中的一张 Iceberg 表：

CREATE TABLE iceberg_benchmark.bucket_partitioned ( watchid bigint, javaenable int, title string, ... ) PARTITIONED BY (bucket(50, watchid)) TBLPROPERTIES ('table_type'='iceberg');

根据 50 个分桶进行划分，分桶依据是 watchid的哈希。

开发者：Dan Ivanik。

支持分桶分区

SELECT watchid FROM "iceberg_benchmark.bucket_partitioned" WHERE watchid = 8005433341155183383 LIMIT 10

ClickHouse 25.4: 51.2 秒.

ClickHouse 25.5: 1.3 秒.

还新增两个函数， icebergHash 和 icebergBucketTransform.

开发者：Dan Ivanik。

支持“版本提示”

Iceberg 表可能包含一个 version-hint.text 文件，指向实际快照。因此可利用它，无需查找最新元数据文件。

新增表级设置 iceberg_use_version_hint ，补充已有的 iceberg_metadata_file_path, iceberg_metadata_table_uuid, iceberg_recent_metadata_file_by_last_updated_ms_field。

有助于在不使用数据目录的情况下，使用存在并发更新的表*

* 是的，Iceberg 生态系统中的一切都复杂又脆弱。对此深感抱歉。

开发者：Arnaud Briche。

性能改进

FINAL 中的二级索引

ClickHouse 允许表在后台合并期间转换数据。

例如， ReplacingMergeTree 进行去重，
AggregatingMergeTree 进行聚合。

如果 SELECT 查询在表名后带有 FINAL 修饰符，
则会 在 SELECT 期间执行合并.

问题在于：二级索引无法在 SELECT 期间跳过数据范围，
因为这些数据会通过合并影响查询结果。

FINAL 中的二级索引

问题在于：二级索引无法在 SELECT 期间跳过数据范围，
因为这些数据会通过合并影响查询结果。

可以通过以下设置启用二级索引筛选：
use_skip_indexes_if_final，它允许筛选数据，
但也可能 跳过部分更新.

ClickHouse 25.5 中的新选项 use_skip_indexes_if_final_exact_mode
— 会在筛选后读取额外范围，以兼顾所有更新。

演示。

开发者：Shankar Iyer。

一些有趣的功能

相关子查询：支持更多类型

— 是依赖外层作用域中列的子查询。

SELECT * FROM users AS u1 WHERE EXISTS ( SELECT * FROM users2 AS u2 WHERE u1.age = u2.age)

它们可出现在多种语境中：EXISTS、IN、标量……

在 25.4 中，我们支持了 WHERE 子句中使用 EXISTS 运算符的相关子查询。

在 25.5 中，我们支持 标量相关子查询 出现在 WHERE 子句中
，还支持相关子查询 出现在 SELECT 中!

现在足以在不修改查询的情况下覆盖 TPC-H 测试套件。

开发者：Dmitry Novik。
