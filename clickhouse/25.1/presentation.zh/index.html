小功能 🎁

在表的键中使用子列

24.12:

CREATE TABLE test ( t Tuple(a UInt8, s String) ) ORDER BY tupleElement(t, 'a')

25.1:

CREATE TABLE test ( t Tuple(a UInt8, s String) ) ORDER BY t.a -- much better!

开发者：Pavel Kruglov。

在表的键中使用子列

配合新的 JSON 数据类型尤其有用！

24.12:

CREATE TABLE test ( data JSON ) ORDER BY getSubcolumn(data, 'headers.referer')

25.1:

CREATE TABLE test ( data JSON ) ORDER BY data.headers.referer -- much better!

支持主键和二级索引。

记录行号和查询编号

clickhouse-client --query " -- First query: SELECT 1; -- Second query: SELECT 2; "

运行脚本时，每条查询的编号及其起始行号都会记录到查询日志和文本日志中。

开发者：Alexey Milovidov。

并行 DDL 查询

CREATE TABLE t1 (...) PARALLEL WITH CREATE TABLE t2 (...) ...

适用于不返回任何输出的查询
（CREATE、DROP、RENAME、ALTER、OPTIMIZE 等）。

此功能旨在加快 RESTORE 命令的执行。

也可加快复杂数据库结构的创建。

开发者：Vitaly Baranov。

在表级别启用 MinMax 索引

24.12:

CREATE TABLE t ( a UInt64, b UInt64, c UInt64, INDEX idx_a(a) TYPE minmax, INDEX idx_b(b) TYPE minmax, INDEX idx_c(c) TYPE minmax ) ORDER BY ();

25.1:

CREATE TABLE t ( a UInt64, b UInt64, c UInt64 ) ORDER BY () SETTINGS add_minmax_index_for_numeric_columns = 1;

开发者：Smita Kulkarni。

性能改进

更快的并行哈希连接

从 24.12 起，并行哈希连接成为默认算法。

现在更快了。演示。

开发者：Nikita Taranov。

更快的向量索引

使用新的二级索引缓存，由服务器设置
skipping_index_cache_size 和 skipping_index_cache_max_entries 控制。

示例：表中有 33,114,778 个 768 维嵌入向量：

全表扫描：216 秒.
索引搜索（不使用缓存）：33 秒.
索引搜索（使用缓存）：0.064 秒 🚀

开发者：Robert Schulze、Michael Kolupaev。

更快的并行副本

ClickHouse 25.1 在 ClickBench 上的性能提升了 — 40%！

并行副本（通过 enable_parallel_replicas 设置启用）允许单个查询使用所有副本的资源，以加快繁重查询，尤其适用于共享存储场景。

开发者：Igor Nikonov、Nikita Taranov。

trace_log 记录符号信息

system.trace_log 表包含 ClickHouse 内置采样性能分析器的调用栈。

采样性能分析器收集查询耗时位置及内存分配位置的信息，并支持生成火焰图，分析范围既可细化到单条查询，也可按时间跨集群聚合。

在 ClickHouse 24.12 中，其中记录的是机器码中的地址，可以使用 addressToLine 和 addressToSymbol 函数即时转换为代码位置。这些信息在每次版本发布后都会失效。

在 ClickHouse 25.1 中，新增持久化的 symbols 和 lines 列，因此可以跨不同构建版本进行分析。

开发者：Alexey Milovidov。

一些有趣的功能

轻量级更新

也称为“即时变更操作”。

SET apply_mutations_on_fly = 1;

现在，所有 ALTER UPDATE/DELETE 都会在 SELECT 查询时即时应用，即使相应操作尚未完全物化。

开发者：Anton Popov。

此功能已为 ClickHouse Cloud 客户启用一年多，现在也已在常规 MergeTree 和 ReplicatedMergeTree 引擎中实现。

自增

CREATE TABLE test ( id UInt64 DEFAULT generateSerialID('test'), data String ) ORDER BY id; INSERT INTO test (data) VALUES VALUES ('Hello'), ('World');

新的 generateSerialID 函数实现了命名分布式计数器
（存储于 Keeper），可用于表中的自增值。

借助批处理，它速度很快，并能安全地用于并行和分布式操作。

开发者：Alexey Milovidov。

更完善的 Merge 表

通过 Merge 表引擎，可以将多个表统一为一个表。
也可使用 merge 表函数。

CREATE TABLE t1 (a UInt8, b String) ENGINE = Memory; CREATE TABLE t2 (a Int32, c Array(String)) ENGINE = Memory; CREATE TABLE merge_table ENGINE = Merge(currentDatabase(), '^t(1|2)$'); SELECT * FROM merge_table; SELECT * FROM merge('^t(1|2)$');

在 24.12 版本中，Merge 表采用第一个表
的结构（除非显式指定结构）。

在 25.1 版本中，Merge 表采用所有表的列的并集。
甚至会将数据类型统一为公共类型或 Variant 数据类型。

开发者：Alexey Milovidov。

通过 HTTP 流式传输事件

格式 JSONEachRowWithProgress, JSONStringsEachRowWithProgress
以流的形式传输换行分隔的 JSON 事件，每个事件可以是以下之一：
progress, meta, row, totals, extremes, exception，一旦事件产生便立即发送。

可正确配合 Transfer-Encoding: chunked 使用，即使启用 HTTP 压缩（Content-Encoding: gzip/deflate/brotli/zstd）也不受影响。

演示。

开发者：Alexey Milovidov。
