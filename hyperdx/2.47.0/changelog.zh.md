## @hyperdx/app@2.47.0

### 次要版本变更

- c6657aa0c: Trace 搜索结果上方改为显示 RED 指标（吞吐量、错误和耗时）。三张图共用同步的悬停光标。错误图可在错误率与错误数量之间切换，点击数量图中的状态系列可筛选结果。日志和其他数据源继续使用原有直方图。
- 81000d0ce: Trace 搜索结果视图新增 RED／热力图切换。热力图使用与仪表板相同的磁贴，显示耗时分布随时间的变化。视图选择保存在 URL 中，刷新或打开共享链接时会恢复相同视图。

### 补丁变更

- 6e7ee8366: 移除 NEXT_PUBLIC_ENABLE_ADHOC_FILTERS 开关。
- 6e7c77247: 图表表格应用编辑后的 Order By，避免沿用上一次点击列标题时设置的排序。
- 1a4c116b2: 精确模式下，使用一次 `groupUniqArrayMap` 读取同一 Map 列的多个键，加快搜索筛选值加载。普通列与各 Map 或 JSON 列分别查询，耗时较长的属性 Map 不会拖慢其余结果。
- 351f19400: 团队的「筛选键获取上限」支持设为 10,000

  团队设置中的输入框原先最多允许每列 1,000 个键，现在可设为 10,000。Map 键发现以该设置值作为每个 Map 列的返回上限，上限最低为 1,000。

- 0c77d52a3: 切换筛选器类型后，旧类型的校验不再阻止保存

  将仪表板筛选器从「PromQL 标签值」切换为其他类型后，保存时不再报错「请选择 PromQL 数据源」。

- 661a5a139: 行详情面板的筛选器按索引引用 JSON 数组元素

  对原生 JSON 列中的数组元素使用「添加到筛选器」时，采用从 1 开始的数组下标（例如 `events[1]`）。此前会使用带引号的键（例如 `events.0`），导致筛选器无提示地返回空结果。

  JSON 字符串内的数组也采用此规则（例如 String 类型的 `Body` 列），现在向 `JSONExtract*` 传入从 1 开始的整数索引。原生 JSON 列中存储的 JSON 字符串会用 `toString()` 包装，以便 `JSONExtract*` 接受它们。

- 3d12509ef: 添加其他筛选器时，保留 JSON 列筛选键的 JSON 写法

  添加第二个筛选器或点击某个筛选器的「加载更多」时，已有原生 JSON 列的键筛选器不会再被重写成 `col['key']`。ClickHouse 会拒绝这种写法，报错 `Illegal type Dynamic of argument of function in`，旧版本则会报错 `First argument for function 'arrayElement' must be array, got 'JSON'`。

- 86acf27c0: 查询文本索引的键和值时，只读取大小最接近中位数的 20 个数据片段

  在文本索引上发现 Map 键或查询「所有值」时，此前会读取时间范围内每个数据片段的索引字典。数据片段较多的表查询缓慢。现在只读取大小最接近中位数的 20 个数据片段。日志和 Trace 数据源可通过新增的「Map 键索引数据片段数」设置（`mapKeyIndexMaxParts`）调整数量，并通过「Map 键索引数据片段大小」设置（`mapKeyIndexPartSelection`，可选中位大小、最小或最大）选择要读的数据片段。对单个筛选键点击「加载更多」时，仍会读取时间范围内的全部数据片段。

- 2f61137e2: `clickstack_search` 在达到时限时返回已找到的行

  MCP 搜索工具使用与应用搜索页相同的渐进式时间窗口，从最新数据开始扫描，时限为 25 秒。达到时限后，会返回已找到的行、`partial` 区块（请求范围、已完整覆盖的范围和未查完的窗口）以及后续调用提示。此前工具在 30 秒后失败。时间窗口辅助函数从应用移到了 `@hyperdx/common-utils/core/searchWindows`，应用行为保持原样。

- 64a55d5b7: 支持按时间列表达式对 Gauge 和 Sum 指标图表分组

  对 Gauge 或 Sum 指标的表格、饼图或柱状图，使用 `toStartOfHour(TimeUnix)` 或 `toDate(TimeUnix)` 等时间表达式分组时，此前会报错 `Unknown identifier TimeUnix`，原因是外层查询读取的分桶 CTE 未包含时间列。现在分组表达式引用时间列时，`TimeUnix` 解析为各指标时间桶的起点，因此所得值与该图表未按时间分组时一致。

- e8d1d9add: 对日期或时间列执行最小值和最大值聚合时，返回实际的最早或最晚时间

  对 Date、DateTime 或 DateTime64 列（例如 `Timestamp`）执行 `min` 和 `max` 时，此前会返回 0，原因是每次聚合都会先将值转为 Float64。表格、数字磁贴和 MCP 工具 `clickstack_table` 现在直接返回时间戳。折线图、柱状图、饼图及其他图表，以及比率、公式和包含多个系列的数字磁贴，继续执行数值转换。

- 0c77d52a3: 将仪表板筛选器类型「查询值」更名为「SQL 表达式值」

  新名称可与「SQL 查询值」和「PromQL 标签值」区分。

- e58329c87: 修改连接主机时要求重新提供密码

  旧版本在修改连接主机时可能将保存的密码发送给新主机。此版本中，变更主机时若未重新提供密码，`PUT /connections/:id` 和 `PUT /api/v2/connections/:id` 均返回 400。Prometheus 端点不使用保存的密码，因此会清除该密码。连接表单会在修改主机时要求输入密码，并显示 API 错误消息。

- a0732b175: 可保存临时仪表板并保留全部内容。
- 67e2eb36e: 使用侧栏布局图标显示或隐藏搜索筛选器。
- 2cec94f7d: 仪表板的 SQL 查询筛选器可选配数据源

  SQL 查询筛选器现在可以选用连接下的数据源或数据源变量，也可以在使用连接变量时进行选择。选定后，SQL 可使用 `$__sourceTable` 和 `$__filters`，与原始 SQL 磁贴一样，将仪表板的筛选选项应用于该数据源。外部 API 和 MCP 通过 `sourceId` 读写该设置。

- 0c77d52a3: SQL 查询筛选器编辑器支持自动补全表名和列名

  与原始 SQL 磁贴编辑器一样，仪表板的 SQL 查询筛选器编辑器现在会提示所选连接下各数据源的表和列。

- 7afa31c71: 团队可将搜索筛选器的「显示所有值」默认设为「全部」或「精确」。
- 6a5fd1127: 深色模式下，字段背景现在带有透明度，可适应弹出层等不同背景。透明度直接在主题令牌中设置，以前使用的 Click UI 令牌会解析为纯色。

## @hyperdx/otel-collector@2.47.0

### 补丁变更

- d945d7ea8: 迁移工具将 `clickhouse-go/v2` 升级到 v2.51.0

  此次升级引入 `github.com/andybalholm/brotli` v1.2.7，修复 Brotli 解压器中的拒绝服务漏洞 GO-2026-6888（CVE-2026-111497）。

- f11b9f58b: 初始化表采用 8,192 个词元的文本索引字典块

  在 ClickHouse 26.6 或更高版本上，采集器的模式迁移在初始化表后通过 `ALTER TABLE … MODIFY SETTING`，为 `otel_logs`、`otel_traces` 和 `hyperdx_sessions` 设置 `text_index_dictionary_block_size = 8192`，默认值为 512。每个数据片段的文本索引稀疏索引缩小至原来的 1/16。通过 `mergeTreeTextIndex()` 读取筛选值时，每次读取都要为每个数据片段加载该索引。在一张有 5.37 亿行的表上，使用 4,096 个词元的块就已将每个数据片段的读取成本降至约 1/10，使低频属性值搜索加快 3–7 倍，高频值搜索加快 10–30%。

  这项变更通过 `ALTER` 执行，因此现有部署也会应用。新的数据片段使用 8,192 个词元的块，现有数据片段在合并前仍保留原有块。已经设置 `text_index_dictionary_block_size` 的表保持原样。自行管理这些表的运维人员可通过 `HYPERDX_OTEL_EXPORTER_SET_TEXT_INDEX_BLOCK_SIZE=false` 关闭变更。ClickHouse 26.2–26.5 不支持该设置，继续使用 512 个词元的块。

- d99be7650: MCP 的 `event_patterns`、`emerging_signals`、搜索降噪和 CLI 现在不会因日期不同而拆分同类日志行。提取模式前，Drain 会将时间戳中的日期部分（星期、日、月、年）掩码为 `<DATE>`，使跨日、跨月或跨年的日志行归入同一模板，避免分别被标记为「新增」和「消失」。时间和 ID 不做掩码。同一天内的分组逻辑保持原样，但严重级别字母不同的 klog 日志行不再合并。掩码不改变日志行的词元数量。`event_patterns` 的下钻谓词将 `<DATE>` 匹配为一个或多个非空白字符，词元内部也可匹配。该行为由模式谓词构建器新增的 `masks` 选项控制，仅 MCP 下钻设置此选项。搜索降噪也会在匹配前以同样的方式对正文做掩码。掩码指令新增可选的 `perWord` 标志，默认关闭，与 drain3 一致。Web 应用的事件模式视图使用自身的 drain3 配置，行为保持原样。

- 7afa31c71: 团队可将搜索筛选器的「显示所有值」默认设为「全部」或「精确」。
- f11b9f58b: Map 文本索引采用大字典块时按键读取值，并按频次降序返回

  针对采用大字典块的 Map key=value 文本索引（至少 2,048 个词元，例如采集器迁移在 ClickHouse 26.6+ 上设置的 `text_index_dictionary_block_size = 8192`），查询「所有值」时会单独读取每个键，以每批最多 10 个键并行查询。每个键读到 20,000 个词元即停止，避免每行都有不同值的键（例如请求 ID 或 UUID）拖慢其他键。查询使用 `topKWeighted(limit)` 按每个词元的行数加权，达到上限时仍优先保留并返回最常见的值。读取时不再应用 `max_rows_to_read`，因为索引按词元排序读取，旧上限会让排序在高基数键后面的每个键都取不到值。

  使用较小字典块的索引（含 ClickHouse 默认的 512）继续使用原有查询形式。一次读取覆盖单个查询中的所有键，按字母顺序返回最前面的值，并保留 `max_rows_to_read` 上限。现在按每批最多 10 个键并行查询，上限最多会影响同批另外 9 个键。每次读取都会加载各数据片段的稀疏索引。字典块小时，稀疏索引较大，逐键读取会成倍增加开销。块大小按索引定义、表的 `text_index_dictionary_block_size`、服务器设置的顺序确定。

  普通列上的文本索引现在使用 `topKWeighted` 返回最高频值，以每批最多 10 列并行查询，并取消行数上限。

## @hyperdx/api@2.47.0

### 次要版本变更

- 7905721bc: 外部 API 支持通过 POST 和 DELETE /api/v2/alerts/{id}/silenced 静默告警或解除静默。

### 补丁变更

- 22377dfcf: 将 check-alerts 的历史查询范围限制在告警间隔内

  check-alerts 任务不再在每轮检查中为每条告警扫描 7 天历史。每条告警先查询一行，跳过当前窗口已评估的告警。未分组的告警从该行获取上一状态，分组告警按自身间隔扫描 1 至 7 天的窗口。

- ef81fe6d8: 新增 `ENABLE_INGESTION_API_KEY`，使应用镜像使用 `INGESTION_API_KEY`

  应用镜像忽略 `INGESTION_API_KEY` 时，外部采集器只能使用为团队生成的密钥，重建团队会更换该密钥。在 API 上设置 `ENABLE_INGESTION_API_KEY=true` 后，API 会同时接受预设密钥和团队密钥。未设置时行为保持原样。

- b129ec1ac: 在服务端 Span 及 `clickhouse_proxy.query` SLI 中，通过 `error_category` 对失败的 ClickHouse 代理请求分类，包括 ClickHouse 在 HTTP 200 响应后写入的错误。Span 还记录上游状态、ClickHouse 错误代码和类型，以及没有 ClickHouse 错误代码的上游错误正文。

- d99be7650: MCP 的 `event_patterns`、`emerging_signals`、搜索降噪和 CLI 现在不会因日期不同而拆分同类日志行。提取模式前，Drain 会将时间戳中的日期部分（星期、日、月、年）掩码为 `<DATE>`，使跨日、跨月或跨年的日志行归入同一模板，避免分别被标记为「新增」和「消失」。时间和 ID 不做掩码。同一天内的分组逻辑保持原样，但严重级别字母不同的 klog 日志行不再合并。掩码不改变日志行的词元数量。`event_patterns` 的下钻谓词将 `<DATE>` 匹配为一个或多个非空白字符，词元内部也可匹配。该行为由模式谓词构建器新增的 `masks` 选项控制，仅 MCP 下钻设置此选项。搜索降噪也会在匹配前以同样的方式对正文做掩码。掩码指令新增可选的 `perWord` 标志，默认关闭，与 drain3 一致。Web 应用的事件模式视图使用自身的 drain3 配置，行为保持原样。
- e58329c87: 修改连接主机时要求重新提供密码

  旧版本在修改连接主机时可能将保存的密码发送给新主机。此版本中，变更主机时若未重新提供密码，`PUT /connections/:id` 和 `PUT /api/v2/connections/:id` 均返回 400。Prometheus 端点不使用保存的密码，因此会清除该密码。连接表单会在修改主机时要求输入密码，并显示 API 错误消息。

- 2cec94f7d: 仪表板的 SQL 查询筛选器可选配数据源

  SQL 查询筛选器现在可以选用连接下的数据源或数据源变量，也可以在使用连接变量时进行选择。选定后，SQL 可使用 `$__sourceTable` 和 `$__filters`，与原始 SQL 磁贴一样，将仪表板的筛选选项应用于该数据源。外部 API 和 MCP 通过 `sourceId` 读写该设置。
