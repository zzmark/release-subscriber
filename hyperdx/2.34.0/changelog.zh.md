Terraform 地址源自每个资源的 ID，而不是其名称，因此在 HyperDX 中重命名资源并重新导出不会产生销毁并重新创建计划。生成器位于“@hyperdx/common-utils”中，因此 API 可以生成与 UI 相同的工件。清单端点将每个列表的行数限制为 1000 行，并报告哪些类型被限制，因此一个非常大的团队被告知其导出是部分的，而不是默默地接收一个。

- ed9d9a67：将搜索词中的“_”和“%”视为文字字符，而不是像通配符

 搜索词直接插入到 ILIKE 模式中，因此 ClickHouse
 将它们的“_”和“%”读取为通配符。 `ServiceName:user_service` 也匹配
 `user-service` 和 `user.service`，以及否定的 `-ServiceName:user_service`
 删除了那些相同的行。令牌索引查找仍然接收原始术语。

- c97789a0：正确拆分包含反斜杠转义引号的 SQL 表达式。
- 2468b256：修复：在搜索中对每个“http://”、“https://”和“localhost:&lt;port&gt;”进行编码，而不是
 只是第一个

 命名两个或多个 URL 的搜索未转义后面的冒号，因此 Lucene 读取
 它们作为字段查询。 `http://a.com http://b.com` 将第二个 URL 编译为
 `http ILIKE '%//b.com%'` — 一个基于裸露 `http` 标识符的谓词，而不是
 日志正文的搜索。

- 6a35df06：在 Lucene 范围内尊重开放 (`*`)、独占 (`{}`) 和非数字边界

 `Duration:[* TO 500]` 编译为 `Duration BETWEEN '*' AND 500`，其中
 ClickHouse 拒绝并显示“TYPE_MISMATCH”。独家和半开放系列，例如
 “持续时间：{100 TO 500}”全部序列化为包含性“BETWEEN”。界限
 使用 parseFloat 进行解析，因此 Timestamp:[2024-01-01 TO 2024-06-01]` 变成
 “2024 年和 2024 年之间”，没有匹配任何内容。的简单英语解释
 搜索现在也标记排除的边界。

- d1c669dc：修复：在比率模式下使用比率值进行系列限制排名

 使用“比率”系列返回类型和系列限制的图表排名最高
 top-N 系列通过裸分子而不是通过绘制的比率，因此
 具有高比率的低容量组可能会被高容量组取代
 比率要低得多。排名现在使用相同的“divide(a, b)”表达式
 图表显示。非比率图表生成与之前相同的 SQL。

- b082f700：检测带有时区或类型包装器的 ClickHouse 时间戳类型



 `DateTime('UTC')` 未分类为日期时间，因此其时间戳的源
 列列出了“日期”分区列和存储桶的“日期时间”列
 “日期”图表 — 将一整天压缩成午夜的一根柱线。时间
 过滤器也只将边界包装在“toDate()”中以获取精确的“Date”类型，因此
 将“Date32”或“Nullable(Date)”列与 DateTime 绑定进行比较，
 失去了整个开始日。
