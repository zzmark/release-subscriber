## @hyperdx/app@2.39.0

### 次版本变更

- e31e5d8d：支持将仪表盘磁贴告警导入 Terraform。Provider 3.28.0 中，`clickhouse_clickstack_alert` 新增了带 `dashboard_id`/`tile_id` 的 `source = "tile"`，因此批量导出和单个告警菜单现在会包含磁贴告警，不再跳过所有非已保存搜索告警。包含磁贴告警的文件要求 `>= 3.28.0`，并说明生成的配置需要如何手动编辑；不含磁贴告警的导出仍可安装在 3.25.x 上。当磁贴名称为空或重复时，不会导出其告警，因为 Provider 的 `tile_ids` 映射以磁贴名称为键并会忽略这些磁贴，告警只能绑定到下次应用仪表盘时可能重新生成的字面 ID；仪表盘由 ProvisionDashboardsTask 预置时也不会导出，因为该任务会整体重写这些磁贴。这两项判断都在服务端针对导入清单和告警列表执行，因为两种响应都不包含仪表盘中同级磁贴的名称。
- 41eee7d3：可直接从图表探索器创建和编辑告警，无需已保存搜索或仪表盘磁贴。在 `/chart` 中构建日志、Trace 或指标图表（Builder 或原始 SQL），添加告警、命名并创建后，告警会持久保存自身的图表配置。告警页面会用图表图标显示这类告警的名称，并链接回已填入对应查询的探索器；告警详情页会渲染该查询，并在完整图表编辑器中同时编辑告警字段和底层图表。
- 34d829c7：功能：按最终用户筛选 LLM 仪表盘。

  在现有会话筛选器旁新增用户筛选器。它会列出搜索时间范围内 LLM Span 中出现的不同用户，并将所有标签页限定到所选用户，包括“错误”标签页中的关联日志事件。

  用户解析采用与“热门用户”图表分组相同的跨方言表达式（`user.email`、`enduser.id`、`user.id`、`ai.telemetry.metadata.userId`），因此下拉框所选值始终能匹配生成该值的行。选择结果保存在 URL 中，可以分享已筛选的视图。

- f007c37f：为最近创建的团队在侧栏添加能够感知上下文的入门清单。完成连接 ClickHouse、添加数据等设置步骤后，第二阶段会跟踪按用户保存在 `user.onboardingData` 中的产品使用里程碑：探索数据、构建仪表盘、设置告警和使用 MCP 服务器。完成状态记录在服务端，因此无论操作来自 UI、外部 REST API v2 还是 MCP 工具都会计入；卡片可以关闭，任务注册表新增任务时会再次出现。
- 264f2164：功能：可在搜索结果表格中选择行并复制或下载。
- 3876d6b9：从表的主索引填充指标名称选择器，因此无需等待对数据执行聚合，几乎可以立即显示内容。在一个报告约 4,900 个 Gauge 指标的数据源上，首批选项由约 770ms 缩短至约 30ms，并会渐进式流入，而不是一次性出现。仍有更多数据传入时，下拉箭头会替换为小型加载指示器。

  选择器现在有两种模式。**浏览**模式通过 `mergeTreeIndex` 表函数从稀疏主索引流式读取 `MetricName`，每个 Granule Mark 一行，而非扫描整列。由于索引只记录每个 Granule 边界处的值，所得列表是一个子集，并偏向确实包含数据的指标（索引可见指标的数据点中位数约为 32k，其余指标约为 14）。**输入**模式会切换到完整、按相关性排序的 `GROUP BY` 搜索，因此索引遗漏的任何指标仍可通过名称找到。占位文字改为 “Search metrics...” 以提示用户搜索。

  实际使用中有两个细节：首次提交某个搜索模式期间，浏览列表会保留并在客户端筛选，选项不会在输入过程中突然清空；下拉框渲染上限提高到 500，与服务端分页大小一致，因此未标记为截断的搜索结果都可以完整渲染。

  完全无法读取索引时，浏览模式会回退到完整列表，例如服务器版本早于 24.2、指标表为 Distributed 或非 MergeTree，或主键不含 `MetricName`，所以任何部署都不会失去选择器。

  `Metadata` 新增 `streamDistinctIndexValues`，这是一个对表和列通用的异步生成器，因此任何主键列（例如 `ServiceName`）都可用相同方式列出。`streamToAsyncIterator` 从 `packages/app` 的会话代码迁至 ClickHouse 客户端旁的 `common-utils`，新增的 `useStreamingQuery` Hook 会把异步可迭代对象累积到 React Query 缓存项中，并通过节流发布部分结果。

- 972634d2：在 Webhook 模板变量 `{{sourceQuery}}` 中报告完整的告警条件。该变量此前只读取图表顶层的 `where`，因此按序列使用 `aggCondition` 定义的常见告警仍会渲染为空。现在变量会报告告警查询实际应用的所有条件：图表的 `where` 加告警所读取序列的 `aggCondition`，以及已保存搜索的 `where` 加固定筛选器。图表的固定筛选器会有意排除，因为磁贴或 inline 告警不会应用它们。值最多保留 2000 个字符。

  将告警的比较器从 `between` 或 `outside` 改为其他类型时，现在会清除已存储的 `thresholdMax`，不再让旧上界留在文档中并由告警 API 返回，造成实际不会触发的范围仍被展示。Webhook 模板在读取时已经防范了这一情况。

  Webhook 表单的变量列表和 API 的回退正文模板现在都来自 common-utils 中的同一列表，`buildWebhookTemplateVariables` 也以该列表约束类型，因此新增变量时不会遗漏这两个位置。“发送测试”负载会为每个变量提供示例值，以便在告警触发前验证正文模板。

  可选数字的文档示例条件现在使用 `{{#unless (eq thresholdMax undefined)}}`，而非 `{{#if thresholdMax}}`；后者会把合法的上界 `0` 误认为不存在。

### 补丁变更

- ab15643f：修复长时间存活会话的默认时间范围解析。
- 71d792a6：修复：页面加载时不再对已禁用数据源执行 ClickHouse 查询。元数据/字段自动补全以及仪表盘筛选值查询现在会排除已禁用的数据源，因此加载页面不会再为已关闭的数据源发出数据源设置查询（例如 `SELECT name, value FROM system.settings`）。
- 34d829c7：修复：LLM 仪表盘的属性存在性筛选改用 mapContains。

  LLM 仪表盘此前使用 `SpanAttributes['key'] != ''` 检查属性是否存在，但跳过索引无法处理该表达式：Trace Schema 的 `mapKeys(SpanAttributes)` 索引只能响应 `mapContains`，而 `!= ''` 会规范化为 `notEmpty()`，因此每个磁贴都会扫描所有 Granule。Map 下标也是子列引用，所以在 ClickHouse 26.3 及更高版本中，每个引用都会在 PREWHERE 规划期间增加一次按 Part 获取大小的操作。

  这些筛选现在以索引可以处理且无需按 Part 查询的 `mapContains` 开头。在一个预发布 Trace 表上，LLM Span 谓词的规划停顿从 36 秒降至 7ms，双键筛选处理的 Granule 从 1,306 个降至 3 个。

  与仪表盘分组所用值表达式配对的门控条件会保留非空检查，所以值为 `''` 的属性仍不会产生空白行。此处值项决定结果，而存在性项只负责裁剪，因此它会包装在 `indexHint` 中，让跳过索引分析可以利用它，同时不对保留下来的每行重新求值。值项不会增加按 Part 查询，因为它读取的键与分组本来就需要读取的键相同。位于 SELECT 列表聚合中的门控条件不会加 Hint，因为跳过索引分析不会进入 SELECT 列表；工具调用门控条件同时用于两个位置，因此会以两种形式暴露。

  唯一的行为变化是 LLM Span 检测现在以存在性为准：只要 Span 携带 `gen_ai.system`，无论其值是什么都会被视为 LLM Span。没有任何内容按该谓词分组。

  对使用物化列的表有一项注意事项：运维人员为某个键创建物化列后，`SpanAttributes['key']` 下标会被重写到物化列，但 `mapContains` 不会匹配这种重写。此类表原本也不受规划成本影响，因为重写后的下标已不是子列引用；因此，这一变化以物化列重写换取跳过索引裁剪，只在这些列不存在时更划算。

  JSON 属性列保持不变：其路径是真实子列，没有可用于裁剪的键索引，增加存在性条件只会导致重复读取。

- 482d2cb0：功能：对告警页面进行分页。
- 5311d63c：修复：为 incident.io Webhook 提供 incident.io 可以接受的正文。

  未设置正文的 incident.io Webhook 此前会发送通用的 `{"text": ...}` 负载，但其中缺少 incident.io 要求的两个字段，因此每次投递都会被拒绝，无法创建告警。现在会发送 incident.io 负载，其中包含在触发和恢复期间保持稳定的去重键，使 incident.io 能关闭其创建的告警；`metadata` 中还包含告警 ID、状态、条件和评估窗口，便于路由。选择 incident.io 服务时也可以使用 Webhook 正文编辑器及模板变量列表，不再仅限 Generic，因此可按告警源的配置字段定制负载。

- 96ac6b1b：修复：在 ClickHouse 26.3 及更高版本上禁用按 Part 计算子列大小。

  ClickHouse 26.3 默认启用了 `allow_calculating_subcolumns_sizes_for_merge_tree_reading`，这会让 PREWHERE 规划为查询引用的每个 Map 键获取各 Part 的大小。在 SharedMergeTree 上，每个“键 × 活跃 Part”都会发出一次 S3 GET，而且发生在读取任何行之前，`max_execution_time` 无法中断。引用大量属性键的查询（LLM 仪表盘会读取约 64 个）可能在规划阶段耗费数分钟。现在只要服务器支持，查询就会将该设置设为 `0`。

- 4db73970：修复：多行查询字段失去焦点后仍保持内容可见。

  多行 SQL 字段此前一旦失去焦点就会折叠成一行，第一行之后的内容在再次点击前都会隐藏。聚焦时字段会扩展为覆盖下方内容的浮动层；如果容器按内容确定大小，浮动层脱离布局流后还会让字段缩成只有一个字符宽的细条。

  现在所有允许多行的字段都会直接按内容确定大小，无论是否聚焦都会扩展布局而不是浮在上方，增长至 150px 后开始滚动。适用范围包括搜索的 WHERE、SELECT 和 ORDER BY、图表编辑器 SQL 字段以及 PromQL；Lucene 搜索字段同样最多扩展到四行。`allowMultiline={false}` 的字段在 SQL 和 Lucene 中仍保持单行。聚焦浮层已被移除，不再保留独立的聚焦展开状态。

  搜索栏旁的语言切换器会同步拉伸，两者之间不再有分隔线。默认尺寸的 Lucene 搜索栏也不再超出切换器：Lucene 输入框此前为 36px 的方框保留 38px 行高，而切换器按 SQL 编辑器使用的 36px 设置，因此会高出输入框 2px。两种语言现在从同一个尺寸表获取高度，接缝平齐，切换语言也不会改变搜索栏高度。只有默认尺寸受影响，紧凑尺寸原本就统一为 30px。

  聚焦会重新着色整个控件，包括语言切换器，但不会覆盖错误或警告边框。

- 84c67f4b：修复：告警通知时长只显示投递时间。

  告警评估列表中的通知时长此前会计时告警决定触发后执行的所有操作：构建消息标题和链接、查询正文中的日志行、渲染模板，最后才是投递。这使该列显示为数秒，而底层 Webhook 只需数毫秒；该列与自身的按目标明细不一致，且数值主要由与通知目标响应速度无关的工作决定。现在只统计投递本身。已经记录的评估仍保留旧数值，因此显示结果仍可能偏高。

- c98be91f：对入门清单“是否有数据”探测中的数据源表名和数据库名进行转义，防止通过恶意命名的数据源实施 SQL 注入。
- cfacdbe5：功能：现在可以保存仪表盘的相对日期范围。
- f7ae72c2：重构：提取 PromQL 函数、PromqlExpressionEditor 和 ChartSeriesControls。
- fda038d6：修复：LLM 仪表盘范围筛选器的选项加载失败时，仍允许清除筛选。

  会话和用户下拉框此前在不同值查询加载中或失败时都会禁用。若已经应用筛选，用户只能看到当前范围却无法移除；当查询持续失败时更会永久卡住。现在只要已应用某个值，这些下拉框就会保持可交互。

- b1e48b99：修复：打开行详情时为列标识符添加引号。
- 78a33ba4：功能：允许将仪表盘筛选器配置为必填。
- db708a82：服务地图节点按绝对错误率阈值着色，不再相对于图中最差服务缩放。无错误的服务现在显示为中性灰色，其余节点划分为三个固定区间（低于 1%、1–5%、5% 及以上）。没有错误数据的服务（只调用其他服务、在时间窗口内没有入站请求）显示为空心而非实心，因此“未测量”不再看起来像“没有问题”。

  此前每个节点都采用红色，强度按整张图的最大值归一化，因此最差服务错误率为 0.3% 的地图会与最差服务为 60% 的地图一样显示深红色，健康服务也与存在少量错误的服务无法区分。错误率图例现在显示四个离散等级，标出 1% 和 5% 边界，并为中空状态增加说明。延迟和吞吐量着色保持不变。

- e31e5d8d：支持将仪表盘磁贴告警导入 Terraform。Provider 3.28.0 中，`clickhouse_clickstack_alert` 新增了带 `dashboard_id`/`tile_id` 的 `source = "tile"`，因此批量导出和单个告警菜单现在会包含磁贴告警，不再跳过所有非已保存搜索告警。包含磁贴告警的文件要求 `>= 3.28.0`，并说明生成的配置需要如何手动编辑；不含磁贴告警的导出仍可安装在 3.25.x 上。当磁贴名称为空或重复时，不会导出其告警，因为 Provider 的 `tile_ids` 映射以磁贴名称为键并会忽略这些磁贴，告警只能绑定到下次应用仪表盘时可能重新生成的字面 ID；仪表盘由 ProvisionDashboardsTask 预置时也不会导出，因为该任务会整体重写这些磁贴。这两项判断都在服务端针对导入清单和告警列表执行，因为两种响应都不包含仪表盘中同级磁贴的名称。
- f007c37f：为最近创建的团队在侧栏添加能够感知上下文的入门清单。完成连接 ClickHouse、添加数据等设置步骤后，第二阶段会跟踪按用户保存在 `user.onboardingData` 中的产品使用里程碑：探索数据、构建仪表盘、设置告警和使用 MCP 服务器。完成状态记录在服务端，因此无论操作来自 UI、外部 REST API v2 还是 MCP 工具都会计入；卡片可以关闭，任务注册表新增任务时会再次出现。
- 3876d6b9：从表的主索引填充指标名称选择器，因此无需等待对数据执行聚合，几乎可以立即显示内容。在一个报告约 4,900 个 Gauge 指标的数据源上，首批选项由约 770ms 缩短至约 30ms，并会渐进式流入，而不是一次性出现。仍有更多数据传入时，下拉箭头会替换为小型加载指示器。

  选择器现在有两种模式。**浏览**模式通过 `mergeTreeIndex` 表函数从稀疏主索引流式读取 `MetricName`，每个 Granule Mark 一行，而非扫描整列。由于索引只记录每个 Granule 边界处的值，所得列表是一个子集，并偏向确实包含数据的指标（索引可见指标的数据点中位数约为 32k，其余指标约为 14）。**输入**模式会切换到完整、按相关性排序的 `GROUP BY` 搜索，因此索引遗漏的任何指标仍可通过名称找到。占位文字改为 “Search metrics...” 以提示用户搜索。

  实际使用中有两个细节：首次提交某个搜索模式期间，浏览列表会保留并在客户端筛选，选项不会在输入过程中突然清空；下拉框渲染上限提高到 500，与服务端分页大小一致，因此未标记为截断的搜索结果都可以完整渲染。

  完全无法读取索引时，浏览模式会回退到完整列表，例如服务器版本早于 24.2、指标表为 Distributed 或非 MergeTree，或主键不含 `MetricName`，所以任何部署都不会失去选择器。

  `Metadata` 新增 `streamDistinctIndexValues`，这是一个对表和列通用的异步生成器，因此任何主键列（例如 `ServiceName`）都可用相同方式列出。`streamToAsyncIterator` 从 `packages/app` 的会话代码迁至 ClickHouse 客户端旁的 `common-utils`，新增的 `useStreamingQuery` Hook 会把异步可迭代对象累积到 React Query 缓存项中，并通过节流发布部分结果。

- 972634d2：在 Webhook 模板变量 `{{sourceQuery}}` 中报告完整的告警条件。该变量此前只读取图表顶层的 `where`，因此按序列使用 `aggCondition` 定义的常见告警仍会渲染为空。现在变量会报告告警查询实际应用的所有条件：图表的 `where` 加告警所读取序列的 `aggCondition`，以及已保存搜索的 `where` 加固定筛选器。图表的固定筛选器会有意排除，因为磁贴或 inline 告警不会应用它们。值最多保留 2000 个字符。

  将告警的比较器从 `between` 或 `outside` 改为其他类型时，现在会清除已存储的 `thresholdMax`，不再让旧上界留在文档中并由告警 API 返回，造成实际不会触发的范围仍被展示。Webhook 模板在读取时已经防范了这一情况。

  Webhook 表单的变量列表和 API 的回退正文模板现在都来自 common-utils 中的同一列表，`buildWebhookTemplateVariables` 也以该列表约束类型，因此新增变量时不会遗漏这两个位置。“发送测试”负载会为每个变量提供示例值，以便在告警触发前验证正文模板。

  可选数字的文档示例条件现在使用 `{{#unless (eq thresholdMax undefined)}}`，而非 `{{#if thresholdMax}}`；后者会把合法的上界 `0` 误认为不存在。
