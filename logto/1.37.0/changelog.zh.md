## 亮点

- **内置帐户中心应用程序现已推出**：为最终用户提供即用型单页帐户中心体验。
- **JWT 定制器增强**：应用程序上下文现在可在自定义脚本中用于访问令牌和客户端凭据令牌。
- **可配置的 ID 令牌声明**：现在可以通过控制台或管理 API 配置其他 ID 令牌声明。

## 新功能和增强功能

### 内置帐户中心应用程序

此版本引入了帐户中心单页应用程序作为最终用户的内置 Logto 应用程序：

- 支持主要电子邮件、电话、用户名和密码的个人资料更新，并具有验证流程。
- 支持 TOTP、备份代码（下载/重新生成）和密钥 (WebAuthn) 的 MFA 管理，包括重命名和删除操作。
- 敏感操作通过密码/电子邮件/电话验证进行控制，并包括专用的成功屏幕。

文档：<https://docs.logto.io/end-user-flows/account-settings/by-account-api>

### JWT 定制器中的应用程序上下文

应用程序上下文（例如应用程序名称、描述和自定义数据）现在可在 JWT 定制程序脚本中用于：

- 访问令牌
- 客户端凭据令牌

这可以实现应用程序感知的 JWT 声明自定义。

### ID令牌声明配置

您现在可以通过控制台或管理 API 配置 ID 令牌中包含的其他声明：

- `自定义数据`
- `身份`
- `角色`
- `组织`
- `组织角色`

## 错误修复和稳定性

### 自定义域的内置应用重定向 URI 修复

修复了自定义域请求下内置帐户中心和演示应用程序的“invalid_redirect_uri”问题。

- **根本原因**：内置客户端元数据仅从默认租户 URL 生成，而运行时“redirect_uri”可以基于自定义域。
- **修复**：“getTenantUrls”现在接受可选的运行时端点。帐户中心和演示应用程序的内置元数据生成现在包括“envSet.endpoint”，因此重定向/注销 URI 自动包括活动的自定义域。

### “告诉我们你自己”部分可见性修复

修复了当仅配置可选的自定义个人资料字段时，注册期间不会出现“向我们介绍一下您自己”部分的问题。

- 以前仅检查必填字段，因此跳过了仅限可选的设置。
- 检查现在包括可选字段以及是否已提交额外的个人资料表格，以确保预期的可见性。

### 社交链接流上下文保存修复

修复了这种情况下社交帐户链接流程损坏的问题：

- “用户名 + 电子邮件”均作为必需的注册标识符启用。
- 启用“要求用户提供缺少的社交登录注册标识符”。
- 社交 IdP 未返回经过验证的电子邮件。
- 用户填写用户名，然后输入已注册的电子邮件。

以前，“link_social”参数在用户名完成后不会传播，导致链接上下文在电子邮件验证之前丢失。该流程现在附加并保留“link_social”，以便预期的链接和登录行为正常工作。
